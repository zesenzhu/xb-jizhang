# 小宝记账项目开发约束

本文件是当前单仓库的项目级开发约束。修改后端、前端、数据库模型、接口契约或部署配置前，应先阅读与任务对应的 `.agent/skills/` 技能文件。

## 项目边界

- `backend/` 是 NestJS API 服务，负责认证、账本权限、账单业务和统计。
- `frontend/` 是 Next.js App Router PWA，负责页面、客户端状态和离线交互。
- `docs/` 保存产品需求、技术方向和开发计划。
- 根目录 `docker-compose.yml` 负责本地全栈编排；生产部署由 Docker Compose 与 Nginx 配合完成。

参考项目中的注册码、设备授权、MQTT、TCP、脚本日志和 AI Agent 不属于本项目，除非需求明确变更，否则不要引入。

## 通用规则

- 使用中文编写用户可见文案、接口说明、关键注释和提交信息。
- TypeScript 开启严格模式；公共接口禁止使用未解释的 `any`。
- 所有账本资源都必须经过账本成员关系和角色权限校验，不能只相信客户端传入的 `ledgerId`。
- 金额统一使用整数分；禁止在业务层使用浮点数计算金额。
- 新增账单使用客户端幂等 ID；修改账单使用版本号或更新时间检测并发冲突。
- 财务数据默认软删除，重要变更保留审计信息。
- 生产数据库只使用 Prisma Migration，不在启动命令中执行有数据丢失风险的 `db push`。
- 修改完成后，至少运行受影响应用的类型检查、Lint、测试或生产构建中的相关验证。

## 技能路由

- 修改 NestJS、Prisma、认证、账本接口或同步逻辑：阅读 `backend-dev-guide` 和 `typescript-type-convention`。
- 修改 Next.js 页面、Axios、Zustand、PWA 或离线队列：阅读 `frontend-dev-guide` 和 `typescript-type-convention`。
- 新增或重构代码时：阅读 `commenting-convention`。
- 准备提交时：阅读 `commit-convention`，并根据实际 diff 编写提交正文。

## 协作沟通与交付要求

- 面向用户的沟通、进度同步、方案说明、提交说明和最终交付默认使用中文；代码、命令、文件路径、API 名称及必要行业术语保持原始写法。
- Git 提交使用 Conventional Commit 格式，保留标准英文类型，例如 `feat:`、`fix:`、`refactor:`、`docs:`、`test:`、`chore:`；冒号后的提交说明使用简洁准确的中文。
- 回复先给结论，再用中文分点说明改动目标、涉及范围、关键实现、验证命令与结果，以及已知风险或未完成项。
- 执行中使用简洁中文同步进度。遇到需求歧义、架构或数据影响、额外权限、无法验证或无关工作区改动时，说明事实、影响和下一步，未经确认不纳入无关改动。
- 提交前必须核对暂存文件范围和差异检查结果；提交后必须说明 commit hash、提交摘要、验证结果和工作区遗留改动。
- 业务流程、接口契约、权限模型、部署方式或测试口径发生变化时，同步检查 `docs/` 中的技术方向和需求文档。

## 自动化测试硬性规则

- 实现、修复或重构行为前，必须阅读 `.agent/skills/testing-standard/SKILL.md`，并按测试分层、Mock 约束和检查清单执行。
- 行为变更必须在同一改动中新增或更新自动化测试。纯文案、注释或无行为影响的样式调整可以跳过，但最终必须说明原因和遗留风险。
- 测试与被测代码就近放置：后端纯逻辑、Service、Controller 和 Guard 使用 `*.test.ts` 或现有 `*.spec.ts`；前端客户端逻辑使用 `*.test.ts` 或 `*.test.tsx`；跨路由服务端流程才使用 E2E。
- 涉及账本和数据管理时，必须覆盖成员权限、跨账本访问、请求契约、幂等 ID、并发版本和错误处理；不能只测试成功路径。
- 不得为了测试暴露生产专用接口，不得把真实生产数据库、Redis 或用户数据用于单元测试。

## 默认验证命令

在仓库根目录优先执行：

```bash
pnpm typecheck
pnpm test
```

按改动范围补充：

```bash
pnpm lint
pnpm test:coverage
```

本地环境不具备执行条件时，最终说明必须明确列出未执行的命令和原因。
