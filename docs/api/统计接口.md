# 小宝记账统计接口

## 1. 文档范围

本文档定义二期统计页面使用的概览、趋势、分类和周期汇总接口。统计接口只读取当前登录用户在当前账本中有权看到的收入和支出账单，不负责修改账单、账户或分类。

本文档描述二期统计后台的当前接口契约与实现：四个查询接口均已实现，概览、分类统计及趋势/周期的非空周期聚合已通过隔离 PostgreSQL 16 验证。旧版 overview 在兼容期内保留独立参数及响应；本文同时记录当前校验差异和下钻边界，不代表统计前端已完成。

## 2. 公共约定

统计接口使用普通用户会话和 `/api` 前缀。调用者必须是目标账本的 `ACTIVE` 成员，`OWNER`、`EDITOR` 和 `VIEWER` 均可查询。所有接口都必须从认证上下文取得用户 ID，再校验 `ledgerId`，不能只相信路径参数。

统计金额使用整数分，服务端聚合结果是唯一口径，前端不重复计算。统计只处理 `EXPENSE` 和 `INCOME`，不接收、不展示和不聚合 `TRANSFER`。

四个接口必须复用同一套规则：

- 账本成员校验；
- 账本 `timezone` 解析和本地自然日边界计算；
- `deletedAt IS NULL` 过滤；
- 当前用户对私人账户的可见性过滤；
- 账本、时间范围、账单类型、分类、账户、付款人和关键词过滤；
- 只统计当前账本，不混用其他账本数据。

## 3. 接口总览

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/ledgers/:ledgerId/statistics/overview` | `VIEWER+` | 收支总额、结余、日均支出和账单数量 |
| `GET` | `/api/ledgers/:ledgerId/statistics/trend` | `VIEWER+` | 按日、月或年返回收支趋势 |
| `GET` | `/api/ledgers/:ledgerId/statistics/categories` | `VIEWER+` | 返回一级/二级分类金额、占比和账单数 |
| `GET` | `/api/ledgers/:ledgerId/statistics/periods` | `VIEWER+` | 按统计周期返回支出、收入和结余汇总 |

四个接口使用二期 `period` 参数时返回同一份规范化的 `range` 上下文。旧版 overview 不返回 `range`。前端切换时间维度、账本或筛选条件时，共用相同的时间参数及 `accountId`、`payerId`、`keyword` 等过滤值；分类类型、趋势指标和分类层级等接口专属参数按各自接口传入，不能让各模块自行推导时间范围。

## 4. 统一查询参数

### 4.1 时间参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `period` | `WEEK \| MONTH \| YEAR \| ALL \| RANGE` | 二期调用必填 | 统计模式；前端默认使用 `MONTH` |
| `anchorDate` | `YYYY-MM-DD` | `WEEK/MONTH/YEAR` 必填 | 按账本时区解释的锚点日期；不允许为未来日期 |
| `fromDate` | `YYYY-MM-DD` | `RANGE` 必填 | 自定义范围起始日期，包含当天 |
| `toDate` | `YYYY-MM-DD` | `RANGE` 必填 | 自定义范围结束日期，包含当天，不能早于 `fromDate` |
| `granularity` | `AUTO \| DAY \| MONTH \| YEAR` | 否 | `trend` 和 `periods` 的分组粒度，默认 `AUTO` |

日期参数是账本时区下的自然日期，不是 UTC 时间戳。服务端将本地日期转换为数据库查询区间 `[startAt, endAt)`：

```text
fromDate = 2026-11-01
toDate   = 2026-11-30
timezone = Asia/Shanghai

查询区间 = 2026-11-01T00:00:00+08:00（包含）
        到 2026-12-01T00:00:00+08:00（不包含）
```

接口响应同时返回本地日期范围和账本时区，前端跳转账单时使用响应中的 `startAt`、`endAt`，不要自行按浏览器时区重算。

规则：

- `WEEK`：账本时区下周一至周日；`anchorDate` 落在哪一周就查询哪一周。
- `MONTH`：账本时区下自然月的第一天至最后一天。
- `YEAR`：账本时区下自然年 1 月 1 日至 12 月 31 日。
- `ALL`：从当前用户在当前账本可见的第一笔未删除收入/支出账单所在自然日开始，到当前账本时区的今天结束。起始日期只受账本成员和私人账户可见性影响，不受本次关键词、分类、账户或付款人过滤影响；没有可见账单时范围为 `null`。
- `RANGE`：`fromDate` 和 `toDate` 均包含，服务端按账本时区转换边界。
- 在有夏令时的账本时区中，服务端分别计算本地周期起点和下一周期起点再转换 UTC；不能假设每个自然日固定为 24 小时。
- `WEEK/MONTH/YEAR` 的 `anchorDate` 不能晚于账本时区的今天；当前自然周期的结束日期可以晚于今天。`RANGE` 的 `toDate` 不能晚于今天。
- `RANGE` 默认最多支持 3660 个本地自然日；超过上限返回 `40022`，避免一次请求生成不可控的日粒度数据。
- 不同 `period` 的专属日期参数不能混用：`WEEK/MONTH/YEAR` 只接受 `anchorDate`；`RANGE` 只接受 `fromDate/toDate`；`ALL` 不接受这些日期参数。组合缺失或冲突时返回 `40021`。

### 4.2 过滤参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | `EXPENSE \| INCOME` | 否 | `categories` 默认 `EXPENSE`；其他三个接口传入时也会过滤账单类型，未传时统计两类 |
| `accountId` | UUID | 否 | 账户过滤，不包含没有账户的账单 |
| `payerId` | UUID | 否 | 付款人过滤，只匹配该账本活跃成员作为付款人的账单 |
| `keyword` | string | 否 | 标题或备注不区分大小写包含匹配；聚合前去除首尾空格；categories 在校验前处理，空字符串视为未传，非空去空格后须为 1–100 字符；其他接口原始字符串须为 1–100 字符，纯空白通过校验后视为未传 |
| `includeComparison` | `true \| false` | 否 | `categories` 是否返回上一对应周期对比，默认 `false`；`ALL` 不支持对比 |

以下参数按接口使用，不属于所有接口共有参数：

| 参数 | 适用接口 | 说明 |
| --- | --- | --- |
| `categoryId` | `overview`、`trend`、`periods` | 精确分类过滤；与 `categoryRootId` 互斥 |
| `categoryRootId` | `overview`、`trend`、`periods` | 过滤一级分类及其全部二级分类 |
| `categoryLevel` | `categories` | `ROOT` 或 `CHILD`，默认 `ROOT` |
| `categoryRootId` | `categories` | 分类下钻上下文；`categoryLevel=CHILD` 时必填 |
| `sortBy` | `categories` | `AMOUNT` 或 `PERCENTAGE`，默认 `AMOUNT` |
| `sortOrder` | `categories` | `ASC` 或 `DESC`，默认 `DESC` |
| `metric` | `trend` | `EXPENSE`、`INCOME` 或 `NET`，默认 `EXPENSE`；决定 `valueCents` 的含义 |

过滤参数只改变聚合数据，不改变 `range` 的自然日期边界。`overview`、`trend` 和 `periods` 中的分类 ID 按分类过滤数据；`categories` 中的 `categoryRootId` 表示分类树展示上下文。ID 须为 UUID。categories 会显式校验 `categoryRootId` 属于当前账本、类型匹配且为一级分类，否则返回 `40421`；其他接口的分类过滤，以及所有接口的账户和付款人过滤通过查询条件约束，不额外返回资源不存在错误，不匹配或不可见时得到空聚合。`payerId` 还要求付款人为当前账本活跃成员。categories 不接受精确 `categoryId`，单传返回 `40021`，与根分类同时传返回 `40023`。

### 4.3 粒度参数

`granularity=AUTO` 的默认规则：

| 统计模式 | 默认粒度 |
| --- | --- |
| `WEEK` | `DAY` |
| `MONTH` | `DAY` |
| `YEAR` | `MONTH` |
| `ALL` | `YEAR` |
| `RANGE` | 本地日期跨度不超过 93 天使用 `DAY`；结束日期不晚于起始日期加 36 个月使用 `MONTH`；更长使用 `YEAR` |

`WEEK` 只允许 `DAY`，`MONTH` 允许 `DAY` 或 `MONTH`，`YEAR` 允许 `DAY`、`MONTH` 或 `YEAR`，`ALL` 只允许 `YEAR`；`RANGE` 允许 `DAY`、`MONTH` 或 `YEAR`。服务端必须保证返回周期数量可控：`DAY` 最多 366 个周期，`MONTH` 最多 120 个周期，`YEAR` 最多 120 个周期；超出限制返回 `40022`。周期按账本时区对齐，首尾周期允许是范围内的部分周期，响应中的周期日期需裁剪到实际查询范围。

`granularity` 对 `overview` 和 `categories` 不改变业务聚合，仅作为统一 `range` 元数据回显；四个接口请求时应传入相同的时间和公共筛选上下文。

### 4.4 请求示例

当前月统计：

```text
GET /api/ledgers/ledger-uuid/statistics/overview?period=MONTH&anchorDate=2026-11-04
```

自定义范围的分类统计：

```text
GET /api/ledgers/ledger-uuid/statistics/categories?period=RANGE&fromDate=2026-10-01&toDate=2026-10-31&type=EXPENSE&categoryRootId=category-uuid&includeComparison=true
```

年度趋势：

```text
GET /api/ledgers/ledger-uuid/statistics/trend?period=YEAR&anchorDate=2026-01-01&granularity=MONTH
```

## 5. 统一响应中的时间范围

四个接口都返回以下结构：

```json
{
  "period": "MONTH",
  "timezone": "Asia/Shanghai",
  "fromDate": "2026-11-01",
  "toDate": "2026-11-30",
  "startAt": "2026-10-31T16:00:00.000Z",
  "endAt": "2026-11-30T16:00:00.000Z",
  "granularity": "DAY"
}
```

`fromDate` 和 `toDate` 是包含边界的本地日期；`startAt` 和 `endAt` 是用于账单查询下钻的 UTC 半开区间，其中 `endAt` 严格不包含。`ALL` 没有可见账单（或首笔可见账单在未来）时，仅 `fromDate`、`toDate`、`startAt`、`endAt` 为 `null`；`period=ALL`、`timezone` 和 `granularity=YEAR` 仍然返回。

分类对比数据使用当前范围前紧邻的对应周期：周对比上一周，月对比上月，年对比上一年；自定义范围按相同的本地自然日数量向前推移。`ALL` 不支持对比。对比范围不能与当前范围重叠。

## 6. 查询统计概览

### 6.1 `GET /api/ledgers/:ledgerId/statistics/overview`

响应 `data`：

```json
{
  "ledgerId": "ledger-uuid",
  "range": {
    "period": "MONTH",
    "timezone": "Asia/Shanghai",
    "fromDate": "2026-11-01",
    "toDate": "2026-11-30",
    "startAt": "2026-10-31T16:00:00.000Z",
    "endAt": "2026-11-30T16:00:00.000Z",
    "granularity": "DAY"
  },
  "totalIncomeCents": 500000,
  "totalExpenseCents": 218050,
  "netCents": 281950,
  "averageDailyExpenseCents": 109025,
  "effectiveDayCount": 2,
  "transactionCount": 8
}
```

统计规则：

- `netCents = totalIncomeCents - totalExpenseCents`，可以为负数。
- `effectiveDayCount` 是应用完全相同的账本、权限和筛选条件后，存在当前用户可见账单的本地自然日数量，不是范围总天数，也不把未来空日期计入分母。
- `averageDailyExpenseCents = totalExpenseCents / effectiveDayCount`，结果按四舍五入保留为整数分；无有效自然日时返回 `0`。
- `transactionCount` 统计过滤后未删除的收入和支出账单数量。
- 没有符合条件的账单时所有金额和数量返回 `0`，时间范围仍按查询参数返回；`ALL` 无可见账单时范围字段为 `null`。

一期兼容期说明（尚未设定移除日期）：

- 仅 overview 在未传 `period` 时进入旧模式，支持可选 ISO `from/to`，也允许两者均不传或仅传一端；`from` 包含、`to` 不包含，两端同时传须满足 `from < to`。
- 旧响应恰为 `from`、`to`、`totalIncomeCents`、`totalExpenseCents`、`netCents`、`transactionCount`；缺失边界回显 `null`，不返回 `ledgerId`、`range`、日均或有效天数。
- 传 `period` 后使用二期响应，不附带旧 `from/to` 字段；不能混用旧边界和二期时间参数，也不能省略 `period` 而传 `anchorDate/fromDate/toDate/granularity`。
- trend、periods、categories 必须传二期时间参数，不提供旧模式；旧模式仍应用成员、私人账户、软删除和公共筛选规则。
- 共用 DTO 接受其他接口的合法专属字段；除 `type` 也参与公共过滤外，`metric` 仅影响 trend，分类展示、排序和对比字段仅影响 categories。

## 7. 查询收支趋势

### 7.1 `GET /api/ledgers/:ledgerId/statistics/trend`

趋势接口按统一 `range` 和 `granularity` 返回连续周期。默认包含范围内的零值周期，确保用户可以看到没有账单的日期、月份或年份。

响应 `data`：

```json
{
  "ledgerId": "ledger-uuid",
  "range": {
    "period": "MONTH",
    "timezone": "Asia/Shanghai",
    "fromDate": "2026-11-01",
    "toDate": "2026-11-30",
    "startAt": "2026-10-31T16:00:00.000Z",
    "endAt": "2026-11-30T16:00:00.000Z",
    "granularity": "DAY"
  },
  "hasData": true,
  "items": [
    {
      "fromDate": "2026-11-01",
      "toDate": "2026-11-01",
      "valueCents": 6800,
      "expenseCents": 6800,
      "incomeCents": 0,
      "netCents": -6800,
      "transactionCount": 2,
      "drilldown": {
        "from": "2026-10-31T16:00:00.000Z",
        "to": "2026-11-01T16:00:00.000Z"
      }
    }
  ]
}
```

`metric` 决定 `valueCents`：`EXPENSE` 返回 `expenseCents`，`INCOME` 返回 `incomeCents`，`NET` 返回 `netCents`。响应始终包含三个明细金额字段，前端可用明细金额切换展示；`valueCents` 始终对应本次请求的 `metric`，如依赖该字段则需按新 metric 重发请求。

每个周期的 `drilldown` 都使用 UTC 半开区间，前端跳转账单列表时带入当前 `ledgerId`、时间区间和公共过滤条件。若范围内至少有一笔可见账单，`items` 包含完整周期序列，空周期金额为零；若范围内没有可见账单，返回 `hasData=false` 和空 `items`，前端展示空状态。`ALL` 有数据时从首笔可见账单所在周期开始连续生成到今天所在周期；没有可见账单时范围为空且 `items` 为空。

趋势响应中的 `hasData` 表示当前用户在应用全部筛选条件后是否有可见账单；示例为 `true`。当 `hasData=false` 时金额数组为空，避免前端绘制全零趋势线。

## 8. 查询分类统计

### 8.1 `GET /api/ledgers/:ledgerId/statistics/categories`

分类接口默认统计支出，调用方可以通过 `type=INCOME` 切换收入。分类分组由 `categoryLevel` 控制：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `categoryLevel` | `ROOT` | `ROOT` 按一级分类汇总；`CHILD` 按选定一级分类下的二级分类汇总 |
| `categoryRootId` | 无 | 传入时只统计该一级分类及其子分类；`categoryLevel=CHILD` 时必填 |
| `sortBy` | `AMOUNT` | `AMOUNT` 或 `PERCENTAGE` |
| `sortOrder` | `DESC` | `ASC` 或 `DESC` |

无 `categoryRootId` 时 `ROOT` 返回全部一级分类汇总；传入 `categoryRootId` 时，`ROOT` 只返回该一级分类的聚合结果，`CHILD` 返回其子分类分布。

一级分类统计包含：

- 直接挂在该一级分类上的账单；
- 挂在该一级分类全部二级分类上的账单。

二级分类统计返回选定一级分类的直接子分类，并额外返回 `ROOT_DIRECT` 汇总行承接直接记在一级分类上的账单，避免下钻后丢失金额。该行展示名为“{一级分类名}（未细分）”，`categoryId` 为一级分类 ID，钻取使用精确 `categoryId`。没有分类的账单在 `ROOT` 视图汇总为 `categoryId=null` 的“未分类”；选择具体一级分类后不包含未分类账单。

统计必须包含仍被历史账单引用的停用分类；分类是否可用于新账单不改变其历史统计。`categoryRootId` 必须指向当前账本、收支类型匹配的一级分类；`CHILD` 模式返回它的直接二级分类。仅返回当前有金额或上一周期有对比数据的分类项，不合成没有数据的默认分类。

响应 `data`：

```json
{
  "ledgerId": "ledger-uuid",
  "type": "EXPENSE",
  "totalCents": 6800,
  "comparisonRange": null,
  "range": {
    "period": "MONTH",
    "timezone": "Asia/Shanghai",
    "fromDate": "2026-11-01",
    "toDate": "2026-11-30",
    "startAt": "2026-10-31T16:00:00.000Z",
    "endAt": "2026-11-30T16:00:00.000Z",
    "granularity": "DAY"
  },
  "items": [
    {
      "categoryId": "category-uuid",
      "categoryRootId": "category-uuid",
      "parentId": null,
      "bucketType": "CATEGORY",
      "name": "餐饮",
      "icon": "food",
      "color": "#F97316",
      "amountCents": 6800,
      "percentage": 100,
      "transactionCount": 2,
      "comparison": null,
      "drilldown": {
        "categoryRootId": "category-uuid",
        "from": "2026-10-31T16:00:00.000Z",
        "to": "2026-11-30T16:00:00.000Z",
        "type": "EXPENSE"
      }
    }
  ]
}
```

分类项的 `bucketType` 为 `CATEGORY`、`ROOT_DIRECT` 或 `UNCATEGORIZED`。`ROOT_DIRECT` 只在 `categoryLevel=CHILD` 且该一级分类当前或对比周期存在直接账单时返回；`UNCATEGORIZED` 只在 `ROOT` 视图返回。`percentage = amountCents / totalCents * 100`，服务端返回最多两位小数；总额为零时所有占比返回 `0`。`comparison` 字段始终存在，只有 `includeComparison=true` 时为对象，包含 `amountCents`、`amountDeltaCents` 和 `percentagePointDelta`；缺失的上一周期分类按零金额处理，上期总额为零时 `percentagePointDelta` 为 `null`。响应另返回 `comparisonRange` 的本地 `fromDate` 和 `toDate`。

未请求对比时，`comparison` 和 `comparisonRange` 返回 `null`。`includeComparison=true` 与 `period=ALL` 同时出现时返回 `40021`。

`totalCents` 是当前分类视图和公共过滤条件下的收入或支出总额：ROOT 全量视图包含全部分类和未分类；指定一级分类后只包含该分类树。分类项先按 `sortBy/sortOrder` 排序；金额或占比相同时按名称升序，再按 `categoryId` 升序，保证顺序稳定。

一级分类的 `drilldown.categoryRootId` 已可原样用于账单列表，同时匹配一级分类直接账单和直接二级分类账单。CHILD 普通行使用 `drilldown.categoryId` 精确筛选二级分类；`ROOT_DIRECT` 使用一级分类 ID 精确匹配直接账单。下钻还须携带返回的 `from/to/type`、当前 `ledgerId` 和已有的账户、付款人、关键词筛选；替换已有分类筛选，不能同时携带 `categoryId/categoryRootId`。

`UNCATEGORIZED` 返回 `drilldown.categoryId=null`，表示未分类语义；当前账单列表仅接受 UUID 分类参数，没有“仅未分类”筛选。前端不能把 null 序列化为字符串，也不能省略分类参数后宣称精确下钻，此项尚需后续扩展。仅上期有数据的分类也会返回，但其下钻仍指向当前范围，结果可以为空。

## 10. 统计过滤和数据口径

- 只统计当前账本内 `deletedAt IS NULL` 的 `EXPENSE` 和 `INCOME` 账单。
- 无账户账单仍参与统计；指定 `accountId` 后只统计该账户账单。
- `SHARED` 账户关联账单对当前账本活跃成员可见；`PRIVATE` 账户关联账单仅对账户所有者可见。
- 不可见私人账户账单不能出现在概览、趋势、分类或周期汇总中，也不能通过总数差异推断其存在。
- 账单的自然日期、周期边界和 `effectiveDayCount` 均按账本 `timezone` 计算，不按服务器时区或浏览器时区计算。
- `categoryId` 是精确分类筛选；`categoryRootId` 包含一级分类本身和全部二级分类。
- 关键词匹配账单标题或备注，规则与账单列表一致。
- 修改、软删除、恢复（如果未来支持）账单或切换账本后，前端必须重新请求统计，不复用其他账本或旧范围缓存。
- 统计页按角色只读；Viewer 可以查询和下钻账单，但不能从统计接口触发记账或账本管理写操作。

## 11. 错误约定

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `40001` | overview/trend/periods 的全局 DTO 校验失败：非法枚举、UUID、日期格式、关键词长度、时间组合冲突或分类参数互斥等 |
| `400` | `40021` | Service 时间解析失败（如未来日期、倒序范围、缺少 period）；categories 的 DTO 校验失败、单传 categoryId、旧 from/to、ALL 对比等非法参数 |
| `400` | `40022` | RANGE 超过 3660 个自然日，或周期数超出 DAY 366 / MONTH 120 / YEAR 120 限制 |
| `400` | `40023` | 仅 categories：categoryId 与 categoryRootId 冲突，或 CHILD 缺少 categoryRootId |
| `401` | `40101` | 没有有效登录会话 |
| `404` | `40421` | 非活跃账本成员；categories 根分类不存在、跨账本、类型不匹配或不是一级分类 |
| `500` | `50001` | 未处理的数据库聚合等服务端异常 |

不允许的 period/granularity 组合属于参数非法，不是范围过大：categories 返回 `40021`，其他接口在 DTO 阶段返回 `40001`。categories 自行映射 DTO 错误，其他三个接口保留全局 ValidationPipe 行为；调用方不能假定所有参数错误均为 `40021`。合法 UUID 过滤无匹配数据时返回零值或空项，不统一报 `40421`。

目前未配置统计专属限流，不声明必然返回 `42901`。错误由统一过滤器返回 `success=false`、`code`、`message`、`data`；全局 DTO 错误的 `data.details` 为校验信息。未处理异常不返回 Prisma 细节，当前响应不包含请求 ID。

## 12. 幂等、缓存和并发

统计接口是只读接口，不使用 `clientRequestId`，也不声明 `If-Match` 或其他并发请求头。初始实现不增加服务端统计缓存，以避免账单、成员权限或私人账户可见性变化后返回过期结果；后续只有在有实际性能数据时才评估缓存。

如果后续引入缓存，缓存键必须包含当前用户、账本、全部过滤参数和账本时区；命中缓存前仍需验证成员状态，权限或账单变化后必须使受影响结果失效，且不能跨用户复用私人账户统计。

## 13. 领域测试要求

- 时间范围：覆盖周一到周日、月份边界、年份边界、自定义范围包含首尾日期、未来日期拒绝和 `Asia/Shanghai` 本地日转换。
- 全部范围：覆盖从当前用户可见的第一笔账单开始、无可见账单返回空范围和有效自然日的计算。
- 概览：覆盖收入、支出、结余、日均支出四舍五入、有效自然日、空结果和对比范围。
- 趋势与周期：覆盖 DAY/MONTH/YEAR、AUTO、连续空周期补零、首尾部分周期和下钻半开区间。
- 分类：覆盖一级分类直接账单、二级分类账单、`categoryRootId`、未分类、金额/占比排序、零总额和环比。
- 数据隔离：覆盖账本成员、跨账本 ID、私人账户可见性、付款人、关键词和软删除过滤。
- Controller 契约：覆盖认证用户、路径参数、统一查询参数传递、非法粒度和错误码映射。
- 数据库集成：使用独立测试数据库验证时区边界、分类树聚合、并发写入后统计一致性；不能使用生产数据。

## 14. 实施状态与兼容边界

- 已实现：overview、trend、categories、periods 四个只读接口；overview 无 `period` 时继续返回旧版 `from/to` 响应。
- 已验证：账本时区范围、半开区间、夏令时、软删除和私人账户过滤、有效天数、ROOT/CHILD 分类聚合、未分类与未细分桶、周期对比及分类下钻。
- 数据库集成：隔离 PostgreSQL 16 上应用 7 条 migration；trend/periods 的 DAY、MONTH、YEAR 非空周期聚合及 23 小时夏令时日期通过验证。另有 61 项数据库和 HTTP 契约断言通过；HTTP 验证使用受控 Guard，不覆盖真实登录会话。
- 保留兼容：overview 无 `period` 的旧响应，移除日期尚未确定；二期调用应显式传 `period`。
- 当前边界：不同端点的 DTO 错误码保留差异；未分类精确账单下钻尚无列表参数；未引入统计缓存或专属限流。
