# 小宝记账账单接口

## 1. 公共约定

账单接口使用普通用户会话和 `/api` 前缀。所有资源都挂在账本下，服务端从认证上下文取得用户，再校验目标账本的活跃成员关系。账单金额使用整数分，时间使用带时区的 ISO 8601 字符串。

第一期只开放收入和支出，不提供转账接口。

本文档主体对应已交付的收入、支出、查询、编辑和软删除能力；第 7 节为三期新增的备注候选评审契约，实现前不能视为已交付。图片附件本期不做，接口见第 8 节的范围说明。

## 2. 接口总览

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/ledgers/:ledgerId/transactions` | `VIEWER+` | 分页查询账单 |
| `POST` | `/api/ledgers/:ledgerId/transactions` | `OWNER/EDITOR` | 创建收入或支出 |
| `GET` | `/api/ledgers/:ledgerId/transactions/:transactionId` | `VIEWER+` | 查询详情 |
| `PATCH` | `/api/ledgers/:ledgerId/transactions/:transactionId` | `OWNER/EDITOR` | 编辑账单 |
| `DELETE` | `/api/ledgers/:ledgerId/transactions/:transactionId` | `OWNER/EDITOR（仅自己创建）` | 软删除账单 |
| `GET` | `/api/ledgers/:ledgerId/note-suggestions` | `VIEWER+` | 查询当前用户历史备注候选（三期新增） |

## 3. 查询账单

账单列表、详情和分类根节点下钻筛选均已实现。

请求示例：

```text
GET /api/ledgers/:ledgerId/transactions?page=1&pageSize=20&type=EXPENSE&categoryRootId=uuid&accountId=uuid&from=2026-10-01T00:00:00.000Z&to=2026-11-01T00:00:00.000Z&keyword=早餐
```

支持的筛选字段：`type`、`categoryId`、`categoryRootId`、`uncategorized`、`accountId`、`payerId`、`from`、`to`、`keyword`。默认过滤软删除记录，按 `occurredAt DESC, createdAt DESC` 排序。

列表参数规则：`page` 默认 `1`，`pageSize` 默认 `20` 且最大 `100`；`from` 使用 `gte`，`to` 使用严格小于 `lt`；`from` 不能晚于或等于 `to`；`keyword` 会去除首尾空格，并对标题和备注执行不区分大小写的包含匹配。账单关联的共享账户对所有活跃成员可见，私人账户只对账户所有者可见；停用账户的历史账单仍可查询。

`categoryId` 是精确分类筛选；`categoryRootId` 必须指向当前账本的一级分类，并匹配直接记在该分类及其二级分类下的账单；`uncategorized=true` 只匹配 `categoryId IS NULL` 的账单。三个分类条件互斥，未分类筛选不能与任一分类 ID 同时传入；未传或传 `false` 表示不启用未分类筛选。不存在或其他账本的根分类 ID 返回 `40421`；同一账本的二级分类 ID 不能作为根节点，或分类条件冲突时返回 `40023`。停用根分类和子分类的历史账单仍参与匹配。统计 ROOT 行的 `drilldown.categoryRootId` 可原样传入；CHILD 普通行的 `drilldown.categoryId` 精确匹配子分类，`ROOT_DIRECT` 的该字段精确匹配根分类直接账单；`UNCATEGORIZED` 行使用 `drilldown.uncategorized=true`。下钻须同时带入返回的 `from/to/type`、当前账本和账户、付款人、关键词筛选，并移除旧分类筛选，确保分类条件互斥。

统计“未分类”行返回 `drilldown.uncategorized=true`，前端可以原样传给列表接口完成精确下钻；不能传字符串 `null`。列表对非法 UUID 等 DTO 字段校验返回全局 `40001`，上述 `40023` 是 Service 分类组合校验。精确 categoryId 不做存在性查询，无匹配记录时返回空分页。

响应 `data` 为统一分页对象，单项至少包含：

```json
{
  "id": "uuid",
  "ledgerId": "uuid",
  "type": "EXPENSE",
  "amountCents": 3500,
  "occurredAt": "2026-10-30T08:00:00.000Z",
  "title": "早餐",
  "note": null,
  "category": { "id": "uuid", "type": "EXPENSE", "name": "早餐", "parentId": "uuid" },
  "account": { "id": "uuid", "name": "微信", "visibility": "SHARED" },
  "payer": { "id": "uuid", "nickname": "小宝" },
  "createdById": "uuid",
  "createdBy": {
    "id": "uuid",
    "username": "xiaobao",
    "nickname": "小宝",
    "avatar": null
  },
  "updatedById": "uuid",
  "version": 1,
  "createdAt": "2026-10-30T08:00:00.000Z",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

详情接口必须重新从数据库读取并应用私人账户可见性校验，不能直接回显创建请求。

## 4. 创建账单

请求 Body：

```json
{
  "clientRequestId": "client-generated-uuid",
  "type": "EXPENSE",
  "amountCents": 3500,
  "occurredAt": "2026-10-30T08:00:00.000Z",
  "categoryId": "uuid",
  "accountId": null,
  "payerId": "uuid",
  "title": "早餐",
  "note": null
}
```

账单创建不接收附件；图片附件本期不做。

服务端校验：

- `clientRequestId` 必须是客户端生成的 UUID；
- `amountCents` 必须是正整数；
- `note` 最多 200 个字符；空备注传 `null`；
- `EXPENSE` 只能使用支出分类，`INCOME` 只能使用收入分类；
- 如果填写账户，账户、分类和付款人必须属于当前账本且处于允许状态；
- 私人账户只能由账户所有者使用；
- `payerId` 必须对应当前账本的活跃成员；
- 相同账本和 `clientRequestId` 已存在时返回第一次创建结果，不重复更新余额。

创建成功返回完整账单详情，状态码 `201`。账单、账户余额和审计记录必须同事务提交。

当前实现说明：

- 已支持 `EXPENSE` 和 `INCOME` 创建；其他账单类型不接受。
- `EDITOR` 和 `OWNER` 可以创建，`VIEWER` 返回 `40321`。
- 创建前校验填写的账户属于当前账本且对当前用户可见、账户启用、分类类型匹配且启用、付款人为当前账本活跃成员。
- 选择账户时，支出创建会扣减账户余额，收入创建会增加账户余额；未选择账户时不影响账户余额。
- `clientRequestId` 在账本内幂等；已存在时直接返回原账单，不重复更新余额和审计。
- 创建完成后重新读取完整账单详情返回，私人账户只允许账户所有者查看。

## 5. 编辑账单

`PATCH /api/ledgers/:ledgerId/transactions/:transactionId`

`OWNER` 和 `EDITOR` 可以编辑，`VIEWER` 拒绝。账户字段可传入新的账户、`null` 或省略；传入 `null` 表示取消账户关联，之后不再影响账户余额。

请求 Body 需要携带当前版本：

```json
{
  "version": 1,
  "amountCents": 4000,
  "occurredAt": "2026-10-30T08:00:00.000Z",
  "categoryId": "uuid",
  "accountId": null,
  "title": "早餐和咖啡",
  "note": null
}
```

允许修改金额、时间、分类、账户、付款人、标题和备注。不能修改 `ledgerId`、`createdById`、`clientRequestId` 和 `source`。`note` 最多 200 个字符，传 `null` 表示清空。

版本不匹配返回 `40922`，不得静默覆盖其他成员的修改。编辑成功后 `version` 递增，并返回数据库回读的最新详情。

## 6. 软删除账单

`DELETE /api/ledgers/:ledgerId/transactions/:transactionId`

请求 Body 携带当前版本：

```json
{ "version": 1 }
```

`DELETE` 只写入 `deletedAt` 并递增版本，同时在同一事务中恢复账户余额和写入删除审计。默认查询、统计和账户余额都排除已删除账单。

删除已删除账单时返回原业务结果，不重复恢复账户余额。删除前必须校验 `OWNER` 权限，或校验 `EDITOR` 是账单创建人，并检查当前版本。

## 7. 历史备注候选

### 7.1 `GET /api/ledgers/:ledgerId/note-suggestions`

返回当前用户在当前账本中最近使用过的备注文本，供记账抽屉在键盘上方展示快捷候选。

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `limit` | `number` | 否 | 默认 `10`，最大 `10`；超过最大值按 DTO 校验返回 `40001` |

请求示例：

```text
GET /api/ledgers/:ledgerId/note-suggestions?limit=10
```

成功响应：

```json
{
  "items": [
    {
      "text": "午餐",
      "lastUsedAt": "2026-11-08T12:30:00.000Z"
    },
    {
      "text": "地铁通勤",
      "lastUsedAt": "2026-11-07T08:15:00.000Z"
    }
  ]
}
```

规则：

- 只查询当前账本、当前用户 `createdById`、未删除账单中的非空备注；不返回其他成员创建的备注。
- 备注去除首尾空白后按文本去重，保留最近一次文本。
- 只返回不超过 200 个字符的备注；历史超长备注仍在账单详情中可读，但不进入候选。
- 按备注最近保存时间 `noteUpdatedAt` 倒序，再按账单创建时间倒序；不按账单金额、分类等无关字段排序。
- 固定上限、非分页；没有候选时返回 `{ "items": [] }`。
- 响应使用 `Cache-Control: private, max-age=30`；账单创建、编辑、删除后客户端应主动失效候选缓存。
- `VIEWER` 可以读取候选，但候选只包含该用户自己的历史备注，不扩大账单读取范围。
- 账本不可见返回 `40421`；`limit` 非法返回 `40001`。

### 7.2 备注长度

创建和编辑账单时 `note` 最多 200 个字符；空备注传 `null`。后端 DTO 与前端输入上限保持一致，不再保留 2000 字符的写入通道。

## 8. 图片附件：本期不做

账单图片附件与对象存储不在三期范围。本期不提供附件上传、读取、删除接口，不在账单详情返回 `attachments`，也不在列表返回 `attachmentCount`。

记账快捷条中的“图片”入口继续保持禁用或隐藏。后续若重新立项，存储选型、上传方式、权限、清理和备份方案以[账单图片附件与对象存储设计](../architecture/账单图片附件与对象存储设计.md)为起点重新评审，不能直接按该设计实施。

## 9. 错误码

| HTTP | code | 场景 |
| --- | --- | --- |
| `400` | `40021` | 金额、时间、类型或关联字段非法 |
| `400` | `40023` | `categoryId` 与 `categoryRootId` 同时传入或根分类层级错误 |
| `403` | `40321` | 当前角色不能创建、编辑或删除账单 |
| `404` | `40421` | 账本、账单或关联资源不可见 |
| `409` | `40921` | 账户/分类状态冲突 |
| `409` | `40922` | 版本冲突或幂等请求冲突 |
| `429` | `42901` | 备注候选请求超过限制 |

资源不可见时不能泄露其他账本、成员私人账户或账单是否存在。

`occurredAt` 必须是有日期、时间且带 `Z` 或 `±HH:mm` 偏移的 ISO 8601 字符串；日期-only、无偏移本地时间和非法日历日期返回 `40021`。

- 集成验证覆盖数据库唯一约束、事务回滚和并发更新，不使用真实用户数据。
