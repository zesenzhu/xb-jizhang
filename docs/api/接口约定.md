# 小宝记账接口约定

## 1. 文档范围

本文档定义 NestJS API 的公共通信规则。领域接口文档只补充业务参数和流程，不重复定义本文件中的响应、鉴权、错误、分页、金额、幂等和并发约定。

## 2. 基础约定

- API 全局前缀为 `/api`。
- 请求和响应使用 JSON；时间使用 ISO 8601 字符串。
- 资源 ID 使用 UUID 字符串。
- 用户可见错误信息使用中文；日志和内部错误可以包含英文技术信息，但不能直接泄露给用户。
- 请求 Body 使用 DTO 校验，未知字段默认被过滤，类型转换由全局 ValidationPipe 统一处理。
- API 文档由 NestJS Swagger 根据 DTO 和装饰器生成，Markdown 文档补充业务语义。

## 3. 认证约定

### 3.1 Cookie 会话

登录成功后由后端通过 HttpOnly Cookie 写入访问凭证和刷新凭证：

| Cookie | 用途 | 客户端脚本可读 |
| --- | --- | --- |
| `access_token` | 访问需要登录的接口 | 否 |
| `refresh_token` | 刷新访问凭证 | 否 |

前端请求通过同源 `/api` 访问后端，并携带 Cookie。Token 不保存到 localStorage，也不要求业务接口在请求 Body 中重复传递刷新凭证。

### 3.2 Cookie 和 CSRF

- 浏览器前端与 API 使用同源 `/api` 路径，生产 Cookie 必须启用 `Secure`，默认使用 `SameSite=Lax`。
- 所有修改、删除、邀请、退出和 Owner 转移等状态变更请求必须校验 `Origin` 或 `Referer`，不能只依赖前端按钮隐藏。
- 如果部署场景存在跨站请求需求，必须增加服务端生成并校验的 CSRF Token；CSRF Token 不能替代 HttpOnly Cookie，也不能作为用户身份凭证。
- 认证失败、来源校验失败和 CSRF 校验失败不能泄露账本、用户或邀请的存在性信息。

### 3.3 接口认证等级

- 公开接口：注册、登录、刷新和健康检查；
- 用户接口：必须有有效登录会话；
- 账本接口：必须登录，并且是目标账本的活跃成员；
- 普通管理接口：必须登录，并且拥有接口要求的账本成员角色。
- 平台管理接口：必须使用 `AdminAuthGuard`，并且拥有接口声明的 `AdminPermission` 权限码；不能使用普通用户 Cookie 或 `LedgerMember` 角色代替。

### 3.4 双身份域

普通用户和平台管理员共用 `/api` 前缀，但路径、Cookie、JWT audience、刷新会话和 Guard 独立：

| 身份 | API 路径 | Access Cookie | Refresh Cookie | audience |
| --- | --- | --- | --- | --- |
| 普通用户 | `/api/auth/**`、普通业务接口 | `access_token` | `refresh_token` | `app` |
| 平台管理员 | `/api/admin/**` | `admin_access_token` | `admin_refresh_token` | `admin` |

普通用户 Token 访问 `/api/admin/**`，或管理员 Token 访问普通用户业务接口，都必须被服务端拒绝。管理端完整接口、权限码和审计约定见[管理端接口约定](./管理端接口约定.md)。

## 4. 成功响应

所有业务接口统一使用：

```json
{
  "success": true,
  "code": 0,
  "message": "操作成功",
  "data": {}
}
```

约定：

- `success` 成功时为 `true`；
- `code` 成功固定为 `0`；
- `message` 用于通用提示，不承载结构化字段错误；
- `data` 返回接口定义的业务数据，没有数据时使用 `null`，列表接口返回分页对象。

Controller 只返回业务数据，由全局响应拦截器统一包装，禁止每个 Controller 手工拼接响应外壳。

## 5. 错误响应

错误统一使用：

```json
{
  "success": false,
  "code": 40101,
  "message": "登录状态已失效",
  "data": null
}
```

建议错误码按领域分段：

| 范围 | 领域 |
| --- | --- |
| `400xx` | 请求参数和业务校验 |
| `401xx` | 登录、凭证和会话 |
| `403xx` | 角色或成员权限 |
| `404xx` | 资源不存在或当前用户不可见 |
| `409xx` | 唯一约束、幂等和并发冲突 |
| `429xx` | 限流 |
| `500xx` | 服务端异常 |

认证和资源错误不能泄露不必要的用户、账本或成员存在性信息。字段级校验错误可以在 `data` 中返回结构化内容，例如：

```json
{
  "success": false,
  "code": 40001,
  "message": "请求参数校验失败",
  "data": {
    "fields": {
      "password": ["密码长度不符合要求"]
    }
  }
}
```

## 6. 分页和筛选

列表接口默认使用 `page` 和 `pageSize`：

```text
GET /api/ledgers?page=1&pageSize=20
```

分页响应统一为：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20,
  "hasNextPage": false
}
```

约定：

- `page` 从 `1` 开始；
- `pageSize` 由服务端设置上限，客户端不能通过超大值绕过限制；
- 时间筛选使用明确的开始和结束时间，避免依赖数据库默认时区；
- 账本资源查询必须从认证上下文取得当前用户，再校验 `ledgerId`。

## 7. 金额、时间和枚举

- 金额传输使用整数分字段，例如 `amountCents: 1250` 表示 `12.50` 元；
- 服务端禁止使用浮点数进行金额计算；
- 时间传输使用带时区的 ISO 8601 字符串；
- 角色、账本类型、成员状态、账单类型和数据来源使用明确枚举，不接受任意字符串；
- 前端展示元、日期和本地化文本，API 负责稳定的数据语义。

## 8. 幂等和并发

### 8.1 幂等创建

账单等支持离线重试的创建接口必须接收 `clientRequestId`：

```json
{
  "clientRequestId": "client-generated-uuid",
  "amountCents": 1250
}
```

同一个账本中再次提交相同 `clientRequestId` 时，服务端返回第一次创建的业务结果，不重复创建。不同账本可以使用相同的客户端 ID。

### 8.2 并发修改

需要并发控制的更新接口在 Body 中携带服务端返回的 `version` 或明确的 `updatedAt`。接口文档没有声明时，客户端不得自行添加 `If-Match` 等请求头。

版本不一致返回 `409xx` 冲突错误，并返回当前资源所需的最小信息；服务端不能静默覆盖其他成员刚刚保存的数据。

## 9. 账本权限

账本相关路径通常包含 `:ledgerId`。服务端必须：

1. 从 Cookie 解析当前用户；
2. 查询当前用户在目标账本中的活跃成员关系；
3. 检查接口要求的 `OWNER`、`EDITOR` 或 `VIEWER` 角色；
4. 再读取或修改账本资源。

请求体中的 `userId`、`operatorId` 或 `role` 不能覆盖认证上下文和服务端权限判断。

## 10. HTTP 方法和状态码

| 场景 | 方法 | 成功状态 |
| --- | --- | --- |
| 创建资源 | `POST` | `201` 或接口约定的 `200` |
| 查询资源 | `GET` | `200` |
| 修改资源 | `PATCH` | `200` |
| 删除/停用资源 | `DELETE` 或 `PATCH` | `200` |
| 无响应体的成功操作 | 任意适用方法 | `204`，需在领域文档明确 |

业务错误使用对应的 HTTP 状态码和统一错误体，不使用 `200` 隐藏失败。

## 11. 日志和安全

- 访问日志可以记录请求 ID、方法、路径、状态码和耗时；不要记录密码、Cookie、Token 或完整账单敏感内容。
- 错误日志记录服务端堆栈和关联请求 ID，响应只返回用户可理解的信息。
- 认证、登录失败、刷新和邀请接口需要限流；具体限流键和窗口在后端技术文档中定义。
- 生产环境 CORS 使用明确白名单，Cookie 根据 HTTPS 部署设置 `Secure` 和 `SameSite`。

## 12. 文档和实现流程

每个领域接口按以下顺序维护：

1. 需求文档先确定用户目标、角色和验收标准；
2. 领域 API 文档确定路径、DTO、响应和错误场景；
3. NestJS Controller、Service 和测试按 API 文档实现；
4. Swagger 生成结果与 Markdown 进行接口契约检查；
5. 接口变更同步更新前端调用说明和相关需求文档。

## 13. 敏感查询参数与日志

- 邀请 Token 等敏感值不得写入访问日志、错误日志、页面标题或分享文案。
- Token 位于查询串时，反向代理访问日志必须隐藏或脱敏对应参数；不能只依赖应用层不记录。
- 邀请相关响应使用 `Cache-Control: no-store`，避免共享设备或代理缓存越权内容。
- `Referrer-Policy` 应避免把包含 Token 的完整邀请 URL 发送给第三方资源。
- 三期不提供图片附件上传、读取或二进制响应接口。第四期采用预签名直传和短期签名读取，具体接口以[第四期账单图片附件与对象存储设计](../architecture/账单图片附件与对象存储设计.md)为准；当前尚未实施。
