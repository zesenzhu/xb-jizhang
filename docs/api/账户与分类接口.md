# 小宝记账账户与分类接口

## 1. 公共约定

所有接口使用 `/api` 前缀、普通用户 Cookie 会话和统一响应结构。账本资源必须先校验当前用户的 `LedgerMember(status=ACTIVE)`。分页、错误、金额和时间格式遵循[接口约定](./接口约定.md)。

## 2. 账户接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/ledgers/:ledgerId/accounts` | `VIEWER+` | 查询当前可见账户 |
| `POST` | `/api/ledgers/:ledgerId/accounts` | `OWNER` 或创建私人账户的 `EDITOR` | 创建账户 |
| `PATCH` | `/api/ledgers/:ledgerId/accounts/:accountId` | 共享账户 `OWNER`；私人账户 `ownerId` 本人 | 编辑或停用账户 |

### 2.1 查询账户

请求：

```text
GET /api/ledgers/:ledgerId/accounts?page=1&pageSize=20&includeInactive=false
```

默认返回当前用户可见且启用的账户。`includeInactive=true` 允许 `OWNER` 查询当前账本停用账户，`EDITOR` 只能查询自己拥有的停用私人账户；`VIEWER` 不能查询停用账户。返回结果不能包含其他成员的私人账户。

响应 `data`：

```json
{
  "items": [
    {
      "id": "uuid",
      "ledgerId": "uuid",
      "ownerId": null,
      "name": "微信",
      "type": "WECHAT",
      "visibility": "SHARED",
      "initialBalanceCents": 0,
      "currentBalanceCents": 125000,
      "includeInAssets": true,
      "icon": null,
      "color": null,
      "isActive": true,
      "createdAt": "2026-10-30T00:00:00.000Z",
      "updatedAt": "2026-10-30T00:00:00.000Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20,
  "hasNextPage": false
}
```

### 2.2 创建账户

请求 Body：

```json
{
  "name": "我的现金",
  "type": "CASH",
  "visibility": "PRIVATE",
  "initialBalanceCents": 10000,
  "includeInAssets": true,
  "icon": null,
  "color": null
}
```

服务端规则：

- `PRIVATE` 自动使用当前用户作为 `ownerId`，忽略客户端传入的 `ownerId`；
- `SHARED` 只允许 `OWNER` 创建且 `ownerId` 必须为空；
- 账户类型必须是受控枚举；
- 初始余额为整数分，默认 `0`；
- 成功返回创建后的完整账户详情，状态码 `201`。

### 2.3 编辑或停用账户

请求 Body 可包含 `name`、`icon`、`color`、`includeInAssets`、`isActive`。不能通过接口直接修改 `ledgerId`、`ownerId`、`visibility` 或 `currentBalanceCents`。

被账单引用的账户只能设置 `isActive=false`，不能物理删除。停用账户不能用于新增账单，重新启用需要再次校验账户管理权限。

账户错误码：

| HTTP | code | 场景 |
| --- | --- | --- |
| `400` | `40021` | 名称、类型或金额非法 |
| `403` | `40321` | 当前角色不能管理账户 |
| `404` | `40421` | 账本或账户不可见 |
| `409` | `40921` | 账户状态或并发更新冲突 |

## 3. 分类接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/ledgers/:ledgerId/categories` | `VIEWER+` | 查询分类 |
| `POST` | `/api/ledgers/:ledgerId/categories` | `OWNER` | 创建分类 |
| `PATCH` | `/api/ledgers/:ledgerId/categories/:categoryId` | `OWNER` | 编辑、排序或停用分类 |

### 3.1 查询分类

请求：

```text
GET /api/ledgers/:ledgerId/categories?type=EXPENSE&includeInactive=false
```

默认按 `parentId`、`sortOrder`、名称返回启用分类。支持 `page`（默认 `1`，最小 `1`）、`pageSize`（默认 `20`，最大 `100`）、`type`（`EXPENSE` 或 `INCOME`）和 `includeInactive`（默认 `false`）。`includeInactive=true` 只允许 `OWNER` 使用。响应返回分类 ID、账本 ID、类型、名称、父级分类 ID、图标、颜色、排序、系统标识和启用状态，并使用统一分页结构。

`parentId=null` 表示一级分类；非空时父级必须是同一账本、同一收支类型的启用一级分类。分类最多两级，有子分类的一级分类仍可直接用于账单。

新建注册用户的默认个人账本，以及通过账本创建接口新建的账本，都会初始化需求文档第 9.2 节的默认分类目录，共 16 个一级分类和 49 个二级分类。一级分类和二级分类的 `isSystem` 均为 `true`，初始化与账本创建在同一事务内完成。历史账本通过版本化 Migration 按账本、类型、父级和名称补齐缺失默认分类，已有分类和历史账单关联不修改、不删除；因此存在旧分类名称时，历史账本的分类总数可能多于 65 条。

完整目录以《一期账本与记账需求》第 9.2 节为产品事实源，覆盖餐饮、交通、购物、居住、生活服务、医疗健康、教育学习、娱乐休闲、人情往来、其他支出，以及工资收入、经营收入、投资理财、报销退款、人情收入、其他收入。

### 3.2 创建分类

请求 Body：

```json
{
  "type": "EXPENSE",
  "name": "餐饮",
  "sortOrder": 10,
  "icon": null,
  "color": null
}
```

同一账本、同一 `type`、同一 `parentId` 下名称不能重复；收入和支出允许同名。服务端必须以规范化后的名称进行冲突校验，并使用数据库唯一约束兜底。成功返回完整分类详情，状态码 `201`。

二级分类创建时必须提交一级 `parentId`；不能引用其他账本、其他收支类型、停用分类或已有父级的二级分类。

### 3.3 编辑、排序或停用分类

请求 Body 可包含 `name`、`parentId`、`sortOrder`、`icon`、`color`、`isActive`。不能修改 `ledgerId`、`type` 和 `isSystem`。设置 `parentId` 时仍必须满足二级分类父级规则，不能形成三级关系。

被账单引用的分类只能停用，停用后不能用于新增账单，历史账单仍然保留分类关联。系统默认分类不允许物理删除。

分类错误码：

| HTTP | code | 场景 |
| --- | --- | --- |
| `400` | `40021` | 名称、类型或排序值非法 |
| `403` | `40321` | 当前角色不是 `OWNER` |
| `404` | `40421` | 账本或分类不可见 |
| `409` | `40921` | 同类型名称重复或状态冲突 |

## 3.4 第五期图标字段

第五期新增的分类图标资源、图标库、图片上传会话和恢复默认接口单独维护在[分类图标接口](./分类图标接口.md)。本接口的分类列表、新增和编辑响应会增加以下字段：

```text
iconSource: NONE | LIBRARY | IMAGE
iconKey: string | null
iconAssetId: uuid | null
iconUrl: string | null
iconUrlExpiresAt: ISO 8601 | null
color: string | null
```

旧版 `icon` 字符串只作为迁移兼容字段处理，客户端不能继续提交任意组件名或图片地址。字段组合由服务端校验：`LIBRARY` 必须有受控 `iconKey`，`IMAGE` 必须有当前账本下已确认的 `iconAssetId`，`NONE` 不能携带两者。

默认分类通过稳定 `defaultKey` 识别，Owner 修改分类名称、排序或停用状态不会改变该键；恢复默认图标只恢复图标和默认颜色。

## 4. 测试要求

- Service 测试覆盖账本隔离、共享/私人账户可见性、角色权限、停用资源和唯一冲突；分类测试覆盖活跃分类查询、类型筛选、停用分类权限、名称规范化和重复名称冲突。
- Controller 测试覆盖路径参数、DTO、认证用户上下文、分页/筛选和异常映射；分类 Controller 测试覆盖查询、创建和编辑字段契约。
- Prisma 集成验证覆盖账户类型约束、分类唯一约束和被引用资源停用行为。
