# 小宝记账管理端接口约定

## 1. 文档范围

本文档定义平台管理端 NestJS API 的认证、权限、路径、请求字段、错误、审计、幂等和并发约定。所有接口仍遵循[接口约定](./接口约定.md)的统一响应外壳，但不复用普通用户的登录凭证。

### 1.1 当前实现状态

当前后台已经实现并完成测试的接口为：

- 管理员登录、刷新、退出和当前管理员：`/api/admin/auth/**`；
- 普通用户分页、详情、状态管理：`/api/admin/users`；
- 账本分页、详情、归档/恢复：`/api/admin/ledgers`；
- 管理员账号列表、状态和角色绑定：`/api/admin/admin-users`；
- 管理审计日志分页查询：`/api/admin/audit-logs`。

敏感账单接口和系统配置接口目前只完成权限码、数据模型和接口约定，尚未进入后台实现范围；在对应模块落地前，前端不得调用这些路径。

## 2. 管理端认证

### 2.1 Cookie 和 Token

| Cookie | 用途 | 可被脚本读取 |
| --- | --- | --- |
| `admin_access_token` | 访问管理端接口 | 否 |
| `admin_refresh_token` | 刷新管理端访问凭证 | 否 |

管理员 JWT 必须包含并校验：

```json
{
  "sub": "admin-user-uuid",
  "type": "admin_access",
  "aud": "admin"
}
```

普通用户的 `access_token`、`refresh_token`、`type=access` 或 `aud=app` 不能访问 `/api/admin/**`。管理端刷新会话只存储在 `AdminRefreshSession`，不与普通 `RefreshSession` 混用。

### 2.2 认证接口

| 方法 | 路径 | 认证 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/api/admin/auth/login` | 公开 | 管理员登录 |
| `POST` | `/api/admin/auth/refresh` | 管理员刷新 Cookie | 轮换刷新会话 |
| `POST` | `/api/admin/auth/logout` | 管理员会话 | 撤销当前会话并清理 Cookie |
| `GET` | `/api/admin/auth/me` | `AdminAuthGuard` | 获取当前管理员资料和权限摘要 |

登录请求：

```json
{
  "username": "operator",
  "password": "password-123"
}
```

登录成功只通过 HttpOnly Cookie 返回 Token，响应数据只返回管理员公开资料和权限摘要。不能返回密码哈希、刷新 Token 原文或完整权限内部配置。

## 3. 权限要求

所有管理端业务接口都必须经过 `AdminAuthGuard`，再经过权限码校验。最低权限在接口表中声明：

| 方法 | 路径 | 最低权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/admin/users` | `admin:user:read` | 用户分页查询 |
| `GET` | `/api/admin/users/:userId` | `admin:user:read` | 用户详情脱敏查询 |
| `PATCH` | `/api/admin/users/:userId/status` | `admin:user:status` | 禁用/恢复用户 |
| `GET` | `/api/admin/ledgers` | `admin:ledger:read` | 账本分页查询 |
| `GET` | `/api/admin/ledgers/:ledgerId` | `admin:ledger:read` | 账本和成员摘要 |
| `PATCH` | `/api/admin/ledgers/:ledgerId/status` | `admin:ledger:status` | 归档/恢复账本 |
| `GET` | `/api/admin/transactions` | `admin:transaction:read_sensitive` | 敏感账单查询 |
| `GET` | `/api/admin/transactions/:transactionId` | `admin:transaction:read_sensitive` | 敏感账单详情 |
| `PATCH` | `/api/admin/transactions/:transactionId` | `admin:transaction:write` | 修改账单 |
| `POST` | `/api/admin/transactions/:transactionId/revoke` | `admin:transaction:write` | 撤销/恢复账单状态 |
| `GET` | `/api/admin/config` | `admin:config:read` | 查询受控配置 |
| `PATCH` | `/api/admin/config/:key` | `admin:config:write` | 修改受控配置 |
| `GET` | `/api/admin/audit-logs` | `admin:audit:read` | 查询管理审计日志 |
| `GET` | `/api/admin/admin-users` | `admin:admin_user:manage` | 管理员列表 |
| `PATCH` | `/api/admin/admin-users/:adminUserId` | `admin:admin_user:manage` | 管理员状态或角色 |

权限不足返回 `40302`。普通用户 Token 或无效管理员凭证返回 `40103`，不返回“该资源存在但你没有权限”等可枚举信息。

## 4. 用户和账本管理

### 4.1 用户查询

`GET /api/admin/users` 支持 `page`、`pageSize`、`keyword`、`status` 和 `createdFrom/createdTo`。结果至少包含用户 ID、用户名、昵称、邮箱脱敏值、账号状态、创建时间和账本数量，不包含密码哈希、Cookie、Token 和完整登录会话。

### 4.2 用户状态

`PATCH /api/admin/users/:userId/status` 请求体：

```json
{
  "status": "ACTIVE",
  "reason": "用户提交申诉后恢复账号",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

`status` 只允许服务端支持的状态。`reason` 是高风险操作必填字段；`updatedAt` 用于并发检查。成功后必须撤销受影响用户的普通刷新会话，并记录管理审计。

### 4.3 账本状态

`PATCH /api/admin/ledgers/:ledgerId/status` 请求体：

```json
{
  "status": "ARCHIVED",
  "reason": "用户申请归档",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

归档是软状态变更，不删除账单、成员、账户或分类。接口默认不允许修改 Owner、成员角色和账单内容。

## 5. 敏感账单接口

### 5.1 查询

查询敏感账单时必须具备 `admin:transaction:read_sensitive`，并提供 `reason` 查询参数或请求体字段。服务端对账单正文、备注、付款人和成员资料按最小必要原则返回，不能因为管理员身份自动返回全部字段。

### 5.2 修改

`PATCH /api/admin/transactions/:transactionId` 请求体至少包含：

```json
{
  "amountCents": 1250,
  "reason": "修复经用户确认的录入错误",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

服务端必须复用普通账单的金额、账户、分类和账本归属校验；版本不一致返回 `40902`，不能静默覆盖普通用户刚刚提交的内容。响应和审计都必须保留管理员操作来源。

## 6. 审计接口

`GET /api/admin/audit-logs` 支持以下筛选：

- `adminUserId`；
- `action`；
- `targetType`、`targetId`；
- `result`；
- `requestId`；
- `createdFrom`、`createdTo`；
- `page`、`pageSize`。

返回数据可以包含操作人、动作、目标、原因、脱敏前后摘要、结果、错误分类、IP、请求 ID 和时间，但不能返回 Token、密码、密钥或未脱敏个人敏感数据。

## 7. 错误约定

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `401` | `40103` | 管理员会话无效、普通用户 Token 或管理员账号停用 |
| `403` | `40302` | 管理员缺少目标权限码 |
| `404` | `40402` | 管理端可见范围内不存在目标资源 |
| `409` | `40902` | 并发版本冲突或状态不允许 |
| `422` | `42201` | 高风险操作缺少合法原因 |
| `429` | `42902` | 管理端登录或高风险操作限流 |

错误响应继续使用公共结构。对没有资源查看权限的管理员，不通过错误文案区分资源是否存在；审计失败信息只返回可处理的错误分类。

## 8. 幂等、并发和审计约束

- 状态变更、账单修改和配置修改请求必须支持客户端 `clientRequestId` 或服务端明确的幂等策略，重复提交不能重复产生业务变更或审计主记录。
- 所有更新接口必须携带 `updatedAt` 或 `version`；本接口未声明的请求不得自行添加 `If-Match`。
- 高风险操作在业务变更和审计写入之间使用同一数据库事务；审计写入失败时业务变更必须回滚。
- 登录失败和权限拒绝是否写入安全日志由后端实现统一处理，但不得记录密码、Cookie 或 Token 原文。

## 9. 测试要求

- 认证契约：校验方法、路径、Cookie、JWT `aud`、刷新轮换和错误码。
- 权限契约：覆盖 `SUPER_ADMIN`、`OPERATOR`、`AUDITOR` 的允许和拒绝场景。
- 用户/账本状态接口：校验 payload、原因、并发字段、会话撤销和审计写入。
- 敏感账单接口：校验无权限、无原因、脱敏、版本冲突、事务回滚和成功审计。
- 审计查询：校验筛选参数、分页、脱敏和不返回密码/Token/密钥。

## 10. 未决问题

1. 管理端是否强制 MFA，以及 MFA 凭证使用独立表还是外部身份服务。
2. 敏感账单是否需要双人审批，以及导出是否需要一次性授权。
3. 管理审计日志保留周期、归档方式和是否需要写入独立存储。
