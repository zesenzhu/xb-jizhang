# 小宝记账账本与成员接口

## 1. 文档范围

本文档定义普通用户的账本创建、查询、修改、切换偏好、复制、空账本删除、成员查询、邀请、角色变更、成员移除、主动退出和 Owner 转移接口。

所有接口都必须遵循[接口约定](./接口约定.md)中的统一响应、错误、分页和 Cookie 鉴权规则。除邀请查询外，账本资源接口必须先校验当前用户在目标账本中的活跃 `LedgerMember` 关系。

本文档定义已实现的一期用户账本与二期账本管理、成员和邀请接口。第一期邀请方式为“邮箱目标 + 一次性邀请 Token”；成员重新加入复用原成员关系，必须通过新的有效邀请完成。账本成员列表使用公共分页响应。

二期普通用户不提供账本归档、恢复、归档筛选或归档状态变更接口。有账单的账本只能继续保留，不能通过本领域接口永久删除。数据库中的 `isArchived` 是现有兼容字段；历史 `isArchived=true` 数据会保留，并按活跃成员关系继续显示。新客户端不得依赖该字段，`includeArchived` 也不属于二期目标契约。平台管理员接口另行维护，不通过普通用户接口治理账本。

## 2. 角色与状态

### 2.1 账本成员角色

| 角色 | 说明 |
| --- | --- |
| `OWNER` | 可以管理账本、成员和全部账本数据；一个账本至少保留一名 Owner |
| `EDITOR` | 可以查看账本并新增、编辑账单，不能管理成员或删除账单 |
| `VIEWER` | 只读访问账本、账户、分类、账单和统计 |

角色保存在 `LedgerMember.role`，不创建系统级 Role 表。邀请只能授予 `EDITOR` 或 `VIEWER`，不能通过邀请直接产生 `OWNER`。

### 2.2 成员状态

- `ACTIVE`：可以按角色访问账本。
- `LEFT`：成员主动退出后保留关系记录，但不能访问账本；重新加入必须创建新的邀请流程。
- `REMOVED`：被 Owner 移除后保留关系记录，但不能访问账本；Owner 必须重新邀请后才能重新加入。
- 重新加入使用原有 `[ledgerId, userId]` 成员关系，将状态改为 `ACTIVE` 并采用新邀请授予的 `EDITOR` 或 `VIEWER` 角色，不创建第二条成员关系。

### 2.3 账本字段

账本摘要至少包含：

```json
{
  "id": "ledger-uuid",
  "name": "家庭账本",
  "type": "SHARED",
  "defaultCurrency": "CNY",
  "timezone": "Asia/Shanghai",
  "icon": null,
  "color": null,
  "memberRole": "OWNER",
  "memberCount": 1,
  "isCurrent": true,
  "isDefault": true,
  "createdAt": "2026-10-30T08:00:00.000Z",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

`memberRole`、`memberCount`、`isCurrent` 和 `isDefault` 都是服务端根据当前用户的成员关系和偏好计算的字段，不能由客户端提交覆盖。`timezone` 使用 IANA 时区标识，默认值为 `Asia/Shanghai`。

## 4. 账本接口

### 4.1 `GET /api/ledgers`

返回当前登录用户的 `ACTIVE` 成员关系对应的账本。历史 `isArchived=true` 不会隐藏仍有活跃成员关系的账本；新客户端不应传 `includeArchived`，旧客户端即使传入也不会改变结果。接口不提供归档状态筛选或变更；响应按个人账本、共享账本的前端分组返回 `type` 和 `memberRole`。

列表响应使用公共分页结构，`items` 为账本摘要。服务端不能根据客户端传入的用户 ID 查询，查询条件必须来自认证上下文中的用户 ID。建议在同一查询中读取 `UserLedgerPreference`，填充 `isCurrent` 和 `isDefault`，避免前端逐个请求判断。

### 4.2 `POST /api/ledgers`

#### 请求体

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `name` | `string` | 是 | 去除首尾空白后不能为空；长度由 DTO 固定 |
| `type` | `PERSONAL \| SHARED` | 是 | `PERSONAL` 默认只能由创建者作为 Owner 使用 |
| `defaultCurrency` | `string` | 否 | 第一期默认 `CNY`；只接受服务端支持的货币代码 |
| `timezone` | `string` | 否 | IANA 时区标识；默认 `Asia/Shanghai` |
| `icon` | `string \| null` | 否 | 展示字段 |
| `color` | `string \| null` | 否 | 展示字段 |

创建账本必须在同一事务中写入 `Ledger` 和当前用户的 `OWNER` 成员关系。请求成功后返回账本摘要。

创建账本不会强制改变用户当前账本；客户端需要通过当前账本偏好接口显式切换。若用户没有可用的当前账本或默认账本，注册流程必须在创建“我的账本”时一并写入偏好。

### 4.3 `GET /api/ledgers/:ledgerId`

返回账本详情和当前用户的 `memberRole`。成员关系不存在、状态不是 `ACTIVE` 或账本 ID 不可见时，统一返回资源不可用错误，不泄露该账本是否存在。

### 4.4 `PATCH /api/ledgers/:ledgerId`

只有 `OWNER` 可以修改 `name`、`icon`、`color`、`defaultCurrency` 和 `timezone`。不能提交 `type`、`creatorId`、`memberRole`、成员关系或归档状态。

修改请求必须携带客户端最后一次读取到的 `updatedAt`，用于检测资料并发冲突。`defaultCurrency` 只有在账本不存在任何账单时允许修改，软删除账单也视为已存在账单；`timezone` 可以修改，但响应和文档必须提示它会改变统计的自然周期分组边界。修改成功后返回最新账本摘要。

请求示例：

```json
{
  "name": "家庭账本",
  "defaultCurrency": "CNY",
  "timezone": "Asia/Shanghai",
  "updatedAt": "2026-11-04T08:00:00.000Z"
}
```

### 4.5 `GET /api/me/ledger-preferences`

查询当前登录用户的当前账本和默认账本。服务端只能从认证上下文获取用户 ID，不能接受 `userId` 查询参数。

```json
{
  "currentLedgerId": "ledger-uuid",
  "defaultLedgerId": "ledger-uuid",
  "currentLedger": {
    "id": "ledger-uuid",
    "name": "家庭账本",
    "type": "SHARED",
    "defaultCurrency": "CNY",
    "timezone": "Asia/Shanghai",
    "memberRole": "OWNER"
  },
  "defaultLedger": {
    "id": "ledger-uuid",
    "name": "家庭账本",
    "type": "SHARED",
    "defaultCurrency": "CNY",
    "timezone": "Asia/Shanghai",
    "memberRole": "OWNER"
  },
  "updatedAt": "2026-11-04T08:00:00.000Z"
}
```

如果保存的账本已被删除、成员关系已失效或记录尚未迁移，服务端会在读取时回退到当前用户最早加入的 `ACTIVE` 账本，并在事务中修复偏好。没有可用账本时返回 `currentLedger: null`、`defaultLedger: null`；注册时会创建首本账本，但用户退出或被移除最后一本账本后可以暂时没有可访问账本。

### 4.6 `PATCH /api/me/ledger-preferences`

#### 请求体

```json
{
  "currentLedgerId": "ledger-uuid",
  "defaultLedgerId": "ledger-uuid"
}
```

两个字段均为可选，但至少提交一个字段。每个 ID 都必须对应当前用户的 `ACTIVE` 成员关系；不能通过该接口获得账本权限，也不能提交其他用户的账本。设置当前账本不会自动修改默认账本，设置默认账本也不会自动切换当前账本。

写入偏好必须在事务中重新校验成员状态。目标账本不可访问时返回 `40401`，成功后返回与查询接口相同的偏好结构。

### 4.7 `POST /api/ledgers/:ledgerId/copy`

只有源账本的 `OWNER` 可以复制。复制请求必须明确指定新账本名称和类型；未传的展示设置沿用源账本。

```json
{
  "name": "家庭账本模板",
  "type": "SHARED",
  "defaultCurrency": "CNY",
  "timezone": "Asia/Shanghai",
  "icon": "home",
  "color": "#F59E0B",
  "clientRequestId": "client-generated-uuid"
}
```

服务端在一个事务中完成：

1. 创建新的 `Ledger` 和操作者的 `OWNER` 成员关系；
2. 复制源账本的分类树、图标、颜色、排序、启用状态和系统标记，并重建父子分类 ID；
3. 不复制账单、软删除账单、账户、账户余额、成员、邀请、统计结果或其他账本业务历史。

复制结果默认不切换当前账本。`clientRequestId` 在当前用户范围内通过数据库唯一约束保证幂等；同一用户使用相同 ID 重试时返回首次创建的账本，不会再创建副本。

### 4.8 `DELETE /api/ledgers/:ledgerId`

只有 `OWNER` 可以永久删除账本。服务端先验证当前用户的活跃 Owner 关系并检查可说明的业务阻碍，再在删除事务中锁定并重新检查资格。事务按账本、用户、当前成员关系的顺序加行锁；删除前再次检查以下条件：

- 账本不存在任何账单，包括 `deletedAt` 不为空的软删除账单；
- 当前用户是活跃 Owner，且没有其他活跃成员；
- 没有状态为 `PENDING` 且尚未过期的邀请；
- 删除后当前用户仍至少拥有另一本可访问的活跃账本。

满足条件后永久删除账本及其成员、邀请、分类、账户等配置数据；指向它的当前/默认账本偏好和复制历史中的源/目标引用由外键置为 `null`。账本不能恢复。请求不接受 `force` 参数，也不能通过客户端绕过上述检查。成功响应为 `data: null`。

无活跃成员或账本不存在时返回 `40401`，非 Owner 返回 `40301`，且不能泄露无权用户的账本存在性。预检查发现以下阻碍时返回对应错误；加锁复核发现条件已变化时返回 `40902`：

| 错误码 | 删除阻碍 |
| --- | --- |
| `40911` | 账本存在账单，包括软删除账单 |
| `40912` | 账本仍有其他活跃成员 |
| `40913` | 账本仍有未过期的待处理邀请 |
| `40914` | 删除后用户将没有其他活跃账本 |

新增账单、邀请或成员与账本删除通过数据库外键行锁互斥；接受邀请在恢复旧成员关系前显式锁定账本。成员退出或移除只锁受影响用户来协调并发删除，不会因为用户将没有其他账本而拒绝退出/移除；因此并发时以取得用户锁的先后决定删除是否仍满足最后一本账本条件。

## 5. 数据模型影响

账本领域的持久化变化已通过 Prisma Schema 和 Migration 实施：

| 模型 | 变化 | 约束和说明 |
| --- | --- | --- |
| `Ledger` | 增加 `timezone` | IANA 时区字符串，默认 `Asia/Shanghai`；Migration 为既有账本回填该默认值 |
| `UserLedgerPreference` | 保存每个用户的当前账本和默认账本 | `userId` 唯一；`currentLedgerId`、`defaultLedgerId` 可空，目标账本必须通过活跃成员关系校验；Migration 为有活跃成员的用户选择最早加入的账本回填两项偏好 |
| `LedgerCopyRequest` | 持久化账本复制幂等记录 | 唯一约束 `[userId, clientRequestId]`，保存源账本、目标账本和创建时间；源/目标账本删除后对应引用置为 `null` |
| `Ledger` 分类关系 | 沿用现有 `Category.parentId` | 复制分类时通过源 ID 到目标 ID 的映射，先创建父分类再创建子分类 |

`UserLedgerPreference` 不改变 `LedgerMember.role`，也不授予账本访问权。当前/默认账本外键使用 `ON DELETE SET NULL`；成员离开或被移除后，读取偏好会回退到其他活跃账本，没有其他活跃账本时返回空摘要。既有账本迁移回填和删除级联行为已在隔离 PostgreSQL 数据库验证。

现有 `Ledger.isArchived` 是兼容字段，旧 `includeArchived` 查询参数可以被解析但不会影响列表；账本修改接口不接受 `isArchived` 写入。当前 Migration 保留历史字段和值；账本列表按活跃成员关系查询，不因 `isArchived` 隐藏账本。二期不提供归档、恢复或归档筛选接口。

## 6. 成员查询与角色管理

### 6.1 `GET /api/ledgers/:ledgerId/members`

所有活跃成员都可以查询成员列表。默认只返回 `ACTIVE` 成员和业务需要的公开资料：

```json
{
  "id": "member-uuid",
  "userId": "user-uuid",
  "role": "EDITOR",
  "status": "ACTIVE",
  "joinedAt": "2026-10-30T08:00:00.000Z",
  "user": {
    "id": "user-uuid",
    "username": "xiaobao",
    "nickname": "小宝",
    "avatar": null
  }
}
```

不得返回用户邮箱、密码、Token、登录状态或其他非成员业务需要的安全字段。是否返回 `LEFT`、`REMOVED` 历史成员需要单独的 Owner 审计接口，本接口第一期不返回。

### 6.2 `PATCH /api/ledgers/:ledgerId/members/:memberId/role`

#### 请求体

```json
{
  "role": "VIEWER"
}
```

只有当前成员为 `OWNER` 时允许操作。目标成员必须是同一账本的 `ACTIVE` 成员，角色只能为 `OWNER`、`EDITOR` 或 `VIEWER`。

普通角色调整不能造成账本没有 Owner。若目标是当前唯一 Owner，不能直接降级，必须使用 Owner 转移接口完成角色变更。

### 6.3 `DELETE /api/ledgers/:ledgerId/members/:memberId`

只有 Owner 可以移除其他成员。服务端将成员状态改为 `REMOVED`，保留成员关系用于审计和防止历史邀请误复活；默认不物理删除。不能移除自己，不能移除个人账本的唯一 Owner。

### 6.4 `POST /api/ledgers/:ledgerId/members/leave`

当前用户主动退出共享账本。服务端将自己的成员状态改为 `LEFT`。个人账本的唯一 Owner、共享账本的最后一名 Owner 都不能退出；个人账本没有退出操作，需保留或按空账本删除规则处理。

## 7. Owner 转移

### 7.1 `POST /api/ledgers/:ledgerId/ownership-transfer`

#### 请求体

```json
{
  "targetMemberId": "member-uuid"
}
```

当前用户必须是 Owner，目标成员必须是同一账本的 `ACTIVE` 成员。操作必须在一个数据库事务中完成：目标成员变为 `OWNER`，原 Owner 默认变为 `EDITOR`。

如果目标成员已经是 Owner，接口应返回幂等成功或明确的业务错误，具体行为在实现时保持一致；推荐返回当前 Owner 状态，不重复写审计记录。

### 7.2 主要错误

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `40001` | 目标成员 ID 格式错误或请求缺少必要字段 |
| `403` | `40301` | 当前用户不是 Owner |
| `404` | `40401` | 目标成员不属于当前账本或已不活跃 |
| `409` | `40902` | 角色状态在并发操作中已发生变化 |

## 8. 邀请接口

### 8.1 创建邀请

#### `POST /api/ledgers/:ledgerId/invitations`

只有 Owner 可以创建邀请。第一期使用邮箱作为邀请目标，角色只允许 `EDITOR` 或 `VIEWER`，有效期固定为 72 小时。

目标账本必须是 `SHARED`；个人账本即使当前用户是 Owner 也必须拒绝邀请请求，并返回 `40903`。邀请入口隐藏不能替代服务端校验。

```json
{
  "targetEmail": "member@example.com",
  "role": "EDITOR"
}
```

服务端先将 `targetEmail` 转为小写并去除首尾空格。同一账本、同一邮箱同时只能有一个 `PENDING` 邀请；存在未过期邀请时返回冲突，Owner 需要撤销或等待过期后重新邀请。

成功时服务端创建 `LedgerInvitation`，生成不可预测的一次性 Token，并只保存 Token 哈希。Token 不出现在后续列表接口中；如果一期由前端复制邀请链接而不是邮件发送，原始 Token 只在创建成功响应中返回一次。

返回数据示例：

```json
{
  "id": "invitation-uuid",
  "ledgerId": "ledger-uuid",
  "role": "EDITOR",
  "status": "PENDING",
  "targetEmail": "member@example.com",
  "expiresAt": "2026-11-02T08:00:00.000Z",
  "inviteToken": "one-time-token"
}
```

`inviteToken` 只能在创建响应中返回给 Owner；日志、普通查询和错误信息不得记录或返回完整 Token。邀请成功后必须登录，并校验当前用户已填写且已规范化的邮箱与目标邮箱完全匹配。第一期不允许没有匹配邮箱的用户接受邮箱邀请。

### 8.2 查询账本待处理邀请

#### `GET /api/ledgers/:ledgerId/invitations`

只有当前账本 Owner 可以查询该账本的邀请列表。默认返回 `PENDING` 邀请，并将已超过有效期但尚未被读取的邀请标记为 `EXPIRED`；响应只返回目标邮箱、角色、状态、创建时间和过期时间，不返回 Token 哈希或完整邀请 Token。

### 8.3 查询当前用户邀请

#### `GET /api/invitations`

只返回当前登录用户有权处理的 `PENDING` 邀请，默认按过期时间过滤。服务端不得接受 `userId` 或 `email` 查询参数作为可信身份来源。

### 8.4 接受邀请

#### `POST /api/invitations/accept`

```json
{
  "token": "one-time-token"
}
```

服务端在事务中完成 Token 哈希校验、过期校验、目标邮箱校验、成员关系恢复以及邀请状态更新。目标用户已经是该账本的 `ACTIVE` 成员时，不重复创建成员并返回状态冲突；目标用户是 `LEFT` 或 `REMOVED` 时，将原成员关系恢复为 `ACTIVE`，角色采用邀请中的 `EDITOR` 或 `VIEWER`。

成功响应返回账本摘要和当前成员角色。接受邀请不能产生 `OWNER`。

### 8.5 拒绝邀请

#### `POST /api/invitations/decline`

请求体与接受邀请相同。服务端校验邀请目标后，将状态更新为 `DECLINED`；重复拒绝已经处理的邀请应保持幂等。

### 8.6 撤销邀请

#### `DELETE /api/ledgers/:ledgerId/invitations/:invitationId`

只有 Owner 可以撤销本账本的 `PENDING` 邀请。撤销后状态变为 `REVOKED`，Token 立即失效。已接受、已拒绝、已过期的邀请不能通过该接口重新激活。

## 9. 成功响应、幂等与并发

### 9.1 成功响应

- `GET /api/ledgers` 返回公共分页对象，`items` 为账本摘要。
- `POST /api/ledgers`、`GET /api/ledgers/:ledgerId`、`PATCH /api/ledgers/:ledgerId` 和 `POST /api/ledgers/:ledgerId/copy` 返回最新账本摘要；复制接口可以额外返回 `copiedCategoryCount`。
- `GET/PATCH /api/me/ledger-preferences` 返回当前和默认账本 ID 及安全摘要。
- `GET /api/ledgers/:ledgerId/members` 返回公共分页对象，`items` 为成员安全摘要。
- 角色修改返回最新成员安全摘要；移除成员和主动退出返回 `data: null`。
- Owner 转移返回最新账本摘要和转移后的新旧成员角色，不能返回密码、Token 或内部安全字段。
- 邀请创建返回邀请摘要；`inviteToken` 只允许出现在创建成功响应中，接受、拒绝和撤销接口不返回完整 Token。

### 9.2 幂等与并发

- 账本创建和邀请创建第一期不支持离线重试幂等 ID；前端提交期间必须避免重复提交，重复的有效邀请按业务唯一性返回冲突。
- 接受、拒绝和撤销邀请是状态迁移操作。对已经达到目标终态的重复请求应保持幂等；对已经进入其他终态的请求返回状态冲突。
- 角色变更、移除、主动退出和 Owner 转移必须在事务中执行，并在更新前重新检查成员状态和 Owner 数量。并发操作导致前置条件失效时返回 `40902`，不能静默覆盖。
- 账本复制必须使用 `clientRequestId` 或等价的持久化幂等记录；同一用户重试同一复制请求时返回第一次复制结果，不得生成多个新账本。
- 账本删除必须在事务锁内重新检查账单、软删除账单、成员、待处理邀请和最后一本账本条件；并发新增账单、邀请、成员或成员状态变化导致条件失效时返回 `40902`，不能静默删除。
- 删除账本按 ledger → user → membership 顺序加锁；邀请接受在恢复成员前锁定 ledger，成员退出或移除在改状态前锁定受影响 user。
- 第一期成员表尚未暴露客户端 `version` 字段，因此不声明 `If-Match` 或自定义并发请求头；服务端以事务条件和数据库结果判断冲突。后续若需要解决同一成员的最后写入覆盖，应增加成员版本字段并同步更新本接口。
- 账本资料修改使用请求中的 `updatedAt` 作为客户端最后已知版本；时间不一致时返回 `40902`。请求示例：

```json
{
  "name": "家庭账本",
  "updatedAt": "2026-10-30T08:00:00.000Z"
}
```

## 10. 错误约定

账本和成员接口至少使用以下错误范围：

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `401` | `40101` | 没有有效登录会话 |
| `403` | `40301` | 已登录但角色不足或成员已失效 |
| `404` | `40401` | 资源不属于当前用户可见范围 |
| `409` | `40901` | 重复邀请、成员关系或唯一字段冲突 |
| `409` | `40902` | Owner 保护、角色并发冲突、偏好状态或删除条件并发变化 |
| `409` | `40903` | 个人账本不允许邀请成员 |
| `409` | `40911` | 账本存在账单（包括软删除账单），不能删除 |
| `409` | `40912` | 账本仍有其他活跃成员，不能删除 |
| `409` | `40913` | 账本存在待处理邀请，不能删除 |
| `409` | `40914` | 删除后用户将没有可用账本 |
| `429` | `42901` | 邀请、接受邀请等接口超过限流阈值 |

除 Owner 明确可见的管理场景外，不能用错误信息区分“账本不存在”和“当前用户不是成员”。

## 11. 权限与事务检查清单

- 所有 `:ledgerId` 都从认证用户开始查询 `LedgerMember`，不能只查询账本本身。
- `VIEWER` 只能执行读取接口；`EDITOR` 不能访问成员和账本管理写接口；`OWNER` 才能管理成员和邀请。
- 个人账本只能保留创建者 Owner，不能邀请成员；共享账本才允许成员和邀请流程。
- 当前账本和默认账本偏好必须校验目标账本的活跃成员关系，不能把偏好写入当作授权操作。
- 偏好没有可访问账本时允许返回 `currentLedger: null` 和 `defaultLedger: null`；成员退出或被移除最后一本账本不因偏好状态而被阻止。
- 角色变更、成员移除、主动退出和 Owner 转移必须使用数据库事务。
- Owner 转移前后都必须保证账本至少有一名 `OWNER`。
- 成员移除和主动退出立即阻断后续账本请求，不能依赖前端重新登录或刷新。
- 邀请 Token 使用不可预测随机值、过期时间和一次性状态，不能把 Token 当作用户身份。
- 二期普通用户接口不得新增归档、恢复、归档筛选或通过归档绕过删除限制的行为。
- 账本修改、成员变更和邀请状态变更需要记录请求 ID 或审计信息，便于定位共享账本争议。

## 12. 领域测试要求

- 账本 Service：覆盖创建账本事务、个人/共享类型、账本列表只返回当前用户活跃成员关系。
- 账本偏好：覆盖当前/默认账本读取、不可访问账本、成员失效后的回退和删除后的偏好清理。
- 账本复制与删除：覆盖分类树复制不复制账单、复制幂等、软删除账单阻止删除、其他成员/待处理邀请/最后一本账本保护。
- 成员权限：覆盖 `OWNER`、`EDITOR`、`VIEWER`、跨账本成员 ID、`LEFT` 和 `REMOVED` 状态。
- Owner 保护：覆盖最后一名 Owner 不能降级、移除或退出，以及 Owner 转移的原子性。
- 邀请流程：覆盖角色限制、Token 过期、Token 撤销、目标邮箱校验、重复接受和重复拒绝。
- Controller 契约：覆盖路径参数、认证上下文、请求体过滤、成功响应字段和主要异常映射。
- 数据库集成：覆盖 `[ledgerId, userId]` 成员唯一约束、邀请状态更新和事务回滚；必须使用隔离测试数据库。

## 13. 邀请交付方式

本期后端不发送邀请邮件。创建邀请时仅向 Owner 返回一次性 `inviteToken`；客户端负责生成并展示可分享的邀请链接，Token 不能从后续查询中再次读取。
