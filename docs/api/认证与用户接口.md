# 小宝记账认证与用户接口

## 1. 文档范围

本文档定义第一期注册、登录、会话刷新、退出登录和当前用户资料接口。公共响应、错误、Cookie、时间和字段校验规则以[接口约定](./接口约定.md)为准；本文档只记录认证与用户领域的路径、参数、权限和业务约束。

本文档处于 `draft` 状态，接口实现前需要根据 DTO、Swagger 和测试结果更新为已评审版本。

## 2. 认证与安全约束

- 注册、登录和刷新接口不要求已有登录状态；用户资料接口必须有有效访问会话。
- 登录成功后，服务端通过 HttpOnly Cookie 写入 `access_token` 和 `refresh_token`，响应 Body 不返回 Token 明文。
- Cookie 的 `Secure`、`SameSite`、`Domain` 和过期时间由部署环境配置；生产环境必须使用 HTTPS。
- `refresh_token` 只能用于 `POST /api/auth/refresh`，不能作为普通业务接口的认证凭证。
- 刷新会话以 PostgreSQL 中的服务端记录为权威来源；Redis 只用于限流、缓存和短期锁，不作为唯一会话存储。
- 每次刷新都轮换刷新凭证，服务端只保存 Token 哈希；重复使用已经轮换或撤销的旧凭证时，撤销对应的会话链。
- 登录失败、刷新失败和账号停用使用不泄露账号存在性的错误信息。
- 密码只保存不可逆哈希；密码、密码哈希、Cookie 和 Token 不得出现在响应、普通业务日志或异常信息中。
- 注册和登录需要按 IP、账号标识或设备维度限流，具体窗口由后端基础设施实现确定。
- 所有状态变更请求校验 `Origin` 或 `Referer`；如果部署场景无法完全依赖 `SameSite`，则增加 CSRF Token。

## 3. 接口总览

| 方法 | 路径 | 登录要求 | 说明 | 成功状态 |
| --- | --- | --- | --- | --- |
| `POST` | `/api/auth/register` | 无 | 注册用户并创建个人账本 | `201` |
| `POST` | `/api/auth/login` | 无 | 创建登录会话 | `200` |
| `POST` | `/api/auth/refresh` | 有效刷新 Cookie | 刷新访问会话 | `200` |
| `POST` | `/api/auth/logout` | 有效或可清理的会话 | 清理当前会话 | `200` |
| `GET` | `/api/users/me` | 是 | 获取当前用户资料 | `200` |
| `PATCH` | `/api/users/me` | 是 | 修改允许更新的资料 | `200` |
| `PATCH` | `/api/users/me/password` | 是 | 修改当前用户密码 | `200` |

除特别说明外，接口均使用统一成功响应和错误响应外壳。`data` 中的对象字段使用 camelCase。

## 4. 注册

### 4.1 `POST /api/auth/register`

#### 请求体

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `username` | `string` | 是 | 全局唯一；长度、字符范围由 DTO 固定并在 Swagger 中声明 |
| `password` | `string` | 是 | 满足密码强度要求；不能与用户名完全相同 |
| `nickname` | `string` | 否 | 用户展示名称；不作为登录标识 |
| `email` | `string` | 否 | 合法邮箱格式；统一转小写并去除首尾空格；填写后全局唯一 |

示例：

```json
{
  "username": "xiaobao",
  "password": "example-password",
  "nickname": "小宝",
  "email": "xiaobao@example.com"
}
```

#### 成功响应

注册必须在一个数据库事务中创建 `User`、个人 `Ledger` 和 `OWNER` 级别的 `LedgerMember`。成功后同时建立登录 Cookie。

```json
{
  "success": true,
  "code": 0,
  "message": "注册成功",
  "data": {
    "user": {
      "id": "user-uuid",
      "username": "xiaobao",
      "nickname": "小宝",
      "email": "xiaobao@example.com",
      "avatar": null,
      "isActive": true,
      "createdAt": "2026-10-30T08:00:00.000Z"
    },
    "defaultLedger": {
      "id": "ledger-uuid",
      "name": "我的账本",
      "type": "PERSONAL",
      "defaultCurrency": "CNY",
      "memberRole": "OWNER"
    }
  }
}
```

如果创建账本或成员关系失败，用户创建也必须回滚，不允许留下没有个人账本或没有 Owner 成员的用户。

#### 主要错误

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `40001` | 用户名、密码、邮箱或昵称校验失败 |
| `409` | `40901` | 用户名或邮箱已被占用 |
| `429` | `42901` | 注册请求超过限流阈值 |

## 5. 登录

### 5.1 `POST /api/auth/login`

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | `string` | 是 | 第一期使用用户名登录；是否支持邮箱登录另见未决问题 |
| `password` | `string` | 是 | 明文仅在 HTTPS 请求中传输，服务端只与密码哈希比较 |

#### 成功响应

成功时重新写入访问 Cookie 和刷新 Cookie，响应只返回当前用户的安全资料及其可访问账本摘要。

```json
{
  "success": true,
  "code": 0,
  "message": "登录成功",
  "data": {
    "user": {
      "id": "user-uuid",
      "username": "xiaobao",
      "nickname": "小宝",
      "email": "xiaobao@example.com",
      "avatar": null,
      "isActive": true
    },
    "ledgers": []
  }
}
```

`ledgers` 的摘要结构与[账本与成员接口](./账本与成员接口.md)一致，至少包含 `id`、`name`、`type`、`defaultCurrency`、`memberRole` 和 `isArchived`。

#### 主要错误

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `401` | `40101` | 用户名或密码错误，或账号不可用 |
| `429` | `42901` | 登录失败次数或请求频率超过限制 |

账号不存在、密码错误和账号停用可以在内部日志中区分，但对外默认使用同一类认证失败响应。

## 6. 刷新会话

### 6.1 `POST /api/auth/refresh`

服务端从 HttpOnly `refresh_token` Cookie 读取刷新凭证。请求 Body 为空，客户端不发送 Token 字段。

刷新成功后轮换访问凭证和刷新凭证；旧刷新凭证不能在轮换后继续使用。服务端在 PostgreSQL 中查询对应的刷新会话，校验未过期、未撤销和 Token 哈希匹配后，原会话标记为已替换，并创建新的刷新会话记录。

如果检测到已替换或已撤销的刷新凭证再次使用，服务端应将该刷新会话链全部撤销，并要求用户重新登录。

```json
{
  "success": true,
  "code": 0,
  "message": "会话刷新成功",
  "data": null
}
```

刷新凭证无效、过期、已撤销或对应账号已停用时，清理认证 Cookie 并返回：

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `401` | `40102` | 刷新凭证不存在、无效或已过期 |
| `429` | `42901` | 刷新请求超过限流阈值 |

## 7. 退出登录

### 7.1 `POST /api/auth/logout`

服务端清理访问和刷新 Cookie，并撤销当前设备对应的刷新会话。退出操作应具备幂等性，重复调用不应产生业务错误；其他设备的刷新会话不受影响。

```json
{
  "success": true,
  "code": 0,
  "message": "退出成功",
  "data": null
}
```

## 8. 获取当前用户资料

### 8.1 `GET /api/users/me`

返回当前认证用户的安全资料，不返回密码哈希、刷新会话、登录失败计数等内部字段。

```json
{
  "success": true,
  "code": 0,
  "message": "获取成功",
  "data": {
    "id": "user-uuid",
    "username": "xiaobao",
    "nickname": "小宝",
    "email": "xiaobao@example.com",
    "avatar": null,
    "isActive": true,
    "createdAt": "2026-10-30T08:00:00.000Z",
    "updatedAt": "2026-10-30T08:00:00.000Z"
  }
}
```

未登录、会话过期或账号停用时返回 `40101`，不返回用户详情。

## 9. 修改当前用户资料

### 9.1 `PATCH /api/users/me`

#### 允许字段

| 字段 | 类型 | 可修改 | 约束 |
| --- | --- | --- | --- |
| `nickname` | `string \| null` | 是 | 空值表示清空昵称 |
| `email` | `string \| null` | 是 | 空值表示清空邮箱；非空时必须全局唯一 |
| `avatar` | `string \| null` | 是 | 第一期先按 URL 字符串处理；上传方式另行设计 |
| `username` | `string` | 否 | 登录标识第一期不允许修改 |
| `isActive` | `boolean` | 否 | 不能由用户资料接口修改 |

服务端必须过滤未知字段，并以认证上下文中的用户 ID 作为更新目标。修改资料不影响用户的任何账本成员角色。

#### 主要错误

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `40001` | 字段格式、长度或 URL 校验失败 |
| `401` | `40101` | 当前会话无效 |
| `409` | `40901` | 邮箱已被其他用户占用 |

## 10. 修改密码

### 10.1 `PATCH /api/users/me/password`

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `currentPassword` | `string` | 是 | 当前密码 |
| `newPassword` | `string` | 是 | 新密码，必须满足密码强度要求，不能与当前密码相同 |

密码修改成功后必须撤销当前用户的全部刷新会话并清理当前认证 Cookie，用户需要重新登录。这样可以降低密码泄露后旧设备继续保持登录状态的风险。

```json
{
  "success": true,
  "code": 0,
  "message": "密码修改成功",
  "data": null
}
```

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `40001` | 新密码不符合校验要求 |
| `401` | `40101` | 当前会话无效或当前密码错误 |
| `429` | `42901` | 密码修改请求超过限制 |

## 11. 刷新会话数据约定

刷新会话由 PostgreSQL 持久化，建议字段如下：

| 字段 | 说明 |
| --- | --- |
| `id` | 会话 ID |
| `userId` | 所属用户 |
| `tokenHash` | 刷新 Token 的 SHA-256 哈希，不保存原始 Token |
| `deviceName` | 设备展示名称，可选 |
| `userAgent` | 创建时的客户端标识，可选 |
| `lastUsedAt` | 最近一次成功刷新时间 |
| `expiresAt` | 会话过期时间 |
| `revokedAt` | 撤销时间，未撤销时为空 |
| `replacedBySessionId` | Token 轮换后指向新会话，可选 |
| `createdAt` | 创建时间 |

刷新会话必须支持按用户全部撤销、按当前会话撤销和按会话链撤销。具体 Prisma 模型和 Migration 在认证模块实施计划中完成。

## 12. 领域测试要求

- 注册 Service：覆盖成功事务、用户名重复、邮箱重复、账本创建失败时整体回滚。
- 登录 Service：覆盖正确凭证、错误凭证、账号停用、限流和 Cookie 写入；错误响应不能泄露账号存在性。
- 刷新与退出：覆盖刷新凭证失效、刷新凭证轮换、重复退出和 Cookie 清理。
- 刷新会话：覆盖旧 Token 重放检测、会话链撤销、单设备退出、改密后全部设备退出和并发刷新。
- 用户资料：覆盖敏感字段过滤、未知字段过滤、邮箱冲突和角色关系不变。
- Controller 契约：覆盖 DTO 到 Service 的参数传递、认证上下文和主要异常映射。

## 13. 未决问题

1. 第一期是否允许使用邮箱登录；当前接口只定义用户名登录。
2. 头像是否接入对象存储上传；当前接口只保留可替换的 URL 字段，不承诺上传接口。
