# 小宝记账 App 需求基础文档

> 文档版本：v0.2
> 创建日期：2026-10-30
> 需求阶段：基础需求与 MVP 范围

## 1. 产品定位

小宝记账是一款支持个人账本和多人共享账本的轻量记账 PWA，核心目标是让用户快速记录收入、支出和账户变动，并通过清晰的统计帮助个人或共享账本成员了解共同的财务情况。

第一阶段优先保证：

- 记一笔足够快
- 数据准确可靠
- 手机端使用方便
- 能查看月度收支
- 网络不稳定时仍然可以暂存账单并在恢复后同步
- 多个用户可以在同一个账本中协作记账

## 2. 用户范围

### 2.1 第一阶段用户

第一阶段即支持多个用户。每个用户注册后自动拥有一个个人账本，也可以创建共享账本或加入其他用户邀请的共享账本。

### 2.2 账本类型

- 个人账本：默认创建，通常只有一个成员
- 共享账本：允许多个成员共同查看和记账

所有账单、账户、分类、预算和统计都属于某个账本，不直接归属于用户。用户通过账本成员关系访问这些数据。

### 2.3 共享账本成员角色

- `OWNER`：管理账本、成员、邀请和全部数据
- `EDITOR`：查看、新增和编辑账单
- `VIEWER`：只能查看账单和统计

第一版不设计复杂的自定义权限矩阵，先使用固定角色。

### 2.4 平台管理端身份

平台管理端服务于系统运营、安全审计和资源治理，不属于普通用户的账本成员权限。平台管理员使用独立的 `AdminUser` 账号、管理员 Cookie、Token audience、刷新会话和权限体系；普通 `User` 不增加简单的 `isAdmin` 字段。

平台管理员初始角色包括 `SUPER_ADMIN`、`OPERATOR` 和 `AUDITOR`，通过 `AdminRole`、`AdminPermission` 及关联关系表达权限。管理员默认只能按权限查询用户、账本、系统配置和审计信息；查看敏感账单、修改账单、修改配置和管理管理员账号需要独立权限，并记录审计。

第一期普通记账功能可以先不交付管理端前端和管理接口，但后端认证、数据库和 API 设计必须保留 `/api/admin/**` 的独立边界。完整规则见《平台管理端需求》和《平台管理端技术设计》。

## 3. 核心概念

### 3.1 账户

账户表示资金存放的位置，例如现金、微信、支付宝、银行卡或信用卡。

### 3.2 分类

分类表示资金变动的业务类型，例如餐饮、交通、工资和购物。

### 3.3 账单

账单表示一次收入、支出或转账记录，是系统的核心业务数据。

### 3.4 标签

标签用于跨分类描述场景，例如出差、旅行、报销和聚餐。

### 3.5 预算

预算表示某个时间周期或某个分类允许使用的金额上限。

### 3.6 账本

账本是账单数据的归属空间，可以是个人账本，也可以是多人共享账本。

### 3.7 账本成员

账本成员表示用户和账本的关系，并保存角色、加入时间和成员状态。用户是否可以访问某条数据，必须通过账本成员关系判断。

## 4. MVP 功能范围

### 4.1 登录与个人资料

#### 功能目标

让用户安全进入自己的记账空间，并保证不同用户之间的数据隔离。

#### 功能清单

- 登录
- 退出登录
- Access Token 自动续期
- 修改密码
- 修改昵称
- 查看当前用户信息
- 登录失效后跳转登录页

注册功能可以根据实际使用方式决定。若第一阶段只给自己使用，可以先通过初始化脚本创建账号。

#### 验收标准

- 未登录用户不能访问账单和统计页面
- 刷新页面后登录状态仍然有效
- Token 过期时能够自动刷新或引导重新登录
- 用户无法读取不属于自己所在账本的数据

### 4.2 账本管理

#### 功能目标

让用户管理个人账本和共享账本，并在多个账本之间切换。

#### 功能清单

- 注册或初始化用户后自动创建个人账本
- 创建共享账本
- 编辑账本名称、图标和颜色
- 查看自己加入的账本列表
- 切换当前账本
- 退出共享账本
- Owner 删除或归档账本

#### 业务规则

- 用户必须至少保留一个可访问账本
- 个人账本默认只有创建者一个 Owner
- 共享账本至少需要一个 Owner
- 删除账本属于高风险操作，必须二次确认
- 切换账本后，首页、账单、账户、分类和统计全部切换到当前账本

#### 验收标准

- 新用户可以直接进入自动创建的个人账本
- 用户可以创建共享账本并邀请其他成员
- 切换账本后不会混入其他账本的数据
- 无权限访问的账本 ID 不能通过接口读取数据

### 4.3 成员与邀请管理

#### 功能目标

让账本 Owner 安全地邀请和管理共享账本成员。

#### 功能清单

- 生成邀请码或邀请链接
- 设置邀请有效期
- 接受邀请
- 拒绝或撤销邀请
- 查看成员列表
- 修改成员角色
- 移除成员
- 成员主动退出账本
- 转移 Owner 身份

#### 邀请状态

```text
PENDING
ACCEPTED
EXPIRED
REVOKED
DECLINED
```

#### 业务规则

- 只有 Owner 可以邀请成员和修改角色
- Viewer 不能新增、编辑或删除账单
- Editor 不能管理成员
- 账本至少保留一个 Owner
- 邀请链接不能无限期有效
- 被移除的成员不能继续读取该账本数据

#### 验收标准

- 未登录用户接受邀请时需要先登录或注册
- 邀请只能被目标用户接受，或使用明确的通用邀请码策略
- 邀请过期、撤销后不能加入账本
- 权限变更后后端接口立即生效

### 4.4 首页仪表盘

#### 功能目标

让用户打开应用后快速了解当前月份的财务概况，并可以立即记账。

#### 页面内容

- 本月收入
- 本月支出
- 本月结余
- 当前账户余额总览
- 最近账单
- 支出分类排行
- 收支趋势
- 快速记账入口

#### 验收标准

- 默认展示当前月份
- 可以切换上月、下月或指定月份
- 统计口径与账单列表一致
- 转账不能被计入收入或支出
- 无数据时展示清晰的空状态

### 4.5 快速新增账单

#### 功能目标

让用户可以在移动端快速完成一次记账。

#### 支持类型

- 支出
- 收入
- 转账

#### 支出和收入字段

- 金额，必填
- 分类，必填
- 账户，必填
- 发生时间，默认当前时间
- 标题或商家，可选
- 备注，可选
- 标签，可选，MVP 后半段加入
- 实际付款人，共享账本中可选

#### 转账字段

- 转出账户，必填
- 转入账户，必填
- 金额，必填
- 发生时间，默认当前时间
- 备注，可选

#### 交互要求

- 支出、收入、转账使用清晰的类型切换
- 金额输入优先适配手机数字键盘
- 默认选中最近使用的账户和分类
- 保存成功后回到当前账单列表或首页
- 支持保存后继续记下一笔
- 金额必须大于 0
- 转出账户和转入账户不能相同
- 共享账本中可以记录实际付款人

#### 验收标准

- 正常网络下保存成功后服务端有完整记录
- 保存失败时用户能看到明确错误，不丢失已填写内容
- 重复点击保存不能产生重复账单
- 离线时可以暂存到账单同步队列
- 保存接口使用客户端幂等 ID，避免多人或离线重试造成重复账单

### 4.6 共享账单协作

#### 功能清单

- 查看当前账本全部账单
- 按创建人筛选
- 按实际付款人筛选
- 查看账单创建人和最后修改人
- 按角色限制新增、编辑和删除
- 记录账单的基础变更信息

#### 业务规则

- 账单必须属于当前账本
- 创建人和实际付款人可以是不同成员
- Editor 可以新增和编辑账单，但不能管理成员
- Viewer 只能查看账单和统计
- 删除账单使用软删除
- 同一账单并发修改时，服务端使用版本号或 `updatedAt` 检测冲突

#### 验收标准

- 成员只能看见自己加入的账本数据
- 切换账本后账单列表完全隔离
- 账单详情可以显示创建人、修改人和付款人
- 无权限操作会返回明确的权限错误

### 4.7 账单列表

#### 功能目标

让用户快速查看、搜索和修改历史账单。

#### 功能清单

- 按日期分组展示
- 按月查看
- 支出/收入/转账筛选
- 分类筛选
- 账户筛选
- 关键词搜索
- 时间范围筛选
- 编辑账单
- 删除账单
- 查看账单详情

#### 列表展示

- 日期
- 类型
- 分类图标
- 标题
- 账户
- 金额
- 同日收入和支出汇总
- 创建人或付款人，共享账本可显示

#### 删除规则

账单删除优先采用软删除。删除后不参与统计，但后续可以在回收站恢复或永久清理。

#### 验收标准

- 列表金额和首页统计一致
- 筛选条件可以组合使用
- 编辑后列表、账户余额和统计同步更新
- 删除后账单不再出现在正常列表和统计中
- 分页或加载更多不会重复显示账单

### 4.8 分类管理

#### 默认分类

支出分类：

- 餐饮
- 交通
- 购物
- 居住
- 通讯
- 娱乐
- 医疗
- 教育
- 人情
- 旅行
- 其他

收入分类：

- 工资
- 奖金
- 副业
- 投资
- 退款
- 红包
- 其他

#### 功能清单

- 查看分类
- 新增分类
- 编辑分类
- 设置图标
- 设置颜色
- 调整排序
- 停用分类
- 设置常用分类

#### 业务规则

- 收入分类和支出分类分开
- 已被账单使用的分类不能直接破坏历史关联
- 停用分类后不能用于新增账单，但历史账单继续保留
- 分类排序影响快速记账页面展示顺序

### 4.9 账户管理

#### 默认账户

- 现金
- 微信
- 支付宝
- 银行卡
- 信用卡
- 其他

#### 功能清单

- 新增账户
- 编辑账户
- 设置初始余额
- 查看当前余额
- 设置账户颜色和图标
- 设置是否计入总资产
- 停用账户
- 查看账户账单
- 设置账户为共享账户或私人账户

#### 业务规则

- 支出会减少账户余额
- 收入会增加账户余额
- 转账会同时减少转出账户余额并增加转入账户余额
- 账户余额变化必须由后端事务保证一致性
- 有历史账单的账户不直接物理删除
- 共享账户对账本成员可见
- 私人账户默认只有账户所有者可见
- 使用私人账户记账时，其他成员只能按权限看到允许展示的信息
- 信用卡可以在后续版本增加账单日和还款日

### 4.10 转账

转账只表示资金位置变化，不属于收入或支出。

示例：

```text
银行卡 → 微信：100 元
```

转账保存后：

- 银行卡余额减少 100 元
- 微信余额增加 100 元
- 本月收入不增加
- 本月支出不增加
- 两条资金变动记录需要使用同一个转账关联 ID

### 4.11 统计分析

MVP 建议实现：

- 月度收入和支出趋势
- 支出分类排行
- 支出分类占比
- 每日支出汇总
- 收入、支出和结余对比
- 最大单笔支出
- 当前月与上月对比
- 按成员统计支出
- 按实际付款人统计支出

统计筛选条件：

- 月份
- 自定义时间范围
- 收入或支出类型
- 分类
- 账户

统计必须以服务端聚合结果为准，前端只负责展示，避免不同页面各自计算导致口径不一致。

### 4.12 预算

建议作为 MVP 后半段功能。

功能清单：

- 设置月度总预算
- 设置分类预算
- 查看已使用金额
- 查看剩余预算
- 查看预算使用比例
- 接近预算时提醒
- 超出预算时提醒

业务规则：

- 预算只统计支出
- 转账不消耗预算
- 删除账单后预算使用额同步减少
- 修改账单分类后预算归属同步变化

### 4.13 数据导入导出

建议提供：

- CSV 导出
- Excel 导出
- JSON 数据备份
- CSV 导入
- JSON 数据恢复

导入前需要：

- 预览数据
- 显示格式错误
- 显示重复数据风险
- 用户确认后再正式导入

## 5. PWA 与离线需求

### 5.1 第一阶段离线能力

- 应用可以安装到手机主屏幕
- 应用图标和启动页完整
- 页面静态资源可缓存
- 最近账单可以离线查看
- 离线可以新增收入、支出和转账
- 网络恢复后自动同步
- 显示当前在线/离线状态
- 显示待同步数量
- 同步失败可以重试

### 5.2 离线账单状态

建议使用以下状态：

```text
PENDING_SYNC   待同步
SYNCING        同步中
SYNCED         已同步
SYNC_FAILED    同步失败
CONFLICT       存在冲突
```

离线生成的账单需要拥有客户端生成的唯一 ID，网络恢复后使用幂等接口提交，避免重复同步。共享账本中的离线新增一般可以自动合并；同一账单被多人同时编辑时，应标记冲突并以服务端数据为最终权威。

### 5.3 暂不纳入第一版

- 多设备复杂冲突自动合并
- 离线编辑大量历史数据
- 图片附件离线上传
- 后台定时同步
- 多人同时编辑同一账单的实时协同

## 7. 主要用户流程

### 7.1 首次使用

```text
打开应用
  ↓
登录
  ↓
自动创建个人账本
  ↓
初始化默认分类和账户
  ↓
进入首页
  ↓
快速记第一笔账
```

### 7.2 创建共享账本

```text
进入账本管理
  ↓
创建共享账本
  ↓
生成邀请链接或邀请码
  ↓
其他用户登录并接受邀请
  ↓
成员加入账本
  ↓
根据角色查看或共同记账
```

### 7.3 日常记账

```text
打开首页
  ↓
点击“记一笔”
  ↓
选择支出/收入/转账
  ↓
填写金额、分类和账户
  ↓
保存
  ↓
首页统计和账户余额更新
```

### 7.4 离线记账

```text
网络断开
  ↓
用户新增账单
  ↓
保存到 IndexedDB
  ↓
显示“待同步”
  ↓
网络恢复
  ↓
提交服务端
  ↓
服务端幂等校验
  ↓
更新为“已同步”
```

## 8. 非功能需求

### 8.1 性能

- 首页首屏在常规网络下快速可用
- 账单列表采用分页或加载更多
- 统计接口由后端聚合
- 大量历史数据不能全部一次性返回
- 快速记账操作反馈应及时

### 8.2 可靠性

- 保存账单必须具备幂等能力
- 账户余额变化使用数据库事务
- 生产数据库定期备份
- 导入前需要预览和校验
- 服务端异常不能导致账单重复写入

### 8.3 安全性

- 用户只能访问自己所属账本中的账单、账户、分类和预算
- 所有接口必须校验账本成员身份和角色
- 密码使用安全哈希保存
- Refresh Token 不通过普通前端状态长期暴露
- 导出和恢复接口必须登录
- 导入接口限制文件大小和格式
- 生产环境启用 HTTPS

### 8.4 可维护性

- 前后端均使用严格 TypeScript
- API 请求和响应定义明确类型
- 模块按领域拆分
- 核心业务规则编写测试
- 数据库变化使用 Prisma Migration
- 重要业务接口补充 Swagger 文档

## 9. MVP 明确不做的功能

以下功能暂不进入第一版：

- 多币种换算
- OCR 小票识别
- 自动读取银行卡或支付平台账单
- 自动扣款
- 投资收益分析
- 负债和贷款完整管理
- 复杂信用卡账单周期
- AI 自动分类

这些功能可以在基础记账流程稳定后再评估。

## 11. 当前待确认事项

以下事项不影响基础工程启动，但在进入对应功能开发前需要确定：

1. 是否开放邮箱、手机号或用户名注册。
2. 邀请优先使用邀请链接、邀请码，还是邮箱邀请。
3. 共享账本中的私人账户是否允许只隐藏余额但显示账户名称。
4. 第一版是否必须支持离线新增，还是先实现 PWA 安装和离线查看。
5. 是否需要信用卡账单日、还款日和负债统计。
6. 是否需要账单图片和小票附件。
7. 默认货币是否固定为人民币。
