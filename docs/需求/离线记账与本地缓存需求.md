# 小宝记账离线记账与本地缓存需求

## 1. 文档目的

本文定义普通用户在网络不可用或网络不稳定时的记账体验，以及账单、常用业务数据和账单图片在设备本地的缓存规则。

本文是离线专项需求草案。产品规则确认后，作为前端离线同步、本地缓存和 PWA 实现的业务依据。具体 IndexedDB 表结构、React Query 配置和 Service Worker 实现由配套技术文档定义。

## 2. 背景与问题

- 用户在地铁、电梯、地下停车场或网络不稳定环境中仍然需要快速记录收入和支出。
- 当前断网时记账按钮不可提交，用户只能保留当前页面表单，无法可靠保存已经填写的账单。
- PWA 页面壳可以离线打开，但服务端账单数据目前主要保存在内存查询缓存中，刷新或重新打开应用后无法保证可用。
- 账单图片使用短期签名地址。每次打开详情都重新申请地址，会增加等待时间；签名地址过期后也不能直接作为长期缓存。
- 共享账本中的权限、成员和并发版本会变化，离线编辑和删除容易产生不可解释的覆盖或越权结果。

## 3. 产品目标

1. 用户可以在离线状态下保存收入或支出草稿，并明确看到其“待同步”状态。
2. 网络恢复后，系统自动或手动将本地账单提交到服务端，保证重复提交不会产生重复账单。
3. 用户可以在离线状态下查看最近一次已缓存的账本、常用分类、账户、成员和近期账单。
4. 已查看过的账单图片可以在有效的本地缓存期内直接展示，减少重复申请签名地址和重复下载。
5. 本地数据按用户和账本隔离，退出登录、切换账号或失去账本权限后不继续展示旧数据。
6. 在线数据仍以服务端为最终事实来源，本地缓存必须明确标识可能过期的状态。
7. 用户可以在普通用户的「我的」页面查看本地占用并主动清理可清理的缓存。

## 4. 非目标

第一阶段不包含以下能力：

- 离线编辑已有账单；
- 离线删除账单；
- 离线修改成员、角色、邀请、账户、分类和账本设置；
- 离线统计与服务端统计自动合并；
- 管理端数据持久化缓存；
- Service Worker 无条件缓存账单 API、管理员 API 或签名图片地址；
- 保证 iOS PWA 在应用完全关闭后执行后台同步或后台上传；
- 对 IndexedDB 中的财务数据和图片提供应用层端到端加密。

## 5. 用户和权限

### 5.1 普通用户

只有已经登录且曾经成功读取过目标账本的普通用户，才能创建离线账单。离线保存时使用最近一次成功读取的账本、分类、账户和成员快照进行表单展示与本地校验。

本地保存不代表服务端已经接受账单。服务端同步时仍需重新校验当前用户会话、账本成员状态、成员角色、分类、账户和付款人。

### 5.2 账本角色

| 角色 | 离线新增 | 本地查看缓存 | 联网同步结果 |
| --- | --- | --- | --- |
| `OWNER` | 允许 | 允许 | 按服务端权限执行 |
| `EDITOR` | 允许 | 允许 | 按服务端权限执行 |
| `VIEWER` | 禁止 | 允许 | 不创建本地待同步账单 |

用户进入离线状态后，如果本地保存的角色是 `OWNER` 或 `EDITOR`，可以先保存待同步账单；服务端同步时角色已经变化，则标记失败或权限冲突，不伪造成功状态。

## 6. 功能范围

### 6.1 离线创建账单

离线创建沿用在线记账字段和规则：

- 类型为 `EXPENSE` 或 `INCOME`；
- 金额为大于 `0` 的整数分；
- 发生时间为带时区的 ISO 8601 时间；
- 分类必须来自本地最近一次成功读取的同一账本和同一收支类型；
- 账户、实际付款人、标题和备注沿用在线字段约束；
- 每笔账单生成唯一的 `clientRequestId`，重试时必须复用；
- 离线账单可以附带本地图片，图片随账单进入待上传队列；
- 保存后显示“已保存到本机，等待同步”，不得显示“已记账”或“云端已保存”。

离线账单默认只在当前用户设备和当前账本中可见。同步成功前，其他共享成员不能看到这笔账单。

### 6.2 本地账单查看

用户可以打开最近成功缓存的账本页面和近期账单列表。页面必须显示缓存时间或“可能不是最新数据”的提示。

本地待同步账单可以出现在当前用户的默认账单列表中，并显示本地状态标识。待同步账单不计入服务端统计结果；页面需要单独展示待同步数量或金额，避免用户误解云端统计已包含本地数据。

### 6.3 常用数据缓存

以下数据可以按用户和账本持久化：

- 当前账本基本信息；
- 启用分类；
- 可用账户摘要；
- 活跃成员摘要；
- 最近访问账单列表；
- 用户实际打开过的账单详情；
- 用户实际查看过的已完成账单图片。

账单列表快照按“每个用户、每个账本最近 500 条账单”保留。筛选和分页结果优先从这份最近账单快照派生，不能因为新增筛选条件而无限制增加快照数量。账单详情只持久化用户实际打开过的详情，不设置固定条数，按容量和最近访问时间清理。

以下数据不进入持久化缓存：

- 管理员用户、管理员权限和审计日志；
- 登录、刷新和退出接口响应中的会话信息；
- 永久保存的图片签名 URL；
- 与当前用户或当前账本无关的数据。

### 6.4 图片本地缓存

账单图片完成上传并成功读取后，前端可以将图片二进制 Blob 缓存到 IndexedDB。缓存键使用当前用户、账本和附件 ID 组成，不保存短期签名 URL 作为长期访问凭证。

图片缓存规则：

- 只缓存用户实际查看过或刚刚上传成功的图片；
- 当前用户本地图片 Blob 缓存默认上限为 `100MB`。行业没有统一的浏览器缓存容量标准，采用该值作为移动端 PWA 的保守默认值，避免图片缓存挤占离线账单空间；
- 图片被删除、账单失去访问权限或用户退出登录后清理；
- 超过本地容量上限时按最近访问时间清理；
- 本地缓存命中时可以离线展示；
- 本地缓存未命中且网络不可用时显示可恢复的图片加载失败状态；
- 未上传完成的图片进入本地待上传队列，不显示为已完成附件。

### 6.5 附件摘要与删除重传

附件摘要和图片 Blob 分开管理。附件摘要至少保留 `attachmentId`、`transactionId`、`status`、`mimeType`、`sizeBytes`、`originalName`、`createdAt`，并在本地补充 `cachedAt`、`lastAccessedAt` 和本地缓存状态。短期签名 URL 只用于本次读取，不写入持久化缓存。

删除附件成功后，立即删除对应的本地 Blob 和附件摘要；如果服务端已经返回附件不存在或已删除，也执行同样的本地清理。重新上传视为新附件，使用新的 `attachmentId` 和新的本地缓存键，不复用旧附件的 Blob、摘要或签名 URL。当前不要求服务端为“同一附件替换内容”提供版本字段，因为删除后重新上传已经形成新的资源身份。

离线第一阶段只支持新增账单及其附件，不支持离线删除附件。这样可以避免删除请求尚未到达服务端时，其他共享成员仍能看到旧附件而本地却提前清除的状态冲突。

### 6.6 个人页面缓存管理

普通用户在 `/user/profile` 的“本地缓存与离线数据”入口管理当前账号的本地数据。页面至少显示图片缓存占用、账单快照数量、待同步账单数量和最近同步时间，并提供以下操作：

| 操作 | 清理范围 | 待同步账单是否保留 |
| --- | --- | --- |
| 清理图片缓存 | 已缓存的图片 Blob 和对应缓存元数据 | 保留 |
| 清理已同步账单快照 | 已同步账单列表、详情和查询快照 | 保留 |
| 清理全部本地数据 | 当前账号的快照、图片、已同步记录和待同步记录 | 不保留 |

“清理全部本地数据”必须二次确认，并明确提示未同步账单会被删除；“清理图片缓存”和“清理已同步账单快照”不能删除待同步账单或待上传图片。清理后页面重新读取本地占用和待同步数量，不能只清除界面状态。

## 7. 同步规则

### 7.1 同步时机

系统在以下时机尝试同步：

1. 应用启动并完成普通用户会话初始化后；
2. 浏览器从 `offline` 恢复为 `online` 后；
3. PWA 回到前台或页面重新可见后；
4. 用户点击“立即同步”或“重试”后；
5. 离线账单写入本地队列后，如果网络已经恢复，立即尝试提交。

系统不承诺 iOS PWA 在应用完全关闭后执行后台同步。应用重新打开或回到前台时必须继续处理未完成队列。

### 7.2 同步状态

| 状态 | 含义 | 用户操作 |
| --- | --- | --- |
| `PENDING` | 已保存到本地，尚未提交 | 等待自动同步或手动同步 |
| `SYNCING` | 正在提交账单或附件 | 等待完成，不允许重复提交 |
| `SYNCED` | 账单和需要上传的附件已完成 | 可以查看服务端详情 |
| `FAILED` | 需要用户处理的失败 | 查看原因并重试或删除本地记录 |
| `CONFLICT` | 服务端状态不允许继续同步 | 查看原因并决定保留或丢弃本地记录 |

### 7.3 服务端结果处理

| 结果 | 本地处理 |
| --- | --- |
| 创建成功 | 保存服务端 `transactionId`，更新为 `SYNCED` |
| 网络错误、超时或 5xx | 保留 `PENDING` 或回退为待重试状态 |
| 401 | 暂停同步，触发普通用户登录态处理；本地数据保留 |
| 403 或 404 | 标记 `FAILED`，提示账本或成员权限已经变化 |
| 409 | 标记 `CONFLICT`，保留本地账单和错误信息 |
| 附件上传失败 | 账单保持已同步，单独标记图片待重试 |

创建请求必须复用本地 `clientRequestId`。服务端已有账本级幂等能力，重试不能重复创建账单或重复影响账户余额。

## 8. 异常和用户提示

- 本地存储空间不足时，禁止伪造保存成功，提示用户清理本地缓存或恢复网络后重试。
- 本地账单写入成功但页面刷新后无法读取时，显示本地数据恢复失败，并保留同步错误摘要；不能将其显示为云端账单。
- 同步期间用户退出登录时，当前同步请求停止或等待结束；未同步数据按原用户隔离保留，不转移给下一个用户。
- 用户登录另一个账号时，不得展示上一个账号的账单、图片、分类或待同步记录。
- 用户被移出账本后，服务端拒绝未同步账单；页面明确提示账本权限已经变化，并允许用户导出或删除本地草稿。
- 账单已同步但附件上传失败时，账单继续可用，图片显示“待上传”并提供单张重试。
- 浏览器清理站点数据、卸载 PWA 或更换设备可能导致本地未同步内容丢失；页面应在离线状态和设置页说明这一限制。
- 用户主动清理全部本地数据会删除未同步账单和待上传附件，二次确认文案必须明确这一后果。

## 9. 验收标准

- 给定用户已登录且曾访问目标账本，当设备断网并提交有效支出，则账单保存到本地 Outbox，显示待同步状态，页面不提示云端已保存。
- 给定离线账单拥有 `clientRequestId`，当网络恢复并触发两次同步，则服务端最多创建一笔账单，账户余额最多变更一次。
- 给定用户处于 `VIEWER` 角色，当用户离线打开记账抽屉，则不能创建待同步账单。
- 给定离线账单同步时用户已被移出账本，当服务端返回权限错误，则本地记录标记失败，不伪造同步成功。
- 给定离线账单包含图片，当账单同步成功且图片上传失败，则账单显示为已同步，图片单独显示失败并可重试。
- 给定用户重新打开已访问过的账本，当网络不可用，则页面显示最近一次缓存内容，并标识缓存可能过期。
- 给定账单详情图片已经被当前用户查看过，当用户再次打开详情且网络不可用，则直接使用本地 Blob 展示图片。
- 给定签名 URL 已经过期但本地 Blob 仍存在，当用户打开附件，则不请求旧签名 URL，直接展示本地图片。
- 给定附件 Blob 和摘要已经被本地缓存，当用户删除附件并重新上传图片，则旧 `attachmentId` 的 Blob 和摘要被删除，新附件使用新的 `attachmentId` 缓存，详情中不显示旧附件。
- 给定用户在 `/user/profile` 清理已同步账单快照，当操作完成后，则待同步账单、待上传附件和对应本地状态仍然存在。
- 给定用户在 `/user/profile` 清理全部本地数据，当二次确认完成后，则当前账号的待同步账单和待上传附件也被删除，并显示清理后的空状态。
- 给定用户退出登录后登录另一个账号，当新账号打开账本页，则不能读取上一个账号的账单、图片和待同步记录。
- 给定本地存储空间不足，当用户保存离线账单或图片，则操作显示可恢复错误，不产生无法追踪的半成功状态。

## 10. 数据、API、UI 和测试影响

### 10.1 数据影响

前端增加按用户和账本隔离的 IndexedDB 数据，包括账单 Outbox、附件待上传队列、查询快照和图片 Blob。服务端不新增离线专用账单表，继续使用现有账单创建接口和 `clientRequestId` 幂等约束。

### 10.2 API 影响

第一阶段复用现有账单创建、附件上传和附件完成确认接口。接口需要保持以下契约：

- 创建账单支持重复 `clientRequestId` 幂等重试；
- 创建账单成功返回服务端 `transactionId`；
- 附件上传会话和完成确认可以独立重试；
- 权限、账本归属、分类、账户和付款人仍由服务端最终校验。

### 10.3 UI 影响

需要增加离线提示、待同步数量、本地保存状态、同步失败原因、冲突状态、图片待上传状态和缓存时间提示；普通用户 `/user/profile` 需要增加本地缓存管理入口。在线成功、离线本地保存和服务端同步成功必须使用不同文案和状态样式。

### 10.4 测试要求

至少覆盖：Outbox 状态转换、幂等重试、网络恢复同步、401 暂停、权限失败、附件依赖、用户与账本隔离、IndexedDB 读写失败、本地 Blob 命中和缓存清理。跨路由的登录恢复与 PWA 行为再使用 Playwright 或真机验收补充。

## 11. 未决问题

1. 待同步账单是否允许用户在本地列表中直接删除，还是必须进入待同步管理入口处理。
2. 同步失败超过多少次后从自动重试改为仅手动重试。
3. 是否需要为离线账单提供本地导出，防止浏览器清理数据造成不可恢复损失。
4. 是否在后续版本增加离线编辑；如果增加，需要先确定基于 `version` 的冲突展示和合并规则。
