# 三期记账体验与共享协作需求

## 1. 文档目的

本文定义第三期的四项需求：共享账本邀请体验修复、历史备注快捷选择、移动端原生键盘布局适配、日期时间选择体验优化；账单图片附件与对象存储不在本期范围，仅保留后续专项设计。本文只定义用户可见行为、业务规则、边界和验收口径，不规定代码模块、数据库表结构或接口路径；相关技术方案在评审通过后分别进入技术/API/UI 文档。

一期账单能力、二期账本管理与统计能力继续保留。三期不重定义角色、金额单位、账单幂等与并发规则。

## 2. 背景

以下现状基于仓库当前实现（提交 `9ee2ebd` 基线）核对，是本期需求要解决的问题依据。

| 主题 | 当前实现 | 由此产生的问题 |
| --- | --- | --- |
| 邀请入口 | 邀请链接为 `/user/invitations?token=...`；接受/拒绝接口只接受一次性 `token` | 链接是唯一可响应的入口 |
| 我的邀请 | `GET /invitations` 返回可处理邀请，但不返回 `token`；列表条目只读 | 用户在“我的邀请”里看得到邀请却无法接受或拒绝 |
| 登录回跳 | 未登录访问受保护页时跳转 `/user/login?redirect=<pathname>`，只带路径不带查询串 | 打开邀请链接 → 登录 → 回到 `/user/invitations`（无 token），邀请无法响应，用户以为要重新登录 |
| 邮箱前提 | 接受/拒绝要求当前账号已填写并匹配邀请目标邮箱 | 未填邮箱的账号被拦下且无就地补全路径 |
| 图片 | 记账快捷条中“图片”为禁用占位；后端无附件模型 | 本期不实施，保留为后续专项能力 |
| 备注 | `Transaction.note` 已入库，单条上限 200 字，抽屉内单行 ⇄ 两行输入 | 无法复用历史备注，重复记账要重复输入 |
| 键盘 | 记账面板依赖 `100dvh`；文本输入框字号为 12px；未处理 `visualViewport` | iOS 聚焦输入框自动放大页面；键盘弹出挤压布局 |
| 时间 | 原生 `datetime-local` + `showPicker()`，无第三方日期组件 | 系统选择器表现不一致，容易被键盘或面板遮挡 |

## 3. 目标与非目标

### 3.1 三期目标

- 邀请从“打开链接 → 登录 → 响应 → 加入账本”全程不丢上下文，且能在“我的邀请”内直接响应。
- 用户能一键复用最近使用过的备注，点选后仍可编辑。
- 原生键盘弹出时页面不自动放大、不整体挤压，备注快捷项稳定出现在输入区附近。
- 用户能可靠修改账单发生日期和时间，选择器不被裁剪或遮挡。

### 3.2 三期非目标

- 不做 OCR、小票识别、自动分类、报销工作流。
- 本期不做账单图片附件与对象存储；不做通用文件网盘，不接受任意文件类型。图片附件保留为后续专项设计，单独立项后再评审。
- 不做邀请邮件/短信/推送外发，不做独立站内消息中心。
- 不做实时协同编辑、账本内聊天。
- 不改造角色模型、账单权限矩阵、金额与统计口径。

## 4. 需求一：共享账本邀请流程修复

### 4.1 结论

“我的邀请”已经存在，问题不在是否实现，而在三处断点：登录回跳丢失邀请参数、邀请列表无法就地响应、缺少邮箱前提的就地补全。本期修复这三处，保留现有“邮箱目标 + 一次性 Token + 72 小时有效期”的安全模型，不改为通用邀请码或开放链接。

### 4.2 流程要求

1. **发起**：`OWNER` 在成员页输入对方邮箱、选择 `EDITOR` 或 `VIEWER` 发起邀请；创建成功后可复制邀请链接，成员页待处理列表可看到目标邮箱、角色与到期时间。沿用现有规则：角色不能授予 `OWNER`，个人账本不能邀请。
2. **打开**：受邀者打开链接，未登录时看到邀请说明（账本名称、邀请人、授予角色、有效期）与登录入口，不暴露账单等账本内容。
3. **登录回跳**：登录或注册成功后回到原邀请页并保留 `token` 与 `action` 参数，直接呈现接受/拒绝操作；已登录用户打开链接不重复要求登录。
4. **就地响应**：“我的邀请”列表中的每条待处理邀请都可以接受或拒绝，不再要求用户必须持有链接。
5. **邮箱前提**：账号未填写邮箱或邮箱与邀请目标不一致时，页面给出明确说明，并提供“补全/更换邮箱”入口；在补全成功后可继续响应，邀请不被消费。
6. **终态**：邀请过期、被撤销、已接受、已拒绝时显示终态与原因，不给可继续加入的假操作；重复点击或刷新不重复消费。
7. **结果**：接受成功加入账本并可直接进入该账本；拒绝成功后该项从待处理列表移除。

### 4.3 业务规则

- 邀请仍以邮箱为目标、一次性 Token 消费、角色仅 `EDITOR`/`VIEWER`、同一账本同一邮箱同时只允许一条 `PENDING`。
- 服务端在响应邀请时重新校验：当前登录身份、目标邮箱匹配、邀请状态与有效期、账本仍存在、当前是否已是活跃成员。
- 登录回跳只接受站内 `/user/**` 路径；拒绝 `//`、反斜杠、`/../` 与其他域，禁止开放重定向。
- `token` 只出现在链接和请求体中，不写入日志、不进入页面标题或分享文案；回跳参数中不得出现访问凭据。
- 已是该账本活跃成员时，响应邀请返回“已加入”提示，不产生第二条成员关系；`LEFT`/`REMOVED` 成员按现状复用原成员关系恢复为 `ACTIVE`。
- 邀请相关错误文案区分“链接无效/已过期/已处理/邮箱不匹配”，但不泄露其他用户资料。

## 5. 本期不做的图片附件

账单图片附件与对象存储不在三期范围。本期不新增附件表、上传/读取/删除接口、对象存储部署、附件备份恢复演练和图片相关验收；记账快捷条中的“图片”入口继续保持禁用或隐藏。

已有的[账单图片附件与对象存储设计](../architecture/账单图片附件与对象存储设计.md)仅作为后续专项方案保留，不进入本期实施计划、数据库迁移和接口契约。后续重新立项时，需要重新确认存储选型、服务器容量、备份恢复和移动端上传体验。

## 6. 需求二：历史备注快捷选择

- 备注继续作为账单字段保存，上限沿用 200 字，不新增独立“备注模板”实体。
- 记账表单的备注区域提供最近使用备注候选，按当前用户在当前账本中的最近使用时间排序，取前 10 条并按文本去重。
- 点选候选仅填入备注，不自动提交；填入后可继续修改、追加或清空。
- 候选只来源于用户有权访问的当前账本中已保存的账单备注；不得跨账本出现，避免共享账本成员互相看到他人私人备注习惯。
- 空备注与纯空白备注不进入候选；账单被删除或备注被改空后，该文本不再作为候选出现。
- 离线新建的账单在同步成功前只在本地可用，不作为服务端候选来源。
- 本期不做候选的手动置顶、删除单条候选或候选分组。

## 7. 需求三：原生键盘与记账面板适配

### 7.1 问题定位

当前记账面板使用 `100dvh` 固定高度，文本输入（标题、备注）字号为 12px。iOS Safari 在聚焦字号小于 16px 的输入框时会自动放大页面；同时面板底部常驻自定义数字键盘，编辑商家或备注时系统键盘弹出，被键盘覆盖的输入框和提交按钮不可达。

### 7.2 要求

- 聚焦标题、备注等文本输入并弹出原生键盘时，页面不得自动放大。字号调整是主要手段，不通过禁止系统缩放规避。
- **键盘不顶起面板**：系统键盘弹出不改变记账面板高度、不把面板整体上推，面板内容保持原位。
- **数字键盘不隐藏**：自定义数字键盘保持原位，被系统键盘覆盖即可，不做卸载、隐藏或重排。
- **编辑条浮于键盘上方**：编辑商家或备注时，一个编辑条动态出现在系统键盘正上方，包含输入框与历史备注候选；键盘收起后编辑条消失，已输入内容保留在表单中。
- 编辑条内提供等效的保存操作：当数字键盘的提交键被键盘覆盖时，用户仍可在不收起键盘的情况下保存账单。
- 备注候选条横向可滑动；无候选时不占用多余高度，避免编辑条高度跳动。
- 键盘收起、切换支出/收入、切换分类或打开时间选择后，已填写内容不丢失，面板布局保持稳定。
- 兼容 iOS Safari、iOS PWA、Android Chrome、Android PWA 以及横竖屏切换；不出现系统键盘与编辑条错位。

## 8. 需求四：日期时间选择优化

### 8.1 问题定位

当前仅依赖隐藏的原生 `datetime-local` 输入框配合 `showPicker()` 唤起系统选择器。不同浏览器表现不一致，选择器容易与键盘、面板底部和底部安全区重叠，用户难以确认选择结果。

### 8.2 要求

- 用户在记账面板点击时间胶囊后，可修改年、月、日、时、分；默认值为当前时间。
- 选择器以**独立弹出层**呈现，叠加在记账面板之上，不与面板底部合体、不使用底部面板形态；打开时先收起系统键盘。
- 选择器提供明确的“取消”和“确认”：取消不改变原值，确认后才更新发生时间；非法时间不允许提交。
- 选择器不得被面板边界、键盘、底部导航或屏幕安全区裁剪；内容超出时可内部滚动，取消与确认始终可触达。
- 键盘可操作，触控目标满足移动端点击尺寸，控件有可读名称。
- 修改后账单日期分组与统计月份仍按现有账本时区规则计算；写入时间为带时区偏移的 ISO 时间。

### 8.3 组件选型要求

当前前端未引入日期组件库。本期采用自建弹窗（日历 + 时间列），要求：受控输入、时区与日历边界正确、可访问、样式受 Tailwind 控制、无新增第三方依赖。若后续确需第三方日历库，须重新评审体积、样式改造与移动端适配成本，并记录结论到 UI 文档。

## 9. 范围与优先级

### 9.1 本期包含

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| P0 | 邀请流程修复 | 阻断共享账本加入，必须先修 |
| P0 | 键盘与面板适配 | 阻断移动端记账输入 |
| P1 | 历史备注快捷选择 | 高频效率提升 |
| P1 | 日期时间选择优化 | 高频输入可靠性提升 |

### 9.2 本期不包含

- OCR、票据结构化、报销审批。
- 邮件/短信/推送通知、站内消息中心、邀请提醒红点之外的提醒形态。
- 备注模板管理、标签体系、图片附件及其批量管理。
- 转账、预算、导入导出。

### 9.3 建议实施顺序

1. 邀请回跳与就地响应（含邮箱补全）。
2. 键盘视口适配与输入字号修正。
3. 备注候选。
4. 日期时间选择器选型与替换。

## 10. 页面与状态

| 页面 | 需要覆盖的状态 |
| --- | --- |
| 我的邀请 `/user/invitations` | 加载中、无邀请、待处理、已处理/过期/撤销、邮箱不匹配、登录刚回跳、响应失败可重试 |
| 成员与邀请 | 待处理邀请列表、复制链接、撤销、创建失败（重复邀请/个人账本） |

## 11. 验收标准

### 11.1 邀请（对应 4.2、4.3）

- 给定未登录用户打开有效邀请链接，当登录成功，则回到该邀请页并保留 `token`，可直接接受或拒绝。
- 给定注册新账号的同一路径，当注册成功，则与登录一致地回到邀请页，不丢失邀请。
- 给定已登录且邮箱匹配的用户，当在“我的邀请”点击接受，则该用户加入账本且只存在一条活跃成员关系。
- 给定已登录但邮箱不匹配的用户，当响应邀请，则服务端拒绝、邀请仍为 `PENDING`，页面给出补全邮箱入口。
- 给定邀请已过期、被撤销或已处理，当打开旧链接或列表刷新，则显示对应终态且不提供接受操作。
- 给定回跳参数指向外部域名或含 `//`、`\`、`/../`，当登录完成，则跳转到站内默认页。
- 给定接受请求被重复提交，则只消费一次邀请且不重复创建成员关系。

### 11.2 备注（对应第 6 节）

- 给定账单保存了非空备注，当在同一账本打开记账抽屉并展开备注，则候选出现且按最近使用排序。
- 给定用户点选候选，则备注被填入且账单未提交，用户可继续编辑。
- 给定用户在其他账本记过备注，则其不出现在当前账本候选中。
- 给定空备注或纯空白备注，则不会成为候选。
- 给定候选多于 10 条，则只展示最近 10 条去重结果。

### 11.3 键盘（对应 7.2）

- 给定 iOS Safari 或 iOS PWA，当聚焦备注输入，则页面不自动放大，输入框与候选条位于键盘上方可见区域。
- 给定聚焦商家或备注输入，当系统键盘弹出，则记账面板高度不变、内容不上推，自定义数字键盘原位保留并被系统键盘覆盖。
- 给定系统键盘弹出，则编辑条出现在键盘正上方，包含输入框与历史备注候选。
- 给定编辑条内金额合法，当用户点击保存，则账单可以保存，不要求先手动收起键盘。
- 给定用户收起键盘，则编辑条消失且备注内容已写入表单，金额与已填内容不变。
- 给定 Android Chrome，当键盘弹出，则布局视口不被压缩，编辑条与键盘不错位。
- 给定切换支出/收入或打开时间选择，则已填写的金额、备注保持。
- 给定系统开启缩放，则应用不阻止缩放。

### 11.4 时间（对应第 8 节）

- 给定打开时间选择后取消，则发生时间保持原值。
- 给定确认合法时间并保存，则详情显示所选时间，日期分组与统计月份按账本时区计算。
- 给定点击时间胶囊，则系统键盘先收起，选择器以独立弹层覆盖在记账面板之上。
- 给定窄屏设备，则选择器内容不超出可视区域，取消与确认均可触达。
- 给定选择器进入实现前，则完成 iOS/Android 真机与无障碍验证并记录结论。

## 12. 测试要求

- 邀请：未登录回跳保留参数、注册回跳、列表就地接受、邮箱不匹配、过期/撤销/重复接受、开放重定向防护。
- 备注：账本隔离、排序与去重、空备注排除、上限 10 条、点选后可编辑。
- 键盘与时间：视口变化、软键盘开合、横竖屏、弹层定位、取消不变、时区与 DST 边界；需在 iOS 与 Android 真机或等效环境手工验收。
- 前端为表单与候选逻辑补充纯函数测试；后端为邀请响应补充 Service/Controller 测试，均不使用真实用户数据。
