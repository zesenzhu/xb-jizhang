# 一期账本与记账产品需求（评审稿）

## 1. 文档目的

本文定义第一期用户端账本、账单浏览与管理、快速记账和分类使用体验，作为后续产品评审、交互设计、后台领域设计、接口设计和前端开发的业务依据。

本文描述用户能做什么、系统如何响应、账单数据代表什么以及不同状态下的体验，不规定 NestJS、Next.js、数据库表、API 路径或组件实现。产品规则确认后，再分别形成后台、接口和 UI 设计文档。

本文是评审稿。带有“建议确认”的内容是完整需求中的推荐默认值，产品确认后更新状态为 `approved`。

## 2. 背景、目标与使用场景

### 2.1 背景与问题

- 用户记完一笔后，需要方便地回到按天组织的流水中核对、回忆和修正。
- 如果新增账单入口与账单浏览分离，用户需要在页面间切换，快速记账会变慢。
- 共享账本中，记录人和实际付款人可能不同；若不分别表达，成员核对账单时容易产生误解。
- 分类需要足够清晰以支持日常记录，同时不能强迫用户每次都进入很细的子分类。

### 2.2 产品目标

第一期围绕“打开账本、快速记账、回看和修正账单”建立完整闭环：

- 用户进入应用后优先看到当前账本流水和收支概览。
- 用户从账单页右下角进入记账抽屉，尽量少填字段即可完成一笔记录。
- 用户能按日期、类型、分类和关键词查找账单，并查看、修改或删除账单。
- 同一账本的成员共享账单视图；写入和修改能力由账本成员角色控制。
- 分类和账单数据保留稳定关系，支持未来增加自定义分类、标签、预算和统计能力。

### 2.3 核心使用场景

1. 用户打开账本页，查看当月收支概览和最近几天的流水。
2. 用户在账单页右下角点击“+”，选择类型、分类、金额和时间后保存；需要连续录入时使用“保存并继续”。
3. 用户想核对某笔消费时，按日期范围、分类或关键词筛选，打开详情并修正错误信息。
4. 共享账本成员共同查看流水；记录人可与实际付款人不同，成员按权限新增、编辑或删除账单。
5. 用户需要快速记录支出或收入，并在账单流水中核对对应的分类、时间和金额。

## 3. 用户与术语

| 术语 | 定义 |
| --- | --- |
| 账本 | 收纳一组收入和支出记录的业务空间；用户可在多个账本间切换。 |
| 账单 | 用户记录的一次资金收入或资金支出。 |
| 记账人 | 创建这条账单的用户。 |
| 实际付款人 | 共享账本中实际承担支出的成员；可以与记账人不同。 |
| 商家/对象 | 支出对应的商户或收入对应的来源名称，是普通文本，不要求先建立商家档案。 |
| 分类 | 描述收入或支出用途的账本内目录。 |
| 账单日 | 按账本时区划分的账单发生日期，用于日期分组和统计。 |

## 4. 一期范围

### 4.1 一期包含

- 查看和切换有权访问的账本。
- 账单页顶部展示当前筛选范围的收入、支出和净收支概览。
- 按账单日分组展示流水，日期从近到远排列。
- 按日期范围、账单类型、分类和关键词筛选、搜索账单。
- 从账单页右下角打开记账抽屉，创建支出和收入。
- 查看账单详情，按权限编辑和删除账单。
- 选择账本内的收入、支出分类；支持一级分类和二级分类。
- 支持个人账本和多人共享账本；展示记录归属并执行成员权限限制。
- 在安装为 PWA 后提供一致的移动端和桌面端核心操作体验。

### 4.2 一期不包含

- 分类管理页面，包括新增、编辑、排序、停用和恢复分类。
- 预算、周期账单、账单分摊、标签、附件、票据识别、账单导入导出。
- 商家档案、商家统计和商家管理。
- 跨币种折算、汇率维护和多币种账本。
- 转账记账；后续迭代再单独设计转账的账户规则和统计口径。
- 离线创建账单和离线队列自动同步。
- 平台管理员查看或修改普通用户的账单。
- 账本创建、共享邀请、成员加入/退出和所有权转移的完整流程；这些由账本与成员领域需求单独定义。

## 5. 页面与导航

### 5.1 账单页

账单页是普通用户进入应用后的主要页面，包含以下区域：

1. **账本栏**：显示当前账本名称和切换入口；仅有一个可用账本时仍显示当前账本名称。
2. **收支概览**：显示当前统计范围的总支出、总收入和净收支。净收支等于总收入减总支出。
3. **查询区**：提供关键词搜索和筛选入口，展示已生效的筛选条件。
4. **账单列表**：按账单日分组，每日一个日期分组卡片，组内按发生时间从晚到早排列；日期较新的分组在上方，较早的分组在下方。
5. **记账入口**：仅在账单页右下角显示“+”按钮；当前成员有新增账单权限时显示。

账单列表采用单列纵向阅读。这里的“瀑布流”指按日期连续向下浏览，不表示多列错落布局。一个日期卡片可包含多笔账单。

### 5.2 账单日分组卡片

每个日期卡片显示：

- 日期和星期；当天是今天或昨天时，可同时显示“今天”“昨天”。
- 当天存在支出时显示支出合计；当天存在收入时显示收入合计；当天没有对应类型时不显示该项。
- 当天的账单行。

### 5.3 账单行

每条账单行至少显示：

- 分类图标与分类名称。
- 账单发生时间；跨日账单按账单时区归入对应日期。
- 商家/对象或备注。有两者时优先显示商家/对象，备注作为次级信息；都为空时不显示占位文案。
- 右侧金额。支出显示负向标识，收入显示正向标识。

支出和收入的颜色与正负标识应保持一致，不能只依靠颜色区分类型。

### 5.4 记账按钮位置与显隐

- “+”按钮固定在账单页右下角，视觉位置参考用户提供的账单页截图；没有新增账单权限的成员不显示该按钮。
- 用户滚动账单列表时按钮保持在视口内，不跟随某一条账单移动。
- 按钮遵守设备底部和右侧安全区域，不遮挡最后一条账单的主要内容或必要操作。
- 打开记账抽屉后，按钮由抽屉覆盖，不重复显示。
- 离开账单页后不显示该按钮。账单详情、分类选择/管理、账户页、成员页、设置页以及登录页均不显示此入口。
- 其他页面如需新建账单，应先返回账单页；第一期不增加全局悬浮记账入口。

### 5.5 页面状态

- **首次加载**：显示账本栏、概览和列表骨架；不以空账单误导用户。
- **有账单**：按日期分组展示，滚动到列表底部后继续加载更早数据。
- **空账本**：显示“还没有账单”状态；有新增账单权限时显示右下角“+”入口；不伪造金额或日期卡片。
- **筛选无结果**：显示“没有符合条件的账单”和清除筛选操作；保留已输入条件供用户修改。
- **加载失败**：保留已显示内容和筛选条件，提供重试；不清空页面状态。
- **切换账本**：概览、日期分组和账单列表切换到新账本；筛选条件重置为默认当月和全部类型/分类/成员；不短暂展示上一个账本的数据。

## 6. 概览、搜索与筛选

### 6.1 默认统计范围

- 首次进入账单页默认显示当前账本、本地账单时区下的当月数据。
- 概览金额、每日合计和账单列表必须使用同一组已生效筛选条件。
- 搜索或分类筛选后，概览同步缩小到匹配的账单，并明确显示“筛选结果”或等价提示。

### 6.2 筛选条件

一期支持以下条件：

| 条件 | 规则 |
| --- | --- |
| 日期范围 | 支持当月、上月、今年、全部和自定义开始/结束日期；起止日期均包含在结果内。 |
| 账单类型 | 全部、支出、收入；默认全部。 |
| 分类 | 支出或收入分类；选择一级分类时包含其全部二级分类账单。 |
| 关键词 | 匹配备注、商家/对象名称和分类名称；忽略首尾空格，不区分大小写。 |
| 记录成员 | 共享账本可选择记账人；默认全部成员。个人账本不显示此条件。 |

筛选条件同时生效时采用“同时满足”规则。日期范围与关键词、类型、分类、成员条件组合后，概览和账单列表保持一致。

- 点击筛选入口后打开筛选面板，分别设置日期范围、类型、分类和记账人。
- 面板提供“重置”和“应用”操作；应用后关闭面板并更新列表、概览和已生效条件标记。
- 关闭面板或点击取消时放弃本次尚未应用的筛选变更。
- 自定义日期范围需要同时选择开始和结束日期；开始日期晚于结束日期时不能应用。

### 6.3 搜索交互

- 搜索框有明确的搜索和清空操作。
- 用户点击搜索操作或在键盘上确认后更新结果，并保留日期、类型、分类和成员筛选；输入过程中不逐字刷新结果。
- 用户清空关键词后恢复其他筛选条件下的完整结果。
- 用户使用“清除全部”后回到默认当月、全部类型、全部分类和全部成员。
- 打开账单详情再返回列表时，保留当前筛选条件和大致滚动位置。

## 7. 快速记账抽屉

### 7.1 打开与关闭

- 用户点击账单页右下角“+”后，从屏幕底部弹出记账抽屉。
- 移动端抽屉覆盖页面下半部并保留账单页上下文；桌面端沿用同一交互结构并限制内容宽度。
- 抽屉左上角为“×”关闭按钮。
- 未填写任何内容时，点击关闭或遮罩可直接关闭。
- 已填写金额或其他有效内容时，关闭前提示“放弃本次记账吗”；用户可选择继续填写或放弃。
- 第一期不把下滑手势作为唯一关闭方式；若支持下滑关闭，也必须执行相同的未保存内容保护。

### 7.2 抽屉信息层级

抽屉从上到下包含：

1. 顶部操作区：关闭按钮、标题、保存操作。
2. 金额显示区：显示当前输入金额和币种。
3. 账单类型选择：支出、收入，位于抽屉主要内容区且在数字键盘上方，作为容易触达的分段选择器。
4. 分类与账单信息区：收支分类、日期时间、账户、商家/对象、实际付款人和备注等字段。
5. 底部数字键盘：固定在抽屉底部，随键盘输入金额；保存操作不能被键盘遮挡。

分类和账单信息允许按空间折叠或分组，但金额、类型、当前分类、发生时间和保存操作必须清楚可见。

- 点击分类字段后进入分类选择面板；面板按一级分类分组，可展开查看二级分类。
- 选择分类后返回记账抽屉，并在分类字段显示所选路径；再次点击可更换。
- 点击日期时间字段后打开日期和时间选择器，确认后返回抽屉并显示新值。
- 点击账户字段后打开当前账本可用账户列表；账户为可选项。
- 点击商家/对象字段后可从当前账本最近使用的最多 5 个名称中选择，也可以输入新文本；建议去重并按最近使用时间排序。
- 点击备注字段后进入文本编辑状态；确认后返回抽屉并显示备注。

### 7.3 类型切换

- 首次打开时默认选中“支出”。
- 用户可以随时切换“支出”和“收入”。
- 支出和收入必须选择对应类型的分类；切换收支类型后清除原分类选择，避免把支出分类误用于收入。
- 在支出和收入之间切换时保留金额、日期时间、备注和已输入的商家/对象文本。

### 7.4 字段与必填规则

| 字段 | 支出 | 收入 | 规则 |
| --- | --- | --- | --- |
| 金额 | 必填 | 必填 | 大于零，精确到分；不允许负数。 |
| 分类 | 必填 | 必填 | 只能选择相同收支类型且可用于新账单的分类。 |
| 发生日期时间 | 必填 | 必填 | 默认当前时间；允许补记过去账单；第一期不支持未来预约账单。 |
| 账户 | 可选 | 可选 | 可以指定一个资金账户；不填写时仍可保存账单。 |
| 商家/对象 | 可选 | 可选 | 支出填写商家，收入填写来源；支持文本输入和历史名称建议。 |
| 实际付款人 | 可选 | 不适用 | 共享账本默认当前用户；可选择该账本内的其他活跃成员。 |
| 备注 | 可选 | 可选 | 普通文本，最多 200 个字符。 |

支出或收入账户未填写时，账单仍可保存；此类账单不影响任何账户余额。

### 7.5 分类选择

- 支出类型只展示支出分类，收入类型只展示收入分类。
- 分类选择先按一级分类组织；有二级分类时，用户可以选择二级分类，也可以直接选择一级分类。
- 直接选择一级分类时，账单只关联一级分类，不自动猜测或选择某个二级分类。
- 已停用分类不出现在新建账单选择器中，但历史账单仍能显示原分类。
- 分类没有子分类时，点击一级分类即完成选择。

### 7.6 日期和时间选择

- 默认值为打开抽屉时的当前日期时间。
- 用户可以修改日期和具体时间，便于补记。
- 日期按账本时区解释；列表分组和统计使用同一时区。
- 选择未来时间时阻止保存，并将日期时间控件定位为需要修正的字段。
- 用户修改日期后，抽屉关闭或保存成功前不得静默重置为当前时间。

### 7.7 数字键盘

- 键盘包含数字 `0` 至 `9`、小数点、删除一位和清空金额操作。
- 金额最多两位小数；输入第三位小数时不接受。
- 小数点只能出现一次；删除操作从末尾删除一位。
- 金额未输入、金额为零或无法按账本币种精确表达时，保存按钮不可提交，并显示可理解的校验说明。
- 外接键盘或系统输入法输入金额时，校验规则保持一致。

### 7.8 保存与继续记账

- **保存**：校验通过后创建账单，成功提示后关闭抽屉并刷新当前账本的列表和概览。
- **保存并继续**：校验通过后创建账单，抽屉保持打开，清空金额、商家/对象和备注；保留账单类型、日期时间、分类和账户，便于连续录入同类账单。
- 保存期间禁用重复提交并显示处理中状态。
- 保存失败时保留用户输入，说明失败原因并允许重试；不得因为网络错误清空表单。同一表单因超时重试不得创建重复账单。
- 如果成员权限在抽屉打开后发生变化并失去创建权限，阻止提交并提示联系账本所有者调整权限。

## 8. 账单详情与管理

### 8.1 查看详情

点击账单行打开详情，展示：

- 类型和金额；
- 分类；
- 发生日期时间；
- 账户（如果填写）；
- 商家/对象、备注（如果填写）；
- 实际付款人（支出且已填写时）；
- 记账人和最后修改人；
- 创建时间和最后更新时间。

查看人不能通过详情页看到其无权访问的其他账本信息。

### 8.2 编辑

- 有编辑权限的成员可从详情进入编辑状态，编辑字段规则与新建账单相同。
- 编辑时预填当前账单全部可编辑字段；取消编辑不改变账单。
- 成功保存后详情、列表、日合计和顶部概览立即反映新数据。
- 若账单在编辑期间已被其他成员修改，提示“账单已更新”，展示最新内容；用户确认后再基于最新内容重新编辑，不静默覆盖他人修改。
- 创建人始终保留为原记账人；修改人和修改时间更新为最后一次成功修改的成员和时间。

### 8.3 删除

- 用户从详情选择删除后，展示账单金额、类型和日期供确认。
- `OWNER` 可以删除账本内任意账单；`EDITOR` 仅可删除自己创建的账单。无删除权限时不展示删除操作。
- 确认删除后账单从默认列表和统计中移除；页面提供 5 秒撤销入口。
- 用户在 5 秒内撤销后，账单恢复到原日期分组和统计。
- 已删除账单不允许继续编辑；重复删除应给出稳定结果，不重复影响统计。
- 删除不等于物理抹除业务记录；共享账本需要保留操作人和操作时间以便追溯。

## 9. 分类产品规则

### 9.1 分类结构

- 分类属于账本，分为支出分类和收入分类，两者不能交叉使用。
- 分类最多两级：一级分类和二级分类。
- 有子分类的一级分类本身仍可用于记账。
- 同一账本、同一收支类型下，同级分类名称不重复；收入和支出可以有同名分类。
- 分类有稳定身份。后续重命名或调整图标不改变历史账单所关联的分类身份，历史账单同步显示该分类最新名称和图标。
- 分类被停用后，不能用于新账单；历史账单仍展示该分类最近保存的名称和图标，并可标记为已停用。

### 9.2 一期分类体验

- 一期提供系统默认收支分类，账单创建时可以选择。
- 分类管理页面不属于本期交付；一期不提供用户新增、重命名、排序或停用分类的入口。
- 默认分类建议覆盖以下常见日常场景，并保留“其他”兜底项：

| 类型 | 一级分类 | 二级分类建议 |
| --- | --- | --- |
| 支出 | 餐饮 | 早餐、午餐、晚餐、饮品零食、其他餐饮 |
| 支出 | 交通 | 公共交通、打车、自驾、长途出行 |
| 支出 | 购物 | 日用品、服饰鞋包、数码家电、其他购物 |
| 支出 | 居住 | 房租、水电燃气、物业、家居维修 |
| 支出 | 生活服务 | 通讯、快递、生活服务、其他生活 |
| 支出 | 医疗健康 | 医疗、药品、运动健身、其他健康 |
| 支出 | 教育学习 | 学费课程、书籍资料、其他学习 |
| 支出 | 娱乐休闲 | 电影演出、游戏、旅游、其他娱乐 |
| 支出 | 人情往来 | 礼金红包、聚会、其他人情 |
| 支出 | 其他支出 | 无 |
| 收入 | 工资收入 | 工资、奖金、补贴 |
| 收入 | 经营收入 | 经营所得、劳务收入、其他经营 |
| 收入 | 投资理财 | 利息、分红、其他投资 |
| 收入 | 报销退款 | 报销、退款、其他返还 |
| 收入 | 人情收入 | 礼金红包、其他人情 |
| 收入 | 其他收入 | 无 |

- 新建账本时提供对应的默认分类；账本内成员看到同一套分类。
- 上表是产品建议目录，名称、层级和排序在需求评审时确认；确认后作为一期默认目录。

### 9.3 后续分类管理预留

后续迭代应支持新增、编辑名称和图标、调整排序、增加二级分类、停用和恢复分类。分类管理必须遵守：

- 不能因停用分类而丢失历史账单；
- 已被历史账单引用的分类不能被物理删除；
- 管理分类的成员权限与普通记账权限分开定义；
- 批量调整分类时必须说明对历史账单展示和统计的影响。

## 10. 多人共享账本规则

账单属于账本，账本成员看到的是该账本范围内的共同流水。成员身份和账单的记账人、实际付款人是不同概念。

| 角色 | 查看账单 | 新增账单 | 编辑账单 | 删除账单 | 选择分类 |
| --- | --- | --- | --- | --- | --- |
| `OWNER` | 允许 | 允许 | 允许 | 允许 | 允许 |
| `EDITOR` | 允许 | 允许 | 允许 | 仅可删除自己创建的账单 | 允许 |
| `VIEWER` | 允许 | 禁止 | 禁止 | 禁止 | 查看账单中已有分类 |

- 列表默认展示当前账本所有成员的账单，不只显示当前用户自己的记录。
- 共享账本可按记账人筛选；实际付款人用于表达谁承担了支出，不能替代记账人。
- 账单详情显示记账人；支出填写实际付款人后也显示实际付款人。
- `EDITOR` 可以编辑账本内账单，但删除权限仅限自己创建的账单；`OWNER` 可以删除账本内任意账单。
- 成员失去账本访问权后，不得继续读取该账本的账单详情或提交新修改。
- 平台管理员身份不继承普通账本成员权限，也不通过普通账单页面修改用户账单。

## 11. 账单业务数据

以下字段描述产品数据含义，字段名可在后台和接口设计阶段调整。

| 数据 | 必需性 | 说明 |
| --- | --- | --- |
| 账本信息 | 必需 | 包含账本标识、名称、币种、展示时区和有效状态；一期默认人民币和 `Asia/Shanghai`。 |
| 账本成员关系 | 必需 | 包含成员、角色和成员状态；仅当前有效成员可访问该账本。 |
| 分类信息 | 必需 | 包含分类标识、账本、收支类型、名称、父级分类、图标、排序和启用状态；一级分类的父级为空。 |
| 账单标识 | 必需 | 唯一标识一条账单，用于详情、编辑和删除。 |
| 账本标识 | 必需 | 账单唯一所属的账本。 |
| 类型 | 必需 | 支出或收入。 |
| 金额 | 必需 | 正数，精确到最小货币单位；类型决定其统计方向。 |
| 币种 | 必需 | 一期每个账本使用一种币种，默认人民币；不进行跨币种折算。 |
| 分类 | 必需 | 必须与账单类型匹配。一级分类直接使用时，二级分类为空。 |
| 发生时间 | 必需 | 用户认定的交易发生时间，用于排序和统计。 |
| 账户 | 可选 | 用户为收入或支出选择的资金账户。 |
| 商家/对象 | 可选 | 支出商家或收入来源的文本名称。 |
| 备注 | 可选 | 用户补充说明，最多 200 个字符。 |
| 记账人 | 必需 | 实际创建账单的成员。 |
| 实际付款人 | 支出可选 | 共享账本内实际承担该笔支出的成员。 |
| 创建时间 | 必需 | 系统记录的首次创建时间，不等同于发生时间。 |
| 最后修改人和修改时间 | 修改后必需 | 用于详情展示和共享账本追溯。 |
| 修改版本 | 编辑时必需 | 用于识别账单是否已被其他成员更新，避免静默覆盖。 |
| 删除状态 | 必需 | 表达账单是否已删除；删除后保留必要的追溯信息。 |
| 删除人和删除时间 | 删除后必需 | 用于共享账本追溯和撤销删除操作。 |

### 11.1 金额规则

- 金额在录入和展示时使用账本币种格式，最多精确到分。
- 账单金额本身始终是正数；支出/收入类型决定金额含义，不能用负金额表达类型。
- 一期不支持同一账本内混合币种，也不支持汇率换算。
- 统计使用精确金额累加，不因展示四舍五入改变账单原值。

### 11.2 账本、成员和分类规则

- 账单始终归属一个账本；不能把账单移动到另一个账本。
- 账本成员角色取 `OWNER`、`EDITOR`、`VIEWER`；账单操作权限按第 10 节执行。
- 分类在同一个账本内唯一识别；跨账本分类即使名称相同，也视为不同分类。
- 分类父级为空表示一级分类；有父级标识表示二级分类。不得超过两级。
- 分类图标和排序用于账单列表、分类选择面板和后续分类管理。

### 11.3 时间规则

- 每个账本有明确的展示时区，一期默认 `Asia/Shanghai`。
- 日期分组和按月统计都以账本时区为准，不以查看成员设备的当前时区重新划分账单。
- 修改发生时间可以改变账单所属日期、月份和统计范围，但不改变创建时间。

## 12. 统计口径

- 总支出：当前筛选结果中的支出金额合计。
- 总收入：当前筛选结果中的收入金额合计。
- 净收支：总收入减总支出，可以为负数。
- 删除账单不参与默认列表、每日汇总和顶部概览；撤销删除后恢复计算。
- 修改金额、分类、类型或发生时间后，旧分组和新分组的统计同时更新。
- 未填写账户的收支账单仍参与收支统计。

## 13. 网络与 PWA 状态

- 一期支持 PWA 安装和正常联网使用；安装状态不改变账单的业务规则。
- 离线时可以打开已安装应用，但账单页明确提示需要联网查看最新账单；一期不承诺展示本地缓存的账单内容。
- 一期离线状态不允许提交新账单、编辑或删除账单，避免共享账本出现不可见的权限变化和同步冲突。
- 用户在提交时遇到断网，表单内容保留在当前页面，恢复网络后可手动重试；不得显示“已记账”成功状态。
- 离线创建和自动同步作为后续独立需求评估，届时需定义待同步状态、重复提交保护、成员权限变化和失败恢复流程。

## 14. 产品交付影响与验证要求

### 14.1 产品交付影响

- **页面**：账单页、账单筛选面板、记账抽屉、分类选择面板、账单详情和编辑状态。
- **业务能力**：账本切换、账单查询与统计、收入/支出、账单修改与删除、分类选择、成员权限和记录归属。
- **产品数据**：账本币种与时区、成员角色、分类层级、账单类型/金额/发生时间、账户、商家/对象、备注、记账人、实际付款人和修改/删除追溯信息。
- **接口设计输入**：需要表达本需求中的账单字段、筛选条件、分页结果、账本角色、创建/编辑/删除结果和并发冲突；具体接口路径与响应结构由后续 API 文档定义。
- **UI 设计输入**：需要覆盖加载、空账本、筛选无结果、无权限、保存失败、断网、保存中、删除确认和撤销等状态。

### 14.2 验证要求

- 金额、分类类型匹配、日期边界和日/月汇总规则应有自动化单元验证。
- 创建、详情、筛选、编辑、删除和角色权限应有服务端请求契约验证，覆盖失败路径和跨账本拒绝。
- 记账抽屉应验证类型切换、必填规则、数字键盘、保存、保存并继续、关闭未保存提醒和失败后保留输入。
- 只有需要验证账单页到记账抽屉再返回列表的完整跨页面流程时，才使用端到端流程验证。

## 15. 验收标准

1. **给定**用户进入账单页，**当**当月数据加载完成，**则**页面显示当前账本、当月收入/支出/净收支概览和按日期从新到旧排列的分组。
2. **给定**同一天有多笔账单，**当**账单列表加载完成，**则**这些账单位于同一日期分组，且每行显示图标、分类、时间、备注或商家/对象和金额。
3. **给定**当前成员有新增账单权限且正在查看账单页，**当**滚动账单列表，**则**“+”固定在右下角；无新增权限的成员或离开账单页后不显示该入口。
4. **给定**用户位于账单页，**当**点击“+”，**则**底部弹出记账抽屉，左上角有关闭按钮，支出/收入类型可切换，底部数字键盘可输入金额。
5. **给定**用户创建支出或收入，**当**分类、金额或时间无效，**则**保存被阻止并定位到需要修正的字段；全部有效时才可提交。
6. **给定**一级分类有二级分类，**当**用户直接选择一级分类，**则**账单关联一级分类且系统不自动选择二级分类。
7. **给定**用户创建支出或收入，**当**未选择账户但其他必填项有效，**则**账单仍可保存且不影响账户余额。
8. **给定**表单校验通过，**当**用户选择“保存”，**则**账单创建成功、抽屉关闭，列表、日合计和概览更新。
9. **给定**表单校验通过，**当**用户选择“保存并继续”，**则**账单创建成功、抽屉保持打开，金额/商家/对象/备注清空，类型/时间/分类/账户保留。
10. **给定**保存遇到服务错误或网络中断，**当**提交失败后重试，**则**表单输入保留、页面不显示错误的成功状态，且同一笔账单最多创建一次。
11. **给定**用户组合关键词、日期、类型或分类筛选，**当**结果加载完成，**则**概览和列表遵守相同条件；清除关键词不清除其他条件。
12. **给定**用户打开账单详情，**当**详情展示完成，**则**用户可以区分发生时间和创建时间，并看到记账人及实际付款人（如有）。
13. **给定**其他成员在编辑期间已更新该账单，**当**当前用户提交旧版本，**则**系统提示数据已更新，不覆盖新内容。
14. **给定**操作者删除账单，**当**操作者是 `OWNER` 或该账单创建人 `EDITOR`，**则**允许删除；其他 `EDITOR` 和 `VIEWER` 无删除入口且不能删除。
15. **给定**有删除权限的成员确认删除，**当**删除成功，**则**账单离开默认列表和统计；5 秒内撤销后恢复原分组和金额。
16. **给定**用户是 `VIEWER`，**当**其尝试新增或编辑账单，**则**操作被拒绝；非账本成员无法读取账单详情或提交操作。
17. **给定**账单发生时间跨设备时区或被修改，**当**重新计算日期分组和月度统计，**则**使用账本时区而非查看设备时区。

## 16. 未决问题与一期建议

| 决策 | 一期建议 | 建议理由 |
| --- | --- | --- |
| 分类层级和一级分类 | 最多两级；有子分类的一级分类允许直接记账。 | 兼顾分类细化和快速记账，不强迫用户每次选择二级分类。 |
| 商家/对象管理 | 文本输入并提供历史名称建议；不做商家档案管理。 | 满足快速选择和关键词查找，同时控制第一期范围。 |
| 概览是否跟随搜索条件 | 跟随全部已生效筛选条件，页面明确提示当前为筛选结果。 | 让顶部统计与用户眼前的账单范围一致。 |
| 离线记账 | 一期不支持离线写入；断网保留表单并允许恢复网络后重试。 | 多人账本还需处理权限变化、重复提交和同步冲突，适合独立设计。 |
| 一级分类默认目录 | 采用第 9.2 节目录作为评审起点，确认后固化为一期默认分类。 | 分类目录需要产品校准，不应在技术实现中临时固化。 |
| 共享账本删除权限 | `OWNER` 可删除全部账单；`EDITOR` 仅可删除自己创建的账单。 | 限制误删范围，同时允许成员修正自己的记录，并保留负责人治理能力。 |

本节各项在产品确认前均为未决项；未确认前，后台和前端设计应按建议值推演，不应将建议当作已批准规则。
