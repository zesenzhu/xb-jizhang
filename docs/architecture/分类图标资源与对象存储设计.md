# 小宝记账分类图标资源与对象存储设计

## 1. 设计结论

第五期分类图标由“图标库图标”和“用户上传图片”两类资源组成。分类本身保存图标来源和稳定引用，图片二进制继续存放在私有对象存储中，PostgreSQL 保存资源元数据和生命周期状态。

| 领域 | 结论 |
| --- | --- |
| 分类图标来源 | `NONE`、`LIBRARY`、`IMAGE` 三种互斥来源 |
| 系统图标 | Tabler 精选子集，保存带命名空间的稳定 `iconKey` |
| 默认分类识别 | 增加稳定 `defaultKey`，不能依赖分类名称 |
| 自定义图片 | 新增独立 `CategoryIconAsset` 资源，不复用账单附件表 |
| 上传 | 延续第四期预签名 `PUT`，浏览器直传 OSS/MinIO |
| 完成确认 | 后端通过 `HEAD` 和文件头读取确认大小、真实 MIME 和对象存在 |
| 读取 | 活跃账本成员通过 NestJS 鉴权后获取短期签名 URL |
| 对象键 | `ledgers/{ledgerId}/category-icons/{assetId}.{extension}` |
| 清理 | `PENDING` 超时、未绑定 `ATTACHED` 资源和被替换资源异步清理 |
| 统计口径 | 图标只提供展示元数据，不改变金额、余额、时间范围和下钻规则 |

本文是第五期后台实现的技术基线。具体路径和请求字段以[分类图标接口](../api/分类图标接口.md)为准。

## 2. 范围与边界

本期包含：

- 默认一级、二级分类的稳定图标映射；
- Owner 选择图标库图标、恢复系统默认图标和上传分类图片；
- 分类图片的上传会话、完成确认、读取地址、替换和清理；
- 分类查询与统计查询返回同一套图标语义；
- 共享账本成员读取同一个账本范围内的分类图标。

本期不包含：

- 任意 SVG 文件上传、AI 生成图标和图标素材市场；
- 通用网盘、独立文件夹、图片内容搜索和 OCR；
- 统计金额、统计周期、余额或账单分类层级调整；
- 历史账单图标快照。历史账单展示当前分类名称和当前分类图标。

## 3. 当前代码与迁移问题

当前 `Category` 使用单个可空 `icon` 字符串，默认分类常量虽然有 `key`，但初始化写入数据库时没有保存该键。仅在现有字段上继续堆叠约定会产生以下问题：

1. 无法区分图标库键、图片资源 ID 和历史遗留字符串；
2. Owner 修改系统分类名称后，服务端无法可靠找到对应的默认图标；
3. 新分类上传图片时，分类可能还没有创建，无法只依赖分类 ID 绑定资源；
4. 图片替换后无法判断旧对象是否仍是当前分类引用；
5. 统计接口和分类接口容易返回不同的图标字段。

因此第五期采用新增字段和独立资源模型的迁移方式。现有 `icon` 数据需要在 Migration 中按已知命名空间转为 `iconKey`；无法识别的历史字符串降级为 `NONE`，不允许直接当作可信的图标组件名使用。兼容字段是否在后续版本删除，单独通过迁移评审确认。

## 4. 分类数据模型

### 4.1 分类图标字段

建议在 `Category` 增加以下字段：

```prisma
enum CategoryIconSource {
  NONE
  LIBRARY
  IMAGE
}

model Category {
  // 现有字段省略
  defaultKey   String?              @map("default_key")
  iconSource   CategoryIconSource   @default(NONE) @map("icon_source")
  iconKey      String?              @map("icon_key")
  iconAssetId  String?              @unique @map("icon_asset_id")
  iconAsset    CategoryIconAsset?   @relation("CategoryCurrentIcon", fields: [iconAssetId], references: [id], onDelete: SetNull)
}
```

`defaultKey` 只对系统默认分类有值，自定义分类为 `null`。`iconAssetId` 只在 `iconSource=IMAGE` 时有值。数据库唯一约束保证一个图片资源最多被一个分类作为当前图标引用。

### 4.2 默认分类稳定键

默认分类常量需要同时维护名称、排序和默认图标：

```text
defaultKey: expense.food
defaultIconKey: tabler:tools-kitchen-2
defaultColor: #F97316
```

初始化和历史补齐必须写入 `defaultKey`。Owner 修改名称、排序、停用状态或当前图标时，不修改 `defaultKey`。恢复默认图标时，服务端根据 `defaultKey` 查找默认图标和颜色，名称、排序和启用状态保持不变。

历史账本补齐时：

- 已有带 `defaultKey` 的系统分类只补缺失图标字段；
- 已有名称、账单关联、停用状态和排序不覆盖；
- 无法可靠匹配旧系统分类的记录进入迁移报告，不按名称强行覆盖；
- 自定义分类不自动获得系统默认图标。

### 4.3 分类图标资源模型

```prisma
enum CategoryIconAssetStatus {
  PENDING
  ATTACHED
  DELETED
}

model CategoryIconAsset {
  id                String                    @id @default(uuid())
  ledgerId          String                    @map("ledger_id")
  uploadedById      String                    @map("uploaded_by_id")
  clientRequestId   String                    @map("client_request_id")
  objectKey         String                    @unique @map("object_key")
  originalName      String?                   @map("original_name")
  declaredMimeType  String                    @map("declared_mime_type")
  declaredSizeBytes Int                       @map("declared_size_bytes")
  mimeType          String?
  sizeBytes         Int?                      @map("size_bytes")
  width             Int?
  height            Int?
  status            CategoryIconAssetStatus   @default(PENDING)
  uploadExpiresAt   DateTime?                 @map("upload_expires_at")
  orphanExpiresAt   DateTime?                 @map("orphan_expires_at")
  uploadedAt        DateTime?                 @map("uploaded_at")
  deletedAt         DateTime?                 @map("deleted_at")
  purgedAt          DateTime?                 @map("purged_at")
  purgeAttempts     Int                       @default(0) @map("purge_attempts")
  lastPurgeError    String?                   @map("last_purge_error")
  lastUploadError   String?                   @map("last_upload_error")
  ledger            Ledger                    @relation(fields: [ledgerId], references: [id], onDelete: Cascade)
  category          Category?                 @relation("CategoryCurrentIcon")
  uploadedBy        User                      @relation(fields: [uploadedById], references: [id], onDelete: Restrict)
  createdAt         DateTime                  @default(now()) @map("created_at")
  updatedAt         DateTime                  @updatedAt @map("updated_at")

  @@unique([ledgerId, clientRequestId])
  @@index([ledgerId, status, createdAt])
  @@index([status, uploadExpiresAt])
  @@index([status, orphanExpiresAt])
  @@index([deletedAt, purgedAt])
  @@map("category_icon_asset")
}
```

资源不直接保存分类外键，是为了支持“新建分类时先上传图片、保存分类时再绑定”。分类通过 `Category.iconAssetId` 保存当前引用，未绑定资源通过反向关系为空识别。只有 `ATTACHED` 且未删除的资源可以被绑定为当前分类图标。资源替换和分类图标字段更新必须在同一数据库事务内完成。

## 5. 资源生命周期

```text
不存在
  -> PENDING（创建上传会话）
  -> ATTACHED（PUT 成功且完成确认通过）
  -> DELETED（取消、替换、超时或业务删除）
  -> purgedAt（对象物理删除成功）
```

### 5.1 创建与绑定

1. Owner 创建上传会话，服务端校验账本成员、文件大小和声明 MIME。
2. 服务端创建 `PENDING` 记录并签发短期 PUT 地址。
3. 浏览器直传对象后调用完成确认接口。
4. 服务端通过 `HEAD` 读取对象长度，并读取文件头检测 JPEG、PNG 或 WebP。
5. 校验成功后更新为 `ATTACHED`。
6. 分类新增或编辑时提交 `iconAssetId`，服务端在事务中校验同一账本、`ATTACHED`、未删除，并绑定资源。

上传完成但分类保存失败时，资源保留 `ATTACHED` 但没有分类反向引用，并设置较短的 `orphanExpiresAt`。清理任务到期后将其标记 `DELETED` 并删除对象，避免临时资源长期占用空间。

### 5.2 替换与清理

替换当前图片时，数据库事务执行以下动作：

1. 校验新资源属于当前账本且状态为 `ATTACHED`；
2. 将旧资源解除分类引用并标记 `DELETED`；
3. 将新资源绑定到分类；
4. 更新分类的 `iconSource=IMAGE` 和 `iconAssetId`。

对象删除在事务提交后异步执行。删除失败只增加重试次数并保存脱敏错误，不能回滚分类保存，也不能删除当前仍被引用的新资源。

## 6. 对象存储与安全

- 生产继续使用私有阿里云 OSS，本地使用私有 MinIO；业务服务只依赖 `ObjectStoragePort`。
- 分类图片和账单附件使用同一个 Bucket 时，使用不同对象前缀和最小权限策略；后续可独立迁移 Bucket。
- 浏览器只能访问当前会话收到的短期签名地址，不能列举 Bucket、指定对象键或调用管理 API。
- PUT 请求必须携带服务端返回的 `Content-Type`，完成确认不信任浏览器声明。
- CORS 允许正式前端和本地开发域名，允许 `PUT`、`GET`、`HEAD`，不使用 `*` 来源。
- 对象键、签名 URL、AccessKey 和图片内容不能写入普通日志或审计日志。
- `CATEGORY_ICON_ENABLED` 作为分类图标功能开关；`ATTACHMENT_ENABLED` 只控制账单附件，避免两个功能共享一个含义不清的开关。

建议配置：

```text
CATEGORY_ICON_ENABLED=true
CATEGORY_ICON_UPLOAD_URL_TTL_SECONDS=600
CATEGORY_ICON_READ_URL_TTL_SECONDS=300
CATEGORY_ICON_MAX_BYTES=2097152
CATEGORY_ICON_LEDGER_QUOTA_BYTES=134217728
```

分类图片是共享账本资源，建议按账本统计 `PENDING + ATTACHED` 的实际或声明大小，不占用某个成员的个人账单附件配额。配额值和是否允许后续扩容在上线前确认。

## 7. 图标库设计

图标库由后端维护可用白名单，前端使用 Tabler 组件渲染。数据库只保存稳定键，不保存 React 组件名或任意客户端代码。

图标键格式：

```text
tabler:tools-kitchen-2
tabler:bus
tabler:wallet
```

图标库条目包含：

```text
key
label
aliases
group
defaultTypes
```

升级图标依赖时必须保留旧键映射或降级到固定默认图标，不能因为包升级让历史分类显示空白。图标库许可证和版权说明随前端依赖和发布物保存。

## 8. 分类与统计响应

分类列表和统计分类项必须使用同一套图标描述：

```json
{
  "iconSource": "IMAGE",
  "iconKey": null,
  "iconAssetId": "asset-uuid",
  "iconUrl": "https://signed.example/短期地址",
  "iconUrlExpiresAt": "2026-11-10T08:00:00.000Z",
  "color": "#F97316"
}
```

图片 URL 是短期读取地址，不保存进业务数据。未登录、成员失效、资源不可用或签名失败时使用前端降级图标。

历史账单不保存图标快照，详情查询通过当前分类元数据返回当前图标。停用分类仍保留元数据和历史关联，只有实际资源被清理时才使用降级图标。

## 9. 并发、幂等与测试

- 上传会话使用 `[ledgerId, clientRequestId]` 唯一约束，重复请求返回已有会话或已完成资源。
- 分类绑定使用条件更新，防止两个 Owner 请求同时把不同图片绑定到同一分类。
- 旧图片清理任务必须检查资源仍未被当前分类引用后再删除对象。
- 图标来源字段由服务端组合校验，不依赖数据库允许任意非法组合。
- 分类查询和统计查询必须过滤其他账本的资源，读取地址必须重新校验活跃成员。

测试至少覆盖：

- 默认分类稳定键和历史分类补齐；
- `NONE/LIBRARY/IMAGE` 字段互斥校验；
- 非法图标库键、跨账本资源和非 `ATTACHED` 资源绑定失败；
- MIME 文件头、大小上限和对象不存在；
- 上传会话幂等、未绑定资源清理和旧资源替换；
- Owner/Editor/Viewer 权限；
- 共享成员读取相同图标、成员移除后不再签发读取地址；
- 统计响应与分类查询使用相同图标字段。

## 10. 实施顺序

1. 固化 Tabler 白名单、默认分类 `defaultKey` 和图标映射；
2. 增加 Prisma 枚举、分类字段、资源模型和 Migration；
3. 实现资源上传会话、完成确认、读取地址和清理任务；
4. 改造分类创建、编辑、恢复默认和查询响应；
5. 改造统计分类响应；
6. 完成 MinIO/OSS 直传、CORS、私有读和清理验证；
7. 再接入前端分类图标和统计图表交互。
