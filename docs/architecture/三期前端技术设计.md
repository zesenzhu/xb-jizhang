# 三期前端技术设计

## 1. 文档目的与范围

本文定义三期四项需求在前端的实现边界、模块落点、数据流、失败恢复与验证方式，作为前端开发和联调依据。产品规则以《三期记账体验与共享协作需求》为准；服务端契约以《三期后端技术评估》和最终 DTO 为准，本文只引用不重定义。

邀请、备注候选与时间校验的契约已写入 `docs/api/账本与成员接口.md` 和 `docs/api/账单接口.md`，后端按契约实现中。前端按契约开发，把接口差异收敛在 `lib/api/*` 适配层；字段以 DTO 和 Swagger 为最终依据。

覆盖范围：邀请流程、备注快捷候选、键盘覆盖与编辑条、日期时间弹窗，以及配套缓存、类型、测试与拆分。图片附件本期不做，仅保留后续设计引用。

## 3. 总体设计

### 3.1 原则

1. **后端未定则先隔离**：待定契约收口在 `lib/api/*` 的类型与适配函数，组件不拼路径。
2. **契约优先、差异收敛**：前端按已冻结的 API 文档开发；确实未实现的能力由适配层降级到现有可用路径，并在界面说明，不在组件里判断接口是否存在。
3. **失败可恢复**：邀请和时间选择失败都保留已输入内容，并给出下一步。
4. **单一事实源**：缓存键、输入字号、安全区写法、账本时区复用既有模块。
5. **覆盖而非挤压**：系统键盘覆盖在面板之上，不改变面板布局；需要可达的编辑内容浮到键盘上方。

## 4. 邀请流程

### 4.1 断点复述

`UserAuthBoundary` 跳登录时只传 `pathname`，`?token=` 丢失；`GET /invitations` 不返回 token，列表条目无可执行动作；接受接口只认 token。三者叠加，用户“看得到邀请但无法响应”。

### 4.2 回跳参数承载

`routes.ts` 扩展：

```ts
/** 允许随回跳携带的查询参数白名单：只放行明确需要的键。 */
const REDIRECT_QUERY_ALLOWLIST: Record<string, readonly string[]> = {
  '/user/invitations': ['token', 'action'],
};

export function getSafeRedirectTarget(
  target: string | null | undefined,
  kind: AuthKind,
): string; // 签名不变：内部解析 pathname + search 后重新拼装

export function getLoginRedirectUrl(kind: AuthKind, pathname: string, search?: string): string;
```

规则：

1. 先按现有规则校验路径（`/` 开头、非 `//`、无 `\`、无 `/../`、同域前缀）。
2. 按 `pathname` 查白名单过滤查询参数，逐个解码后重新编码，未知参数丢弃。
3. 拼装结果整体作为 `redirect` 参数编码进登录地址。
4. `getSafeRedirectTarget` 返回前重复执行 1–3，防止手工构造的 `redirect` 绕过白名单。

调用侧：

- `UserAuthBoundary` 在 effect 内读取 `window.location.search`（不使用 `useSearchParams`，避免为布局新增 Suspense 边界与静态渲染分支）。
- `user-client.ts` 的 `handleUserRefreshFailure` 改用同一函数，两处行为一致。
- 登录/注册成功仍走 `router.replace(redirectTarget)`。

### 4.3 邀请页状态

页面状态由 `GET /api/invitations/token` 的 `blockedReason` 直接决定，不再靠错误文案猜测：

| 接口返回 | 页面状态 | 界面 |
| --- | --- | --- |
| 无 token | `list` | 我的邀请列表；条目可直接响应 |
| `blockedReason = null` | `ready` | 邀请说明卡（账本名、邀请人、角色、到期）+ 接受 + 拒绝 |
| mutation pending | `submitting` | 按钮 loading，禁止重复提交 |
| 接受成功 | `accepted` | 成功态 + 进入账本；`alreadyMember=true` 显示“已在该账本” |
| 拒绝成功 | `declined` | 成功态，刷新列表 |
| `EMAIL_REQUIRED` | `need-email` | 说明 + 去补全邮箱（携带回跳） |
| `EMAIL_MISMATCH` | `email-mismatch` | 展示脱敏目标邮箱 + 去更换邮箱 |
| `ALREADY_MEMBER` | `already-member` | 显示“已加入”并直达账本 |
| `EXPIRED` / `REVOKED` / `DECLINED` / `ACCEPTED` | `terminal` | 终态文案 + 返回账本入口，不显示接受 |
| `LEDGER_UNAVAILABLE` | `terminal` | 账本不可用 |
| 请求失败 | `failed` | 错误条 + 重试，保留 token |
| `canAccept=false` 且以上均不匹配 | `blocked` | 通用不可响应说明 |

纯函数 `resolveInvitationState(detail, mutation)` 只做映射，不发请求，便于单测。

只有 `blockedReason = null` 且 `canAccept` 为真时才渲染主按钮；执行接受/拒绝时若仍返回 `40031`/`40331`（例如邮箱在页面停留期间被清空），按动作级错误就地提示并重新拉取详情，不退化成终态。

### 4.4 接口与适配层

| 场景 | 接口 | 认证 |
| --- | --- | --- |
| 登录前查看邀请 | `GET /api/invitations/preview?token=` | 公开 |
| 登录后恢复邀请上下文 | `GET /api/invitations/token?token=` | 登录 |
| 就地接受 | `POST /api/invitations/:invitationId/accept` | 登录 |
| 就地拒绝 | `POST /api/invitations/:invitationId/decline` | 登录 |
| 列表 | `GET /api/invitations` | 登录 |
| 兼容旧链接 | `POST /api/invitations/accept`、`POST /api/invitations/decline`（body 带 token） | 登录 |

适配层集中在 `lib/api/invitation-api.ts`，组件不拼路径：

```ts
export interface InvitationPreview {
  ledgerName: string;
  inviterName: string;
  role: InvitationRole;
  status: InvitationStatus;
  expiresAt: string;
  canRespondAfterLogin: boolean;
}

export interface InvitationTokenDetail {
  id: string;
  ledger: InvitationLedgerRef;
  inviter: { id: string; nickname: string | null; avatar: string | null };
  role: InvitationRole;
  status: InvitationStatus;
  createdAt: string;
  expiresAt: string;
  targetEmailMasked: string;
  hasEmail: boolean;
  emailMatched: boolean;
  canAccept: boolean;
  canDecline: boolean;
  blockedReason: InvitationBlockedReason | null;
}

export function getInvitationPreview(token: string): Promise<InvitationPreview>;
export function getInvitationDetail(token: string): Promise<InvitationTokenDetail>;
export function acceptInvitationById(invitationId: string): Promise<AcceptedInvitationResult>;
export function declineInvitationById(invitationId: string): Promise<null>;
```

- 新页面统一走“详情/列表 → 按 ID 响应”；仅当详情接口不可用时，才回退到带 token 的兼容接口，回退分支集中在适配层，不在组件里分叉。
- 列表项来自 `GET /api/invitations`，包含 `inviter` 公开资料，可直接调用按 ID 响应接口，不需要 token。
- 接受返回值包含 `alreadyMember`：为真时不重复提示“加入成功”，直接进入账本并说明已在该账本。

### 4.5 重复提交与缓存

- 邀请预览、详情、列表的响应均为 `Cache-Control: no-store`，前端不写入持久缓存，TanStack Query 用 `staleTime: 0`。
- 同一邀请在同一页面只允许一个进行中 mutation。
- 成功后失效：`['user','invitations']`、`['ledgers']`、`['ledgers','preferences']`。
- 失败不清空列表，保留筛选与滚动位置。

### 4.6 安全约束

- token 只出现在地址栏与请求体；不写入 `console`、错误上报、页面 `title` 与分享文案。
- 成功后 `router.replace` 清掉带 token 的地址，避免历史记录中再次打开。

## 5. 图片附件：本期不做

图片附件与对象存储移出三期范围。本期不新增附件上传、预览、队列、删除相关组件、类型、缓存键和测试；记账快捷条的“图片”入口继续保持禁用或隐藏。

已有的账单图片附件与对象存储专项设计仅作为后续方案保留，不进入本期实施拆分。后续立项时再评审上传顺序、存储选型和移动端弱网体验。

## 6. 备注快捷候选

### 6.1 数据来源

对齐后端：`GET /api/ledgers/:ledgerId/note-suggestions?limit=10`，`VIEWER` 及以上可读，返回：

```ts
export interface NoteSuggestion {
  text: string;
  lastUsedAt: string;
}
```

排序、去重、200 字过滤与“仅当前用户创建”的隐私规则由服务端保证；前端只做展示与截断。

降级方案（接口未就绪时）：从当前账本最近一页账单聚合非空备注。仅作过渡，代码注释标注删除条件，接口上线后立即移除，避免长期双口径。

### 6.2 纯函数与缓存

```ts
export function buildNoteSuggestions(
  input: readonly { text: string | null; lastUsedAt: string }[],
  limit = 10,
): string[];
```

规则：trim 后判空、按 trim 文本去重、保持传入顺序、截断 `limit`。

缓存键 `queryKeys.noteSuggestions(ledgerId) = ['ledger', ledgerId, 'notes', 'suggestions']`，`staleTime` 30s；账单创建/编辑/删除成功后失效。

### 6.3 交互

- 位置：系统键盘态下停靠在键盘上方（见 7.6）；数字键盘态下不占用空间。
- 点击候选填入备注并聚焦输入框，光标置末尾，不自动提交。
- 中文输入法组合期间不触发筛选或截断。
- 无候选时不渲染占位块。

## 7. 键盘与可视区

### 7.1 结论先行

按产品确认的口径，采用 **overlay（覆盖）模型**，不是 resize（顶起）模型：

1. 系统键盘弹出**不改变**记账面板高度，也不把面板整体上推。
2. 自定义数字键盘**不隐藏、不卸载、不重排**，保持原位被系统键盘覆盖即可。
3. 编辑商家/备注时，一个**编辑条动态浮现在系统键盘正上方**，承载输入框、历史备注候选与必要的保存操作。
4. 键盘收起后编辑条消失，值已实时写回表单，不依赖“关闭时提交”。

### 7.2 根因

1. 输入框字号 12px，iOS 在聚焦小于 16px 的控件时强制放大页面。
2. 面板以 `100dvh` 呈现，键盘弹出后底部的金额卡与数字键盘被覆盖；若改为跟随 `visualViewport` 收缩，则变成“整体顶起”，与期望相反。
3. 底部固定区被覆盖后，被遮挡的输入与提交按钮不可达，用户只能先收起键盘。
4. `interactive-widget` 未声明，Android Chrome 可能选择 resize 模式，导致布局视口被压缩。

### 7.3 视口 Hook

```ts
export interface ViewportMetrics {
  /** 可视视口高度（px） */
  height: number;
  /** 可视视口相对布局视口的偏移（iOS 被系统滚动时非 0） */
  offsetTop: number;
  /** 键盘在布局视口底部占用的高度，已钳制为 >= 0 */
  keyboardInset: number;
  isKeyboardOpen: boolean;
}

export function useVisualViewport(): ViewportMetrics;
```

`keyboardInset` 计算（单位 px，均取整数）：

```ts
keyboardInset = Math.max(0, window.innerHeight - metrics.offsetTop - metrics.height);
```

- 监听 `visualViewport` 的 `resize` 与 `scroll`，`requestAnimationFrame` 合并同帧回调。
- `keyboardInset > 120` 视为键盘打开，避免地址栏收起造成误判。
- 不支持 `visualViewport` 时 `keyboardInset` 恒为 0、`isKeyboardOpen` 恒为 `false`，编辑条退回“贴在面板底部”的降级位置。
- 卸载时移除监听并取消挂起 rAF。

### 7.4 面板高度保持不动

- `BottomSheet` 的 `variant="full"` 继续使用 `h-[calc(100dvh-1.5rem)]`，**不**绑定 `visualViewport`，也不因键盘开合重算。
- 在 `app/layout.tsx` 的 `viewport` 显式声明 `interactiveWidget: 'resizes-visual'`，避免 Android Chrome 使用 resize 模式压缩布局视口。
- 面板打开期间保持 `body` 滚动锁；不调用 `window.scrollTo` 或 `scrollIntoView` 于面板外层，防止系统接管页面滚动后固定定位漂移。

### 7.5 编辑条（NoteComposerDock）

```ts
export interface NoteComposerDockProps {
  open: boolean;
  field: 'title' | 'note';
  title: string;
  note: string;
  suggestions: readonly string[];
  canSubmit: boolean;
  onChange: (patch: { title?: string; note?: string }) => void;
  onClose: () => void;
  onSubmitBill: () => void;
}
```

- 以 `position: fixed` 挂载到 `body`，`bottom: keyboardInset`，左右与面板同宽（`max-w-md`），层级 `z-[65]`（高于面板 `z-50`、嵌套面板 `z-[60]`，低于时间弹窗 `z-[70]`）。
- 结构自上而下：字段标题（商家/备注）+ 输入框 + 历史备注候选 chips + 「完成」。金额合法时额外提供「保存账单」，避免数字键盘的提交键被覆盖后无法保存。
- 输入框 `autoFocus`、`enterKeyHint="done"`、16px 字号；备注为 2 行可伸至 4 行，超出内部滚动。
- 输入即写回表单（`onChange`），不做“关闭时提交”，防止误触收起导致内容丢失。
- 「完成」= 收起键盘并关闭编辑条；`Esc` 与点击面板空白区域同效。
- 打开编辑条前若已有其它焦点，先 `blur` 再聚焦，避免 iOS 连续两次弹键盘造成闪烁。

### 7.6 为什么不用“隐藏数字键盘 + 面板增高”

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 隐藏数字键盘、面板跟随可视区增高 | 面板整体上移，触控位置漂移，退出编辑后还要恢复高度 | 不采用（与期望相反） |
| 数字键盘保持原位、被系统键盘覆盖 + 编辑条浮于键盘上方 | 面板稳定不动，只增加一层编辑条 | **采用** |

overlay 模型下不需要焦点状态机：数字键盘始终挂载，编辑条只由“是否在编辑文本字段”决定开关，减少状态同步与重挂载风险。

### 7.7 字号与 iOS 放大

- 编辑条输入与面板内可聚焦输入统一 16px（`text-base`，允许 `tracking-tight` 微调观感，禁止 `transform: scale` 伪装小字号）。
- `globals.css` 增加护栏：`@media (max-width: 768px) { input, textarea, select { font-size: 16px } }`。
- 不通过 `user-scalable=no` 禁止系统缩放；`viewport` 保持 `width=device-width, initial-scale=1`。
- 源码契约测试锁定护栏存在，防止后续新增控件回退。

### 7.8 候选栏

- 位于编辑条内部、输入框下方、键盘上缘之上，横向可滚动。
- 点击候选填入备注并把光标置于末尾；中文输入法组合期间不触发筛选或截断。
- 无候选时不渲染占位块；候选行高度固定，避免出现/消失造成编辑条跳动。

## 8. 日期时间选择（独立弹窗）

### 8.1 结论

按产品确认，日期时间使用**独立弹出层**，不与记账面板底部合体，也不使用底部面板形态：用户点击时间胶囊后，面板上方弹出一个居中对话框，选择日期与时间后确认写回。

### 8.2 方案对比

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 原生 `datetime-local` + `showPicker()` | 零依赖 | 遮挡与一致性不可控、易与键盘叠加 | 仅保留兜底 |
| 底部面板内嵌滚轮 | 与面板同源 | 用户明确否决；与键盘覆盖区争夺底部空间 | 不采用 |
| **居中弹窗（日历 + 时间列）** | 与底部布局解耦、不受键盘影响、视觉聚焦 | 需自建交互与无障碍 | **采用** |
| 第三方日历库 | 桌面日历成熟 | 体积、样式改造、移动端仍需二次适配 | 暂不引入 |

### 8.3 组件契约

```ts
export interface DateTimePickerDialogProps {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  /** 账本时区下的本地时间文本 YYYY-MM-DDTHH:mm */
  value: string;
  /** 账本时区（IANA），默认取当前账本，缺省回退 LEDGER_TIME_ZONE */
  timeZone?: string;
  onConfirm: (nextLocalValue: string) => void;
  /** 允许的最大时间，用于禁止未来时间 */
  maxLocalValue?: string;
  minuteStep?: 1 | 5 | 10;
}
```

### 8.4 打开与关闭顺序

1. 点击时间胶囊 → 先把当前焦点 `blur()`，收起系统键盘。
2. 同一手势内打开弹窗（`open` 置真），弹窗挂载到 `body`，层级 `z-[70]`（高于面板 `z-50`、嵌套面板 `z-[60]`）。
3. 弹窗以 `position: fixed; inset: 0` 铺满布局视口，内部 `max-h-[80dvh]` + 内容滚动，底部 `env(safe-area-inset-bottom)`。
4. 取消或遮罩点击 → 关闭且不写回；确认 → 校验后写回并关闭。
5. 关闭后焦点回到时间胶囊，避免焦点丢失到 `body`。

键盘动画未结束时弹窗可能短暂与键盘同屏，属可接受过渡；不为此延迟渲染，避免点击后无反馈。

### 8.5 结构

```text
┌──────────────────────────────┐
│ 选择时间                   ✕ │
│ 2026年11月8日 周六 18:05      │  ← 实时摘要（aria-live）
│ ‹  2026年11月  ›              │  ← 月份切换
│ 日 一 二 三 四 五 六          │
│         … 日历格 …            │  ← 未来日期禁用
│ 时  [18]   分  [05]           │  ← 两列滚轮，snap
│ 取消              确认        │
└──────────────────────────────┘
```

- 日期格最小 36×36px，选中态与今日态可区分且不只靠颜色。
- 时/分两列滚动列表，`minuteStep` 控制步进，默认 5 分钟；列表高亮随选择滚动吸附。
- 未来时间在 `maxLocalValue` 外禁用并说明，与现有“不能记未来的账”规则一致。

### 8.6 纯函数与时区

集中在 `lib/bill/datetime-picker.ts`，全部单测：

- `splitLocalDateTime(value)`、`composeLocalDateTime(date, time)`：非法值返回 `null`。
- `daysInMonth(year, month)`、`addMonths`、`addDays`、`clampToMax`、`snapMinute`。
- `toOccurredAtIso(localValue, timeZone)`：按账本时区换算为带偏移的 instant，复用 `lib/bill/timezone.ts`。

**同时修正既有缺陷**：`BillFormBody.toLocalInputValue` 使用设备本地时区（`getFullYear/getHours`），当设备时区与账本时区不一致时显示与落库偏差。改为按账本时区格式化，并让 `handleTimeChange` 走 `toOccurredAtIso`，保证提交值始终是带偏移的 ISO 字符串（后端要求，非法值返回 `40021`）。

### 8.7 无障碍

- `role="dialog"` + `aria-modal="true"`，标题通过 `aria-labelledby` 关联，打开时焦点进入弹窗。
- 日历格 `role="gridcell"`，可用方向键移动、`Enter` 选择；时/分列 `role="listbox"` + `aria-label`。
- `Esc` 关闭，`Tab` 循环限制在弹窗内，关闭后焦点归还触发元素。

## 11. 错误与文案

沿用 `ApiRequestError`（`code`/`status`/`message`）与现有映射习惯，新增：

| 场景 | 前端表现 |
| --- | --- |
| 邀请不存在或 Token 无效（`40431`） | 终态卡 + 返回账本入口 |
| 邀请已过期/撤销/拒绝/已接受（`40931`） | 按 `data.status` 显示终态，不显示接受 |
| 账号未填邮箱（`40031`，`action=SET_EMAIL`） | 引导补全邮箱，带回跳 |
| 邮箱不匹配（`40331`，`action=CHANGE_EMAIL`） | 展示 `targetEmailMasked` + 去更换邮箱 |
| 已是活跃成员（接受返回 `alreadyMember=true`） | 提示已加入并直接进入账本 |
| 限流（`42901`） | 提示稍后重试，保留表单内容 |
| 时间非法/未来（`40021` 或本地校验） | 弹窗内联提示，确认禁用 |

文案统一走中文常量，避免同一错误在多页面出现两套说法。

## 14. 风险与未决

1. **iOS 固定定位与页面滚动**：键盘弹出时若系统滚动页面，`position: fixed` 元素会漂移。方案已用 `offsetTop` 补偿，仍须在 iOS 真机验证编辑条是否始终贴住键盘上缘。
2. **弹窗与键盘的过渡**：iOS 键盘收起有动画，弹窗可能短暂与键盘同屏。可接受，但需确认视觉上不出现“误点到键盘区域”。
3. **iOS 视口抖动**：`visualViewport` 在键盘动画期间高度连续变化，`scrollIntoView` 时机需实测；必要时按开合状态而非像素差判断。
4. **截图缺失**：图一至图三未提供，编辑条与弹窗的具体视觉以本文描述为准，评审后可能微调。
5. **降级方案移除条件**：邀请列表只读、备注客户端聚合两处降级必须有明确下线时间点，否则形成双口径。
