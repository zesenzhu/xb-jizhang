# 小宝记账项目文档索引

## 文档目的

`docs/` 是产品需求、技术方案、接口契约、UI 交互和开发计划的统一维护入口。文档描述必须与代码、测试和部署配置保持一致；当规则发生变化时，先更新对应文档，再修改实现。

## 推荐阅读顺序

1. 先阅读产品需求，确认目标、范围和验收标准。
2. 再阅读领域需求，确认用户、账本、成员和账单规则。
3. 然后阅读总体架构、后端、前端和数据模型文档。
4. 联调时阅读对应领域的 API 文档，接口字段以 DTO 和 Swagger 为最终技术契约。
5. 开发任务执行前阅读 `superpowers/plans/` 中对应的实施计划。

## 文档状态

- `draft`：正在整理，不能作为唯一实现依据。
- `review`：等待需求或技术评审。
- `approved`：已确认，可以作为实现依据。
- `implemented`：对应规则已落地并完成验证。
- `deprecated`：历史文档，仅用于追溯，不再指导新实现。

## 维护规则

- 需求文档描述业务目标和规则，不绑定具体代码结构。
- API 文档按业务领域维护，字段细节与 DTO、Swagger 保持一致。
- 技术决策发生争议时，新增 ADR 记录背景、选项、结论和后果。
- 变更完成后检查相关文档的 `related` 链接、状态、版本和验收标准。
- 文档中的未决内容集中写在“未决问题”，不能用模糊措辞伪装成已确定方案。
