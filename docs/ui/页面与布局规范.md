# 小宝记账页面与布局规范

## 1. 文档定位

本文档定义普通用户端和平台管理端的页面结构、响应式布局、公共状态、权限差异和移动端交互要求。它不替代视觉设计稿，也不定义具体 API 字段。

## 2. 两端视觉和交互定位

| 端 | 主要设备 | 布局方向 | 组件方向 | 核心目标 |
| --- | --- | --- | --- | --- |
| 普通用户端 | 手机优先，兼容桌面 | 顶部栏 + 底部导航；宽屏扩展 Sidebar | Tailwind + 通用基础组件 | 快速记一笔、清楚反馈同步状态 |
| 平台管理端 | 桌面优先，兼容窄屏 | Sidebar + Header + 内容区；窄屏 Drawer | 表格、筛选、抽屉和高风险确认 | 高效治理、权限清晰、操作可审计 |

两端可以共享 Button、Input、Dialog、Badge、EmptyState 等无业务权限的基础组件，但不能共享完整导航、Layout 或身份 Provider。

## 3. 普通用户端 Layout

### 3.1 移动端

```text
┌────────────────────────────┐
│ 当前账本   网络/同步   用户 │  顶部栏
├────────────────────────────┤
│                            │
│        页面主体内容         │
│                            │
│                      记一笔 │  浮动操作
├────────────────────────────┤
│ 首页  账单  统计  账本/设置  │  底部导航
└────────────────────────────┘
```

要求：

- 底部导航避开安全区，适配刘海屏和手势区域；
- “记一笔”在首页和账单页保持可见，但不能遮挡输入框和底部导航；
- 金额输入优先使用移动端数字键盘，金额和提交结果必须有稳定的视觉反馈；
- 当前账本切换和同步状态在顶部可见，不只依赖颜色；
- 侧滑、弹层和返回操作不能破坏表单草稿；
- 横屏或窄屏下账单内容允许滚动，但主要操作不能被横向表格挤出屏幕。

### 3.2 桌面端

```text
┌────────────┬──────────────────────────────┐
│ 账本与导航  │ 顶部栏：当前账本 / 状态 / 用户 │
│            ├──────────────────────────────┤
│            │ 页面主体                       │
│            │                                │
└────────────┴──────────────────────────────┘
```

桌面端可以显示 Sidebar、快捷统计和多列表格，但快速记账仍然保持单一主入口，不因为宽屏增加不必要步骤。

## 4. 管理端 Layout

### 4.1 桌面端

```text
┌────────────┬──────────────────────────────┐
│ 管理端 Logo │ Header：面包屑 / 管理员 / 退出 │
│ 仪表盘      ├──────────────────────────────┤
│ 用户管理    │ 筛选区                         │
│ 账本治理    │ 表格或详情                     │
│ 审计日志    │ 分页、状态和操作反馈           │
└────────────┴──────────────────────────────┘
```

要求：

- 菜单按权限码过滤，隐藏菜单不替代后端权限校验；
- 列表页统一提供加载、空数据、错误、筛选中和分页状态；
- 高风险操作必须使用明确的确认弹窗，展示目标、影响、操作原因输入和最终结果；
- 敏感字段默认脱敏，查看完整值必须有独立权限并记录审计；
- 操作失败不能只显示短暂 Toast，页面需要保留可理解的错误状态。

### 4.2 窄屏管理端

- Sidebar 改为 Drawer，打开后不锁死返回操作；
- 表格优先转为卡片或允许横向滚动，关键状态和操作保持可见；
- 筛选条件折叠到“筛选”面板，已生效条件以标签展示；
- 高风险确认内容按纵向布局排列，原因输入框保持足够高度；
- 不引入普通用户端底部导航，避免两个身份域的交互混淆。

## 5. 页面状态规范

所有依赖服务端数据的页面至少覆盖：

| 状态 | 页面表现 |
| --- | --- |
| 首次加载 | 页面骨架或明确加载指示，不显示伪造数据 |
| 空数据 | 说明当前范围没有数据，并提供下一步操作 |
| 请求失败 | 展示原因、重试入口和不丢失的用户输入 |
| 无权限 | 说明当前角色不能操作；不展示敏感数据 |
| 网络离线 | 显示离线标识；仅允许文档定义的离线操作 |
| 待同步 | 展示数量和同步入口，不标记为已入账 |
| 同步冲突 | 保留本地输入和服务端版本，提供处理入口 |
| 保存成功 | 显示服务端确认结果并刷新相关汇总 |

错误、离线和同步状态不能只通过颜色表达，必须同时有文字、图标或可访问性标签。

## 6. 普通用户页面约定

### 6.1 `/user`

- 页面目标：显示当前账本的月度概览、最近账单和“记一笔”入口；
- 无账本：显示创建或接受邀请的引导；
- 无账户/分类：显示创建基础数据的引导，但不阻塞已允许的流程；
- 权限差异：`VIEWER` 隐藏记账写入口，服务端拒绝仍需正确展示；
- 离线态：允许读取缓存概览，明确标注数据可能不是最新。

### 6.2 `/user/ledger`

- 页面目标：列出当前用户可访问的账本并切换工作区；
- 切换成功：更新 URL、工作区状态和相关服务端查询缓存；
- 账本不可访问：清理当前账本状态并提示成员关系已失效；
- 空状态：提供创建个人/共享账本或处理邀请入口。

### 6.3 `/user/ledger/[ledgerId]/transactions`

- 页面目标：按月份、类型、分类、账户和成员筛选账单；
- 列表使用分页和服务端筛选，不能依赖一次性加载全部账单；
- 删除是软删除，成功后刷新列表和统计；
- `VIEWER` 只能查看，`EDITOR` 可新增/编辑，删除等高风险动作遵循后端权限；
- 移动端优先显示金额、类型、分类、时间和同步状态，详情使用抽屉或页面。

### 6.4 `/user/ledger/[ledgerId]/transactions/new`

- 页面目标：快速新增收入或支出；
- 必填信息：类型、金额、分类、账户；时间默认当前时间；
- 在线保存必须等待服务端确认；离线保存标记为待同步，不伪造为已入账；
- 重复点击和网络重试使用 `clientRequestId`，界面只能产生一个明确的同步结果；
- 表单校验失败时保留用户已填写内容。

### 6.5 `/user/ledger/[ledgerId]/members`

- 页面目标：查看成员、发起邀请和处理角色协作；
- `OWNER` 可看到管理入口，`EDITOR`/`VIEWER` 只看到允许的成员信息；
- 邀请 Token、邮箱和成员历史状态遵循后端接口的脱敏和权限规则；
- 成员被移除或退出后，页面下一次请求必须表现为无权限或资源不可用。

## 7. 管理端页面约定

### 7.1 `/admin`

- 页面目标：显示用户数、账本数、近期状态变化和待处理运营事项；
- 数据只显示管理员权限允许的摘要；
- 加载失败时不能展示旧用户或旧账本的敏感数据作为占位；
- 管理员没有某项权限时，相关卡片不展示或展示无权限状态。

### 7.2 `/admin/users`

- 页面目标：分页查询普通用户并执行允许的账号状态操作；
- 默认显示脱敏邮箱和基础状态；
- 禁用/恢复账号需要原因、确认和结果反馈；
- 成功后刷新用户列表，失败后保留筛选条件和分页位置。

### 7.3 `/admin/ledgers`

- 页面目标：平台范围查看账本摘要和归档状态；
- 不使用普通用户的当前账本上下文；
- 归档/恢复需要原因、并发字段和审计结果；
- 默认不展示账单正文和成员隐私字段。

### 7.4 `/admin/audit-logs`

- 页面目标：查询管理员操作审计记录；
- 支持按管理员、动作、资源、结果、请求 ID 和时间筛选；
- Token、密码、密钥和未脱敏敏感数据永不展示；
- 审计查询失败需要明确重试，不清空已设置的筛选条件。

## 8. 可访问性与反馈

- 交互控件必须有可见文本或可访问名称；
- 键盘用户能够访问导航、筛选、弹窗和表单提交；
- Toast 只作为补充，关键错误和保存结果必须在页面结构中保留；
- 加载、离线、同步和权限状态提供文本，不依赖颜色单独表达；
- 弹窗打开后焦点进入弹窗，关闭后返回触发控件；
- 移动端触控目标保持足够间距，避免金额键盘误触。

## 9. 组件边界

```text
components/
├── ui/                 Button、Input、Dialog、Badge 等无业务组件
├── common/             AmountDisplay、EmptyState、ErrorState 等跨端组件
├── user/               用户端账本、账单、成员和设置组件
├── admin/              管理端筛选、脱敏、高风险确认和审计组件
└── mobile/             普通用户端金额键盘、底部导航、同步提示
```

`AmountKeypad`、`MobileBottomNav` 和 `SyncStatusBar` 属于普通用户端移动组件；`MaskedField`、`HighRiskActionDialog` 和 `TableFilterBar` 属于管理端组件。任何组件跨端复用前必须确认没有身份、权限或数据域耦合。

## 10. UI 测试要求

- 普通端：覆盖移动底部导航、账本切换、快速记账表单、空状态、离线和待同步反馈；
- 管理端：覆盖菜单权限过滤、窄屏 Drawer、筛选、脱敏展示和高风险操作确认；
- 组件测试优先使用可访问角色、标签和文本，不依赖 CSS class 或内部 DOM；
- 认证和跨路由流程使用 E2E，组件测试不伪造 Next.js Server Component 的完整运行环境。

## 11. 未决问题

1. 管理端第一期是否同时提供移动端完整操作，当前先保证桌面可用和窄屏可访问。
2. 普通用户首页是否允许自定义底部导航顺序，当前固定为首页、账单、统计、账本/设置。
3. 管理端视觉主题和品牌色是否独立于普通用户端，当前只规定 Layout 和交互边界。
