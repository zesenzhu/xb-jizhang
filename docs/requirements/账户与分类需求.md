# 小宝记账账户与分类需求

## 1. 文档范围

本文档定义账本账户和收支分类的业务规则。账户、分类均属于账本资源，所有访问必须经过当前用户的活跃成员关系校验。

本文档不定义账单写入、统计和离线同步的具体接口；账单如何引用账户和分类见[账单需求](./账单需求.md)。

## 2. 账户需求

### 2.1 账户用途

账户用于表达资金存放或支付来源，例如现金、银行卡、支付宝和微信。每个账户属于一个账本，账户余额使用整数分保存。

账户字段包含：

- 账户名称；
- 受控类型：`CASH`、`BANK_CARD`、`CREDIT_CARD`、`ALIPAY`、`WECHAT`、`OTHER`；
- 共享或私人可见性；
- 初始余额和当前余额；
- 是否计入资产；
- 图标、颜色和启用状态。

### 2.2 共享账户和私人账户

- `SHARED` 账户对账本全部活跃成员可见并可用于记账。
- `PRIVATE` 账户只对 `ownerId` 对应的成员可见并可用于记账。
- 共享账户只能由 `OWNER` 创建、编辑和停用，`EDITOR` 和 `VIEWER` 可以读取并在允许时使用。
- `EDITOR` 可以创建、编辑和停用自己拥有的私人账户；不能修改其他人的私人账户。
- `VIEWER` 不能创建、编辑或停用账户。
- 账户 ID、`ownerId` 和 `visibility` 不能绕过服务端的账本归属和可见性校验。

### 2.3 账户生命周期

- 新增账户的 `initialBalanceCents` 默认是 `0`，创建后初始余额计入当前余额。
- 账户停用使用软状态，不删除历史账单和余额变化记录。
- 停用账户不能用于新增账单，但历史账单仍可查询和展示。
- 已被账单引用的账户不能物理删除。
- `OWNER` 可以查询当前账本的停用账户；`EDITOR` 只能查询自己拥有的停用私人账户，`VIEWER` 不能查询停用账户。
- 账户重新启用需要满足当前操作者的账户管理权限，私人账户所有者可以重新启用自己的账户。

## 3. 分类需求

### 3.1 分类用途

分类用于区分收入和支出的业务用途，例如餐饮、交通、工资和房租。分类只属于账本，不属于某个用户。

分类必须包含：

- `EXPENSE` 或 `INCOME` 类型；
- 名称；
- 排序值；
- 图标、颜色和启用状态；
- 是否为系统默认分类。

### 3.2 分类权限

- 所有活跃成员可以读取当前账本的启用分类。
- 只有 `OWNER` 可以新增、编辑、排序、停用和重新启用分类。
- `EDITOR` 和 `VIEWER` 不能修改分类，但可以在允许的账单操作中选择分类。
- 分类名称在同一账本、同一类型下不能重复，收入和支出可以分别使用同名分类。

### 3.3 分类生命周期

- 创建个人账本或共享账本时，系统在同一事务中写入一期默认收入和支出分类。
- 当前默认分类使用《一期账本与记账需求》第 9.2 节的 16 个一级、49 个二级目录，并使用 `isSystem=true` 标记。
- 系统默认分类允许 Owner 修改展示名称、图标和排序，但不能被物理删除。
- 已被账单引用的分类只能停用，停用后不能用于新增账单，历史账单保留原分类。
- 默认列表只返回启用分类；管理操作可以通过明确参数读取停用分类。

## 4. 空状态和异常

- 无账户时，客户端显示创建账户引导，但不伪造账户余额。
- 无分类时，客户端显示创建分类引导；新增账单不能提交缺失分类的收入或支出。
- 访问其他账本或其他成员私人账户时，服务端返回资源不可用，不泄露资源是否存在。
- 账户或分类停用后，客户端刷新列表和快速记账表单，不能继续使用旧的启用状态。

## 5. 验收标准

- 给定活跃成员，当其读取账本账户和分类，则只返回当前账本且符合可见性和启用状态的数据。
- 给定 `EDITOR`，当其创建私人账户，则账户的 `ownerId` 必须是当前认证用户。
- 给定 `EDITOR`，当其修改共享账户或其他成员私人账户，则服务端拒绝操作。
- 给定 `VIEWER`，当其提交账户或分类写操作，则服务端拒绝且数据库无变化。
- 给定已被账单引用的账户或分类，当用户尝试物理删除，则服务端拒绝并要求停用。
- 给定同一账本同一分类类型下的重复名称，当用户创建分类，则服务端返回冲突。
- 给定账本首次创建，当事务成功，则账本存在默认收入和支出分类；任一步失败则整体回滚。

## 6. 未决问题

1. 默认分类名称和排序值已在一期后端实现中确定；后续如需调整，应通过版本化的数据迁移或初始化策略处理，不能依赖客户端硬编码 ID。
2. 信用卡负债余额是否允许为负数，需要在账户余额实现前确认；第一期账户金额仍使用整数分。

## 7. 实现状态

- 账户管理和分类管理后端接口已落地，分类模块已接入应用模块。
- 新建注册用户的默认个人账本，以及后续新建账本，都会在同一 Prisma 事务内创建 16 个一级和 49 个二级默认分类；事务失败时不保留半成品账本。
- 分类查询支持 `page`、`pageSize`、`type` 和 `includeInactive`；启用分类对所有活跃成员可见，停用分类查询仅允许 `OWNER`。
- 当前分类实现未提供物理删除接口，符合被账单引用资源只能停用的约束。
