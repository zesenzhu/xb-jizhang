# 小宝记账三期用户需求

## 1. 文档定位

本文档把第三期提出的五项体验与能力需求收敛为可评审、可验收的产品范围：共享账本邀请体验修复、账单图片附件、历史备注快捷选择、移动端键盘布局适配，以及日期时间选择体验优化。本文定义用户可见行为、规则和验收口径，不代替后续技术设计、API 契约或 UI 设计。

当前仓库已有邮箱目标邀请、邀请列表、接受/拒绝/撤销接口和成员恢复能力；第三期邀请工作以复现并修复端到端流程为主，不预设需要重写后端邀请模型。当前尚未提供用户提及的图一、图二、图三，因此涉及视觉对比的部分基于文字描述定义目标，评审时应补充截图确认。

## 2. 背景与问题

1. 共享账本目前通过一次性链接/Token 分享。受邀者打开链接后登录，登录完成未能顺畅回到邀请处理流程，导致重复登录、邀请未被正确响应或用户不知道如何加入。
2. 账单缺少图片附件，用户无法保存票据、凭证或消费现场信息；图片需要可靠、可控且成本适合个人项目的存储方案。
3. 备注虽可输入，但没有历史复用入口，重复记账时需要反复输入相同内容。
4. 移动端原生键盘弹出时，页面可能整体上移或被浏览器缩放，金额、备注和保存操作容易错位；参考应用将备注快捷项放在键盘上方。
5. 当前日期时间选择控件遮挡内容或不适合移动端操作，需要更清晰、可预测的选择体验。

## 3. 目标与非目标

### 3.1 目标

- 邀请链接打开、登录/注册、查看邀请、接受/拒绝形成连续且可恢复的流程。
- 用户能为账单添加、查看和移除图片附件，并保障附件仅对有权访问账单的成员开放。
- 用户输入过的备注可在之后快速选择，并可继续编辑，不改变备注本身的账单语义。
- 键盘弹出时页面不发生非预期整体缩放或布局跳动；备注快捷项稳定处于输入区域/键盘上缘附近。
- 用户能在移动端可靠修改账单发生日期和时间，且弹层不遮挡关键内容。

### 3.2 非目标

- 本期不做 OCR、自动识别金额/商家、图片内容分析或票据报销工作流。
- 本期不做多人实时协同编辑、聊天式通知中心或推送通知系统；邀请通知仅覆盖应用内待处理邀请列表和入口提醒。
- 本期不建设通用文件网盘，不支持任意文件类型。
- 本期不重写账本成员角色、账单权限、金额计算和统计口径。
- 不在需求文档指定最终日期组件代码实现；组件选择在 UI/技术设计阶段验证后确认。

## 4. 用户与权限

- 账本 `OWNER`、`EDITOR` 可按现行账单权限新增或编辑账单及其附件；`VIEWER` 只能查看已有附件，不能新增、删除或编辑账单。
- 邀请发起权限沿用现行规则：只有账本 `OWNER` 能邀请、撤销邀请和管理成员。
- 邀请接收者必须登录；邮箱邀请必须由目标邮箱匹配的当前用户处理。不能因为用户已登录就绕过目标邮箱校验。
- 服务端对所有账单和附件操作重新校验账本成员状态、角色和附件归属。前端隐藏操作不是授权边界。

## 5. 功能范围与业务规则

### 5.1 共享账本邀请流程优化（P0）

#### 推荐方案

保留现有“指定邮箱 + 一次性 Token + 我的邀请列表”的安全模型，修复链接承接和登录回跳。邀请通知管理以应用内“我的邀请”为主入口；受邀用户通过邀请链接进入邀请详情，登录/注册后回到该邀请，而不是重新开始登录或丢失邀请上下文。账号/邮箱直接邀请可以作为现有邮箱邀请的发起方式，不另做联系人搜索或开放式用户名枚举。

邀请链接是进入邀请详情的导航凭据，不代表已加入账本。最终接受操作仍须登录、校验邮箱目标、检查邀请有效期/状态并由服务端原子消费。重复打开、重试和重复点击不得创建重复成员关系。

#### 流程要求

1. Owner 在共享账本成员页输入受邀邮箱、选择 `EDITOR` 或 `VIEWER` 并发起邀请；创建成功后可复制邀请链接，并可在邀请管理列表看到待处理、已接受、已拒绝、已过期或已撤销状态。
2. 受邀者打开链接后看到账本名称、邀请人、授予角色、有效期和明确的登录/注册或处理入口；不得在登录前暴露账单等账本内容。
3. 未登录用户登录或注册成功后回到原邀请详情。登录状态已有效时直接进入邀请详情，不重复要求登录。
4. 已登录用户可接受或拒绝；邮箱不匹配时说明需要切换/补全匹配邮箱，不消费邀请，不泄露其他用户资料。
5. 用户也可以从“我的邀请”查看所有当前账号可处理的邀请并执行接受/拒绝；处理结果和失败原因清晰可见。
6. 邀请失效、撤销或已处理时显示最终状态和可行的下一步，不提供继续加入的假成功反馈。
7. 接受成功后加入账本并切换/提供进入账本入口；拒绝成功后从待处理列表移出，但可按现行数据策略保留终态记录。

#### 邀请规则

- 继续遵循现行 72 小时有效期、Token 一次性消费、原始 Token 仅创建成功时返回、数据库仅存哈希及角色不能授予 `OWNER` 的规则。
- 同一账本和目标邮箱同时只能有一个有效待处理邀请。
- Owner 可撤销未处理邀请；撤销后旧链接立即不可用。
- 当前用户已经是该账本活跃成员时，接受邀请应提示已加入，不生成重复成员关系。
- 登录回跳参数只承载允许的站内邀请路由/短期邀请引用，不允许开放重定向；不得将访问/刷新 Token 写入 URL、日志或持久化明文。
- 登录完成但接受请求失败时保留可恢复的邀请入口；不能无限循环跳转。

### 5.2 账单图片附件与对象存储（P1）

#### 产品需求

- 收入、支出账单可添加多张图片，图片为可选信息；一期建议上限 5 张/笔，单张上限 10 MB，支持 JPEG、PNG、WebP，上传前展示缩略图并允许移除。
- 保存后的账单详情和列表可查看附件；点击图片可放大查看。删除账单、删除附件或失去账本访问权限后，用户不能继续通过旧地址读取图片。
- 上传失败、网络中断、格式不支持、超过大小限制时说明原因，保留账单其他字段和可重试状态；不能把未成功上传的附件显示为已保存。
- 同一张图片的重复请求不得产生重复关联；孤立上传对象应可被后台清理。
- 离线时允许先在当前设备暂存待上传图片与待同步账单，但本期不承诺跨设备可见或无限期本地保存。用户必须看到待上传状态；清理浏览器数据或设备损坏导致的未上传文件不保证恢复。

#### 存储方案分析与推荐

图片属于二进制对象，不建议直接存入 PostgreSQL，也不建议只存应用容器本地目录：前者会膨胀主库备份和恢复，后者在容器重建、扩容或迁移时容易丢失或难以共享。推荐“对象存储保存文件 + PostgreSQL 保存元数据和账单关联”的边界。

对个人自托管场景，建议以 S3 兼容对象存储为接口标准，首选评估 MinIO 自建单节点作为起步方案；文件存于独立持久化磁盘卷，元数据保存对象键、媒体类型、字节数、校验值、上传者、所属账单和时间。应用通过短期签名上传/下载地址或后端授权代理访问，不公开桶和永久可猜测地址。数据库仅保存对象键及必要元数据，不保存签名 URL。

MinIO 适合快速自建和未来迁移，但不等于自动备份或高可用：单机磁盘损坏会导致附件丢失，必须纳入独立备份、容量告警、恢复演练、HTTPS、访问密钥轮换和磁盘空间管理。若用户不愿承担对象存储运维，后续可切换到 S3/兼容云对象存储；本期数据模型和应用接口应避免依赖厂商私有能力。该选择属于推荐方向，正式落地前需核对部署资源、MinIO 版本/许可策略及异地备份预算。

#### 安全和隐私

- 文件访问必须同时校验当前用户对账本和账单的权限；不可仅凭对象 URL 是否难猜来保护。
- 服务端校验扩展名、声明类型、文件大小和实际文件内容；拒绝脚本、HTML、SVG 等可执行或易触发主动内容风险的格式。
- 上传对象使用随机不可预测键名；限制上传频率和总量，避免覆盖已有对象。
- 删除附件时先确保数据库关联不可见，再异步清理对象；清理失败可重试并记录状态。
- 日志不记录签名 URL、存储密钥或图片内容；加密传输，备份文件需受控。

### 5.3 历史备注快捷选择（P1）

- 保存账单时将备注作为账单数据持久化；备注为空时保存为空，不生成空快捷项。
- 记账表单的备注输入区提供最近使用的非空备注候选，优先按当前用户在当前账本中的最近使用时间排序；候选可横向滚动，不遮挡备注输入和金额/保存主操作。
- 点选候选后将其填入备注输入框，用户可以追加、修改或清空；选择候选本身不自动提交账单。
- 只有用户有权访问的当前账本中的已保存备注可作为候选，不能跨账本泄露共享账本内容；同一规范化文本去重，最多展示 10 条近期候选。
- 候选由已成功保存的账单生成；离线账单仅在本地可用，待同步成功后进入服务端候选。编辑或删除账单后，候选按现存有效账单重新计算或在近期缓存过期后消失。
- 快捷备注是历史文本复用，不增加独立“备注模板”管理、共享模板或备注分类能力。

### 5.4 原生键盘与记账页面布局（P0）

- 金额、备注等输入聚焦并弹出原生键盘时，页面不得因输入焦点自动放大；页面整体不得被不可逆挤压或造成主要表单字段、提交操作无法访问。
- 记账内容区在键盘弹出后可滚动到当前输入项；底部安全区、键盘可视区域和固定操作栏需协调，不能重复叠加遮挡。
- 备注输入聚焦时，备注快捷候选条显示在备注输入区附近、键盘上方可见区域；使用原生键盘时不得被键盘完全覆盖。候选条内容过多时可横向滑动。
- 键盘收起后页面恢复原布局和滚动位置，不残留错误高度或空白；输入中切换收入/支出、分类或日期时不丢失已填写内容。
- 兼容 iOS Safari/PWA 与 Android Chrome/PWA 的可视视口变化、软键盘弹出/收起及横竖屏；不要求阻止用户使用系统缩放辅助功能。
- 页面应避免依赖单一设备固定像素高度；发生时间选择或图片预览弹层打开时按可视区域布局。

### 5.5 日期时间选择体验优化（P1）

#### 选择器目标

- 用户可清楚查看并修改年、月、日、时、分；默认值仍为当前时间，取消不改变原值，确认后仅提交合法时间。
- 日期和时间选择不得被底部导航、键盘、安全区或屏幕边缘裁切；窄屏优先使用适合触控的底部面板/全屏面板，桌面端可使用日历弹层。
- 默认状态、用户已修改状态及确认/取消动作均明确可见；屏幕阅读器可读取控件名称，触控目标满足移动端可操作尺寸。
- 用户跨日修改时间后，发生时间、账单日期分组和统计月份按既有账本时区规则一致处理。

#### 组件选择建议

现有前端依赖为 Tailwind CSS 和项目自建基础 UI，当前依赖清单未显示已选的完整日期时间组件库。建议先评估成熟、可访问且支持受控输入的 React 日期选择器，并验证移动端弹层定位、时区处理、键盘输入兼容和许可维护情况；如果桌面日历与移动端原生体验冲突，可采用“桌面日历 + 移动端底部面板”的同一业务控件适配，而不是为了统一外观强行使用一个不适合移动端的弹出日历。

候选库须通过真实 iOS/Android 浏览器验证，覆盖时区/DST 边界、无障碍、维护活跃度、体积、React/Next 兼容性及样式可控性。未完成验证前不在需求层锁定具体库名；不建议未经验证直接将原生 `datetime-local` 作为唯一跨平台交互方案。

## 6. 优先级与建议阶段

| 优先级 | 范围 | 说明 |
| --- | --- | --- |
| P0 | 邀请流程端到端修复；键盘布局基础适配 | 当前存在阻断加入账本和移动记账的体验缺陷 |
| P1 | 历史备注候选；日期时间选择器优化；账单图片附件与对象存储 | 提升高频记账效率和凭证完整性，附件包含额外运维成本 |
| P2 | OCR、备注模板管理、邮件/推送通知、对象存储高可用 | 不纳入本期交付 |

建议实施顺序：先修复邀请与键盘这两个主流程问题；并行完成备注候选与日期选择器 UI 验证；对象存储先完成部署、备份恢复和权限设计，再开放附件上传，避免先上线不可备份的文件存储。

## 7. 页面与状态要求

### 7.1 成员与邀请管理

入口为共享账本成员管理页及全局“我的邀请”入口。必须覆盖加载中、无待处理邀请、待处理邀请、已接受/拒绝/过期/撤销、邮箱不匹配、登录失效、网络错误和接受冲突。网络失败时保留邀请上下文并提供重试；已处理邀请不显示可重复接受的主按钮。

### 7.2 记账表单

备注快捷候选属于备注输入体验的一部分。必须覆盖无历史备注、候选加载失败、键盘显示/隐藏、候选被选中、输入被修改、离线待同步、图片上传中/失败/成功等状态。表单滚动不能使金额、备注、发生时间等字段被永久遮挡。

### 7.3 图片查看

附件缩略图显示加载失败占位和重试入口；无权访问或签名地址过期时需重新请求授权，不显示破损图片作为成功状态。移除附件需有明确反馈；有已保存账单附件时不得因关闭预览而误删。

## 8. 业务影响与数据边界

- 账单备注仍是账单字段，不创建独立模板实体。若备注候选读取影响较大，可在技术设计阶段决定用聚合查询还是派生缓存，但账单数据为唯一事实来源。
- 图片附件引入账单与附件元数据关联。附件必须归属于唯一账单和账本；删除策略、对象清理、账单软删除后的可见性和备份策略需在技术/API 设计中明确。
- 邀请仍使用现有邀请实体和成员关系，不因增加邀请通知入口复制一套成员状态。
- 本期不修改金额单位、账单幂等 ID、并发版本、账本成员权限或统计口径。

## 9. 验收标准

### 9.1 邀请流程

- 给定未登录用户打开有效邀请链接，当用户登录成功，则系统回到该邀请详情而非账本首页或再次要求登录。
- 给定已经登录且邮箱匹配的用户打开有效邀请链接，当用户接受邀请，则该用户加入对应账本且只生成一条活跃成员关系。
- 给定已登录但邮箱不匹配的用户，当其接受邀请，则服务端拒绝且邀请仍为待处理状态，页面说明下一步操作。
- 给定邀请已撤销、过期或处理，当用户打开旧链接，则页面显示对应终态且不能加入账本。
- 给定用户从“我的邀请”拒绝待处理邀请，当操作成功，则邀请变为拒绝状态并从待处理项移除。
- 给定恶意回跳地址，当认证流程完成，则系统只跳转到允许的本站路径。
- 给定接受邀请请求重复提交或网络重试，当服务端处理请求，则不得重复创建成员关系或重复消费邀请。

### 9.2 图片附件

- 给定有权编辑账单的成员上传符合限制的图片，当上传和保存成功，则账单详情可查看该图片，数据库保存元数据和对象键而非图片二进制。
- 给定 `VIEWER` 或非账本成员请求上传、删除或读取附件，当服务端校验请求，则拒绝操作且不泄露对象地址。
- 给定不支持格式、超限文件或内容类型伪装，当用户上传，则服务端拒绝且账单和其他附件保持不变。
- 给定上传中断或对象存储不可用，当上传失败，则页面保留其他表单内容并明确标识该图片未保存，可重试。
- 给定附件已移除或账单已删除，当用户使用旧访问地址请求图片，则不能继续取得无授权访问。
- 给定对象存储备份恢复演练，当恢复完成，则数据库中有效附件关联对应对象可读取；孤立对象清理失败可重试且不恢复已删除附件的公开访问。

### 9.3 备注快捷选择

- 给定账单成功保存非空备注，当用户在同一账本打开新记账表单，则候选中可以看到该备注并按最近使用顺序排列。
- 给定用户选择一条备注候选，当候选填入输入框，则用户仍可编辑或清空，且账单不会自动提交。
- 给定用户在其他账本记过备注，当用户查看当前账本候选，则其他账本的备注不会出现。
- 给定空备注或仅空白备注，当账单保存成功，则该内容不会成为快捷候选。
- 给定候选超过展示上限，当用户打开备注快捷栏，则仅展示最近 10 条去重候选且可以横向访问可见内容。

### 9.4 键盘适配

- 给定 iOS Safari/PWA 或 Android Chrome/PWA 中记账页面，当金额或备注输入聚焦并弹出系统键盘，则页面不自动缩放，当前输入和候选条可见且可操作。
- 给定备注输入框聚焦且有历史候选，当键盘弹出，则候选条位于输入区与键盘上缘之间或视觉相邻区域，不被键盘完全遮挡。
- 给定键盘打开时表单内容超出可视区域，当用户滚动表单，则所有必填字段和主提交操作均可访问。
- 给定用户收起键盘或切换设备方向，当布局重新计算，则页面恢复正常高度且没有残留空白、重叠或内容丢失。
- 给定用户开启系统辅助缩放，当页面显示记账表单，则应用不强制禁止系统缩放功能。

### 9.5 日期时间选择

- 给定用户打开日期时间选择器，当用户取消，则原发生时间保持不变。
- 给定用户确认合法日期时间，当账单保存成功，则详情显示所选时间且日期分组和统计月份遵循账本时区。
- 给定窄屏设备打开选择器，当用户操作日期和时间，则控件不超出可视区域、不被导航或安全区遮挡，确认和取消操作均可触达。
- 给定日期时间组件候选方案，当其进入实现前，则完成 iOS/Android 真机或等效浏览器验证、无障碍和时区边界测试并记录选型结论。

## 10. 测试要求

- 邀请：覆盖未登录回跳、已登录直接进入、目标邮箱不匹配、有效期/撤销、重复接受、终态展示、开放重定向防护和邀请列表空/错误状态。
- 图片：覆盖账本成员权限、跨账本访问、类型/大小校验、上传失败重试、元数据与对象关联、删除授权失效及孤儿对象清理。
- 备注：覆盖账本隔离、排序、去重、空备注排除、最多 10 条、选中后可编辑及离线待同步边界。
- 键盘和日期选择器：覆盖可视视口改变、软键盘开合、横竖屏、弹层定位、取消不变、时区/DST边界和键盘可访问性；需在 iOS Safari/PWA 与 Android Chrome/PWA 手工验收。
- 测试不得依赖真实对象存储或真实用户数据；对象存储使用隔离的测试适配或模拟服务，仍需单独进行部署级备份恢复演练。
