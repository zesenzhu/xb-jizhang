# 小宝记账平台管理端需求

## 1. 文档范围

本文档定义小宝记账平台管理端的身份边界、角色权限、后台管理能力、审计要求和验收标准。管理端是服务端的独立权限域，前端管理页面可以后续开发，但后台身份、数据库模型和 API 约定必须从现在开始预留并按本规则实现。

本文档不改变 `OWNER`、`EDITOR`、`VIEWER` 三种账本成员角色。账本成员角色回答“用户在某个账本中可以做什么”，平台管理员角色回答“平台工作人员可以管理哪些系统资源”，两者不能互相替代。

## 2. 现状与问题

当前系统已经具备普通用户、账本和账本成员角色，但没有平台级管理能力。如果直接给 `User` 增加 `isAdmin` 字段，会产生以下问题：

- 普通用户会和后台工作人员共用登录入口、Cookie 和 Token，身份边界不清晰；
- 管理员权限容易被普通账本接口误用，越过 `LedgerMember` 约束；
- 后续需要多个管理员角色、权限码和权限变更记录时，`isAdmin` 无法扩展；
- 管理用户、查看敏感账单和修改账单等高风险操作没有统一审计主体。

## 3. 设计目标

- 管理员和普通用户使用独立账号体系，默认不建立账号关联。
- 管理员登录、刷新会话、退出登录和 Token 校验与普通用户完全隔离。
- 后台权限使用角色和权限码表达，权限校验由服务端完成。
- 管理员默认只能管理平台元数据和用户/账本状态，不能随意修改账单内容。
- 查看敏感账单、修改账单、修改系统配置和管理管理员账号等高风险操作必须单独授权并记录审计。
- 所有后台写操作都能定位到管理员、请求、目标资源、操作原因和结果。

## 4. 身份与账号边界

### 4.1 两类身份

| 身份 | 数据模型 | 登录入口 | Cookie | 主要权限边界 |
| --- | --- | --- | --- | --- |
| 普通用户 | `User` | `/api/auth/login` | `access_token`、`refresh_token` | 通过 `LedgerMember` 访问自己的账本 |
| 平台管理员 | `AdminUser` | `/api/admin/auth/login` | `admin_access_token`、`admin_refresh_token` | 通过平台权限码管理系统资源 |

管理员如果同时需要使用记账功能，单独注册或分配一个普通用户账号。第一期不把 `AdminUser` 与 `User` 关联，也不允许管理员 Token 直接访问普通用户接口。

### 4.2 Token 隔离

- 普通用户 Token 的 `aud` 固定为 `app`，管理员 Token 的 `aud` 固定为 `admin`。
- 普通用户和管理员使用不同的 Cookie 名称、刷新会话模型和 Guard。
- 管理员 Guard 必须同时校验签发类型、`aud`、签发密钥、账号状态和权限快照/权限查询结果。
- 任何一类 Token 访问另一类接口都返回认证失败，不通过权限不足响应泄露身份信息。

## 5. 管理员角色与权限

### 5.1 初始内置角色

| 角色 | 定位 | 默认能力 |
| --- | --- | --- |
| `SUPER_ADMIN` | 平台安全负责人 | 全部管理权限，包括管理员账号、角色权限和系统高风险操作 |
| `OPERATOR` | 日常运营人员 | 用户和账本基础查询、账号状态处理、非敏感运营操作 |
| `AUDITOR` | 审计和只读人员 | 查询审计日志、用户、账本和被授权的只读数据，不能修改业务数据 |

角色不是最终授权依据，服务端必须检查角色关联的权限码。后续可以增加角色，但不能通过前端传入角色名称绕过权限码判断。

### 5.2 权限码方向

权限码使用稳定的英文编码，文案使用中文。初始权限至少包括：

| 权限码 | 用途 | 风险级别 |
| --- | --- | --- |
| `admin:user:read` | 查询用户列表和用户详情 | 低 |
| `admin:user:status` | 禁用或恢复用户账号 | 中 |
| `admin:ledger:read` | 查询账本摘要、成员和状态 | 低 |
| `admin:ledger:status` | 归档或恢复账本 | 中 |
| `admin:transaction:read_sensitive` | 查看敏感账单详情或导出 | 高 |
| `admin:transaction:write` | 修改或撤销账单 | 高 |
| `admin:config:read` | 查询系统配置 | 中 |
| `admin:config:write` | 修改系统配置 | 高 |
| `admin:audit:read` | 查询管理审计日志 | 中 |
| `admin:admin_user:manage` | 管理管理员账号、角色和权限 | 极高 |

没有明确授予 `admin:transaction:read_sensitive` 或 `admin:transaction:write` 时，管理员不能通过后台接口读取或修改账单正文。运营查询应优先返回脱敏摘要。

## 6. 后台功能范围

### 6.1 管理员认证

- 管理员登录、刷新会话、退出登录和查看当前管理员资料。
- 管理员会话支持按设备撤销和全部会话撤销。
- 登录失败、账号停用、刷新凭证失效和权限不足不泄露敏感账号信息。
- 管理员登录和高风险操作需要限流；多因素认证作为上线前安全增强项评估。

### 6.2 用户管理

- 分页查询用户、按用户名/邮箱/状态筛选。
- 查看用户基础资料、账号状态、创建时间和账本数量。
- 禁用或恢复用户账号，必须填写操作原因。
- 禁用用户后，普通用户登录、刷新会话和账本写操作立即受影响；历史业务数据不删除。
- 后台默认不提供直接查看密码、Token 或完整认证会话的能力。

### 6.3 账本管理

- 分页查询账本、创建者、成员数量、账本类型和归档状态。
- 查看账本基本信息、成员摘要和风险状态。
- 归档或恢复账本，必须填写操作原因并记录审计。
- 后台默认不能直接修改账本成员角色、Owner 或账本业务数据；确需处理时必须拆分为明确权限并保留审计。

### 6.4 账单管理

- 默认只提供脱敏统计和账单数量等运营信息。
- 查看敏感账单必须具备独立权限，并在请求中填写查看原因。
- 修改、撤销或恢复账单必须具备独立高风险权限，并填写操作原因、目标账单和变更内容。
- 管理员修改账单不能伪装成普通用户操作，账单的 `updatedById` 与管理审计必须保留管理员身份。

### 6.5 系统配置

- 查询和修改允许后台管理的配置项，例如注册开关、邀请策略和展示配置。
- 密钥、密码、Token、数据库连接信息等秘密不能通过普通配置接口返回。
- 配置修改必须记录修改前后值；敏感配置只记录脱敏摘要或哈希。

### 6.6 审计查询

- 按管理员、操作类型、目标资源、结果、请求 ID 和时间范围查询审计日志。
- 审计日志只允许追加，不允许普通后台接口修改或删除。
- 审计查询本身也记录访问日志，但不能因为查询日志产生无限递归记录。

## 7. 高风险操作规则

以下操作必须满足“独立权限 + 操作原因 + 审计日志 + 服务端事务/并发检查”：

- 禁用或恢复用户账号；
- 归档或恢复账本；
- 查看敏感账单或导出敏感数据；
- 修改、撤销或恢复账单；
- 修改系统配置；
- 管理员账号、角色和权限变更。

操作原因不能由前端隐藏字段代替，服务端必须校验非空、长度和敏感内容规则。高风险操作失败也要记录失败结果和错误分类，不能记录密码、Token 或完整秘密。

## 8. 验收标准

- 给定普通用户访问 `/api/admin/**`，当服务端校验请求身份，则拒绝访问且不泄露管理端资源信息。
- 给定管理员访问 `/api/auth/**` 的普通用户接口，当服务端校验 Token audience，则拒绝访问。
- 给定 `AUDITOR` 查询用户或审计日志，当请求权限满足，则可以读取脱敏结果；当尝试禁用用户，则服务端拒绝操作。
- 给定 `OPERATOR` 没有敏感账单权限，当查询账单详情，则服务端不返回账单正文。
- 给定管理员执行高风险操作但未提供操作原因，当提交请求，则校验失败且不发生业务变更。
- 给定高风险操作成功或失败，当请求处理完成，则生成包含管理员、目标、原因、请求 ID、IP、前后数据摘要和结果的审计记录。
- 给定管理员账号被停用，当其使用旧访问 Token 或刷新凭证，则服务端拒绝后续访问并撤销相关会话。
- 给定同一后台写请求被重复提交，当服务端检测到相同幂等标识，则不会重复产生业务变更。

## 9. 非目标与未决问题

- 前端 `/admin` 页面、菜单、权限树和视觉设计不在本次实现范围，后续单独设计。
- 不引入旧项目的注册码、设备授权、MQTT、TCP、脚本日志或 AI Agent 业务。
- 管理员是否强制启用 MFA、审计日志保留周期、敏感账单脱敏字段和导出审批流程，需要在生产上线前确认。
