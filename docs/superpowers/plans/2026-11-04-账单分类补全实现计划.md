# 账单分类补全实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将账单分类补全为最多两级，并为新建账本内置覆盖日常收支场景的默认分类目录。

**架构：** Prisma `Category` 增加可空自关联 `parentId`，服务端强制父级同账本、同收支类型且只能是一级分类；分类查询返回父级标识，已有前端 `CategoryGrid` 和 `category-tree` 负责按一级/二级组织选择。默认分类在注册和新建账本的同一事务中批量初始化，并通过幂等 Migration 为历史账本补齐缺失目录；历史分类不重命名、不删除。

**技术栈：** NestJS、Prisma、PostgreSQL、Next.js、TanStack Query、TypeScript、Jest、前端轻量契约测试。

**规格依据：** `docs/需求/一期账本与记账需求.md` 第 9 节及 `docs/api/账户与分类接口.md` 分类接口约定。

## 全局约束

- 分类只允许 `EXPENSE` / `INCOME`，账单类型必须与分类类型一致。
- 分类最多两级；一级分类可以直接用于账单，二级分类必须挂在同账本同类型的一级分类下。
- 分类名称在同账本、同收支类型、同父级下唯一；停用分类不能用于新账单。
- 分类管理写操作仍只允许账本 `OWNER`，分类读取允许活跃成员。
- 数据库变更使用 Prisma Migration，不使用生产 `db push`。
- 本次不新增分类管理页面，不把并行记账抽屉的无关改动带入提交。
