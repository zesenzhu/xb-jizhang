# 二期统计后台实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按账本时区实现二期统计概览、趋势、分类和周期汇总接口，并保持账单列表统计下钻一致。

**Architecture:** 统计接口共享一套日期范围解析、账本成员校验、账户可见性和账单过滤规则。自然日期用时区感知日期类型转换为 UTC 半开区间；聚合使用 PostgreSQL 按账本本地日期分组，响应周期由相同日期工具补齐。现有 ISO `from/to` 概览参数在迁移期保留。

**Tech Stack:** NestJS 11、Prisma 7、PostgreSQL、`@js-temporal/polyfill`、class-validator、Jest。

**Spec:** `docs/api/统计接口.md`、`docs/需求/二期账本管理与统计需求.md`、`docs/api/账单接口.md`

## Global Constraints

- 日期周期、自然日和有效统计天数均按账本 IANA `timezone` 计算，不能假设自然日固定为 24 小时。
- 只统计当前账本、未软删除的 `EXPENSE/INCOME`；TRANSFER 不进入统计。
- 所有聚合复用成员、私人账户、账单分类、账户、付款人和关键词过滤条件。
- 金额以整数分聚合；比例使用明确的四舍五入规则；无数据时按接口契约返回空范围或零值周期。
- `categoryRootId` 必须同时匹配一级分类本身和其二级分类，账单列表下钻使用相同条件。
- 不新增服务端统计缓存；无文档依据不发送并发控制请求头。
- 每个行为先写并观察失败测试，再实现；每个可独立验证的模块单独提交。
