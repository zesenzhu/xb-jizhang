# 分类模块实现计划

## 目标

在已有账本成员权限和账户模块基础上，完成账本收支分类的查询、创建、编辑、排序、停用和重新启用能力，并确保新建账本自动拥有可用的默认分类。

## 实施范围

- [x] 增加分类模块、DTO、Service 和 Controller。
- [x] 只允许活跃账本成员访问分类；启用分类对所有活跃成员可见。
- [x] 只允许 `OWNER` 创建、编辑、排序、停用和重新启用分类。
- [x] 支持 `EXPENSE` / `INCOME` 类型筛选、分页和停用分类管理查询。
- [x] 创建和编辑分类名称时执行 `trim()`，数据库唯一约束冲突映射为 `40921`。
- [x] 注册创建默认个人账本、新建账本时，在同一事务内创建四条默认分类。

> 后续分类补全计划将新建账本默认目录扩展为 16 个一级和 49 个二级；本历史计划保留当时的四分类交付记录。
- [x] 补充分类 Service、Controller，以及注册和建账默认分类测试。
- [x] 完成后端类型检查、全量测试、Lint、构建和 Prisma 校验。

## 默认分类

| 类型 | 名称 | 排序 | 系统标识 |
| --- | --- | --- | --- |
| `EXPENSE` | 餐饮 | `10` | `true` |
| `EXPENSE` | 交通 | `20` | `true` |
| `INCOME` | 工资 | `10` | `true` |
| `INCOME` | 其他收入 | `20` | `true` |

## 验证结果

- 分类及受影响测试：`6` 个测试套件、`29` 个用例通过。
- 后端全量测试：`32` 个测试套件、`98` 个用例通过。
- `pnpm typecheck`：通过。
- `pnpm lint`：通过。
- `pnpm build`：通过。
- `DATABASE_URL=... pnpm prisma validate`：通过。

## 后续边界

- 分类物理删除不在当前接口范围内；被账单引用的分类只能停用。
- 账单写入模块需要继续校验分类属于当前账本、类型与账单类型匹配且分类处于启用状态。
