# 平台管理端后台实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 NestJS 后台建立与普通用户完全隔离的管理员身份、RBAC 权限、刷新会话、用户/账本管理 API 和管理员审计链路。

**Architecture:** 管理端与普通用户共用 NestJS 服务和 PostgreSQL，但使用独立的 `AdminUser`、`AdminRefreshSession`、`AdminAuthGuard`、Cookie、JWT audience 和权限上下文。管理端写操作通过权限码、操作原因、并发字段和 `AdminAuditLog` 事务保证可追溯；前端 `/admin` 页面暂不实现。

**Tech Stack:** NestJS 11、Prisma 7、PostgreSQL、JWT HttpOnly Cookie、Node `scrypt`、Jest。

**Spec:** `docs/requirements/平台管理端需求.md`、`docs/architecture/平台管理端技术设计.md`、`docs/api/管理端接口约定.md`

## Global Constraints

- 普通用户 `User` 与平台管理员 `AdminUser` 不建立账号关联，不增加 `User.isAdmin`。
- 普通用户 Cookie/Token 使用 `access_token`、`refresh_token`、`aud=app`；管理员使用 `admin_access_token`、`admin_refresh_token`、`aud=admin`。
- 管理员刷新会话只存储 `AdminRefreshSession`，Token 只保存 SHA-256 哈希。
- 权限最终由服务端权限码判断；前端路由和菜单不构成安全边界。
- 高风险操作必须校验独立权限、非空操作原因、`updatedAt`/`version`，并在同一事务中写入审计。
- 审计日志不得保存密码、Cookie、Token、JWT Secret、数据库连接串或未脱敏敏感数据。
- 所有行为变更先写失败测试，再写最小实现；测试使用浅层 Prisma Mock，不连接真实业务数据库。
- 代码、Swagger 描述、用户可见文案和新增注释使用中文；API 路径、权限码、枚举和配置键保留原始写法。
