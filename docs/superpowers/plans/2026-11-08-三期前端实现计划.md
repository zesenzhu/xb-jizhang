# 三期前端实现计划

## 目标

按三期四项需求完成前端改造：邀请流程全链路可响应、历史备注可复用、键盘覆盖下仍可完成记账、日期时间可用独立弹窗选择。图片附件本期不做。

后端接口按 `docs/api/账本与成员接口.md` 与 `docs/api/账单接口.md` 实现中，前端先完成纯函数与页面骨架，联调阶段只改适配层。

## 实施范围

### 任务 1：登录回跳保留邀请参数（无后端依赖）

- [ ] `lib/routing/routes.ts` 增加 `REDIRECT_QUERY_ALLOWLIST` 与 `getLoginRedirectUrl(kind, pathname, search?)`。
- [ ] `getSafeRedirectTarget` 解析并复校验查询串，未知参数丢弃，保持现有 `//`、`\`、`/../` 拦截。
- [ ] `UserAuthBoundary` 跳登录时读取 `window.location.search`，不再只传 `pathname`。
- [ ] `lib/api/user-client.ts` 的 `handleUserRefreshFailure` 改用同一函数。
- [ ] 测试 `frontend/test/redirect-query.test.ts`：保留 `token`/`action`、丢弃未知参数、拒绝外部与畸形地址、无 search 时行为不变。

### 任务 2：我的邀请页改造（依赖任务 1）

- [ ] `lib/api/invitation-api.ts` 增加 `getInvitationPreview`、`getInvitationDetail`、`acceptInvitationById`、`declineInvitationById`，保留旧 token 方法作兼容。
- [ ] `lib/api/invitation-types.ts` 增加 `InvitationPreview`、`InvitationTokenDetail`、`InvitationBlockedReason`。
- [ ] `lib/invitation/invitation-state.ts` 实现 `resolveInvitationState`，由 `blockedReason` + mutation 状态推导。
- [ ] 页面渲染邀请详情卡、终态卡、待处理列表；列表条目支持就地接受/拒绝。
- [ ] 邮箱缺失/不匹配时跳个人资料补全，携带回跳地址，返回后重新拉详情。
- [ ] `blockedReason=ALREADY_MEMBER` 直接进入账本，不显示接受。
- [ ] 成功后 `router.replace` 清掉 `token`。
- [ ] 测试 `frontend/test/invitation-state.test.ts`：九种 `blockedReason`、提交中、失败、终态不可回到可响应。

### 任务 3：键盘覆盖与编辑条（无后端依赖）

- [ ] `lib/viewport/use-visual-viewport.ts` 输出 `height`、`offsetTop`、`keyboardInset`、`isKeyboardOpen`，rAF 合并，无 `visualViewport` 时回退。
- [ ] `app/layout.tsx` 的 `viewport` 增加 `interactiveWidget: 'resizes-visual'`。
- [ ] `BottomSheet` 全屏形态保持 `100dvh`，不跟随键盘重算高度。
- [ ] `SheetMetaFields` 输入字号改为 16px；`globals.css` 增加移动端 16px 护栏。
- [ ] 新增 `NoteComposerDock`：`position: fixed`、`bottom: keyboardInset`、`z-[65]`，含输入框、候选、完成、保存账单。
- [ ] 保证切换编辑字段不重建输入控件（`SheetMetaFields` 常驻）。
- [ ] 测试 `frontend/test/keyboard-inset.test.ts`、`note-composer.test.ts`、`mobile-input-guard.test.ts`。

### 任务 4：历史备注候选（依赖任务 3，接口为 `note-suggestions`）

- [ ] `lib/api/note-api.ts` 增加 `getNoteSuggestions`，`limit` 固定 10。
- [ ] `query-config.ts` 增加 `noteSuggestions(ledgerId)` 键，`staleTime` 30s。
- [ ] `lib/bill/note-suggestions.ts` 实现 `buildNoteSuggestions`（trim、去重、截断）。
- [ ] `NoteSuggestionBar` 接入编辑条；点击填入不提交；输入法组合期间不截断。
- [ ] 账单创建/编辑/删除成功后失效候选缓存。
- [ ] 测试 `frontend/test/note-suggestions.test.ts`。

### 任务 5：日期时间弹窗（依赖任务 3）

- [ ] 新增 `components/ui/modal.tsx`：居中弹窗、遮罩、焦点环路、`z-[70]`、安全区。
- [ ] 新增 `DateTimePickerDialog`：日历格 + 时/分列，取消不改值，确认才写回。
- [ ] `lib/bill/datetime-picker.ts` 提供拆分/组装/边界/步进/时区换算纯函数。
- [ ] `BillFormBody` 的 `toLocalInputValue` 改为按账本时区格式化，`handleTimeChange` 输出带偏移 ISO。
- [ ] 点击时间胶囊先 `blur` 收起键盘，再打开弹窗。
- [ ] 测试 `frontend/test/datetime-picker.test.ts`，覆盖闰年、月末、未来时间裁剪、时区跨日。

## 实施约束

- 不新增第三方日期组件库；弹窗与滚轮自建。
- 不引入图片附件相关组件、接口与测试。
- 所有金额仍走 `lib/bill/amount.ts` 字符串处理，禁止浮点参与业务判断。
- 邀请与备注接口字段以 DTO、Swagger 为准；适配层之外不出现接口路径字符串。
- 每个任务完成即补测试，测试与被测代码就近放置，沿用 `tsx` + `node:assert` 风格。

## 交付顺序

任务 1 → 2 与 3 并行 → 4 → 5。任务 2、4、5 的联调依赖后端接口就绪；未就绪时保留纯函数与骨架，页面以“暂不可用”状态降级，不伪造成功。

## 后续边界

- 图片附件与对象存储另行立项，本期不改动 `SheetQuickChips` 的禁用态。
- 单会话踢出与本地优先异步记账不属于本计划，另行评审后单独排期。
- 账本时区在账单页已按 `ledger.timezone` 读取，本期只补齐记账写入侧换算。
