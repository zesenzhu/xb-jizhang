# 账单列表查询实现计划

## 目标

在账单创建和详情查询基础上，实现账本账单列表的分页、筛选、排序和私人账户可见性控制。

## 实施范围

- [x] 新增列表查询 DTO 和 `TransactionQuery` 类型。
- [x] 支持 `page`、`pageSize`，每页最大 `100`。
- [x] 支持 `type`、`categoryId`、`accountId`、`payerId` 筛选。
- [x] 支持 `from` 包含、`to` 不包含的时间范围筛选。
- [x] 支持标题和备注的不区分大小写关键词包含匹配。
- [x] 默认过滤 `deletedAt != null` 的软删除账单。
- [x] 共享账户对所有活跃成员可见，私人账户仅账户所有者可见。
- [x] 按 `occurredAt DESC, createdAt DESC` 分页返回统一结构。
- [x] 补充 Service、Controller 测试和空列表/非法时间范围场景。

## 查询约束

```text
活跃账本成员校验
  → 组合 ledgerId、deletedAt、筛选条件和账户可见性
  → 并行查询分页数据与总数
  → 返回 items、total、page、pageSize、hasNextPage
```

列表不会因为账户停用而隐藏历史账单，只会继续校验私人账户所有权；默认查询不包含软删除账单。

## 验证结果

- 列表、创建与详情测试：`2` 个测试套件、`17` 个用例通过。
- 后端全量测试：`34` 个测试套件、`115` 个用例通过。
- `pnpm typecheck`：通过。
- `pnpm lint`：通过。
- `pnpm build`：通过。

## 后续边界

- 编辑账单继续使用 `version` 乐观锁，不能依赖列表查询结果直接覆盖。
- 软删除账单在列表过滤后，还需要单独实现余额恢复和删除审计。
- 统计模块应复用同样的软删除和账本隔离口径。
