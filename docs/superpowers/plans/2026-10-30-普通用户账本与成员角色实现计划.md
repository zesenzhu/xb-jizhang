# 普通用户账本与成员角色实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 NestJS 后台实现普通用户的账本、成员角色和邮箱邀请流程，使多人共享账本具备可用的服务端权限边界。

**Architecture:** 新增 `ledger`、`ledger-member`、`invitation` 三个模块。所有资源查询先通过当前用户的 `LedgerMember` 活跃关系确定可见范围，再执行账本或成员操作；角色变更、成员状态迁移、Owner 转移和邀请消费使用 Prisma transaction。普通用户和平台管理员继续保持独立身份域。

**Tech Stack:** NestJS 11、Prisma 7、PostgreSQL、class-validator、Jest、Node `crypto`。

**Spec:** `docs/requirements/用户与成员角色需求.md`、`docs/api/账本与成员接口.md`、`docs/architecture/后端功能设计.md`

## Global Constraints

- 所有账本资源必须从认证用户的 `LedgerMember(status=ACTIVE)` 关系开始校验，不能信任客户端传入的操作者 ID。
- `OWNER`、`EDITOR`、`VIEWER` 是账本级固定角色，不新增系统级普通用户 Role 表。
- `LEFT`、`REMOVED` 成员不能访问账本；重新加入必须通过新的有效邀请复用原成员关系。
- 最后一个 `OWNER` 不能被降级、移除或主动退出；Owner 转移必须在一个事务中完成。
- 邀请 Token 使用随机原文一次性返回，数据库只存 SHA-256 哈希；邀请不能直接授予 `OWNER`。
- 行为变更先补失败测试，再写最小实现；Service 使用浅层 Prisma Mock，不连接真实生产数据库。
- 代码、接口错误文案、注释和文档使用中文；API 路径、枚举和权限值保留原始写法。
