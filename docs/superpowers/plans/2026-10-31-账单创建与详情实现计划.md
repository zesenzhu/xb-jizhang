# 账单创建与详情实现计划

## 目标

在已有账本成员、账户和分类能力基础上，完成收入/支出账单的创建与详情查询，并保证账户余额、幂等和创建审计的一致性。

## 实施范围

- [x] 新增 `transaction` 模块、创建 DTO、Service 和 Controller。
- [x] 只允许活跃账本的 `OWNER`、`EDITOR` 创建账单，`VIEWER` 拒绝写入。
- [x] 校验金额为正整数分、时间为有效 ISO 8601 时间。
- [x] 校验账户属于当前账本、处于启用状态并对当前用户可见。
- [x] 校验分类属于当前账本、处于启用状态且类型与账单一致。
- [x] 校验付款人为当前账本的活跃成员。
- [x] 支出扣减账户余额，收入增加账户余额。
- [x] 使用账本级 `clientRequestId` 实现重复提交幂等。
- [x] 在同一事务中创建账单、更新余额和写入 `CREATE` 审计。
- [x] 详情查询重新回读数据库，并拒绝泄露其他成员的私人账户账单。
- [x] 补充 Service 和 Controller 测试。

## 事务边界

```text
校验活跃成员和写权限
  → 校验幂等记录、账户、分类和付款人
  → 创建 Transaction
  → 更新 Account.currentBalanceCents
  → 创建 TransactionAuditLog
  → 回读完整详情
```

数据库唯一约束触发并发幂等冲突时，服务端回读同一账本和 `clientRequestId` 的原账单；无法回读时返回 `40922`。

- `pnpm typecheck`：通过。
- `pnpm lint`：通过。
- `pnpm build`：通过。
- `DATABASE_URL=... pnpm prisma validate`：通过。

## 后续边界

- 账单列表和筛选单独实现，必须继续处理私人账户可见性。
- 编辑需要 `version` 乐观锁，并在同一事务内重算旧/新余额影响。
- 软删除需要恢复余额、递增版本并写入删除审计。
- 转账不属于本阶段范围，现有数据库遗留字段不纳入本阶段接口和业务逻辑。
