## 2. 需要先修的既有问题

这些问题会让新页面「看起来生效但实际无效」，必须在迭代一开始处理。

### 2.1 `AmountDisplay` 颜色硬编码

当前 `colored` 生效为 `text-emerald-400` / `text-rose-400`，与需求要求的语义色不一致，且在浅色卡片上对比度不足。

改为消费 `text-financial-income` / `text-financial-expense`，同时给 `globals.css` 补暗色覆盖。改动影响现有首页与 `FoundationDashboard`（后者是死代码，可忽略）。

### 2.2 未定义类名

`text-ios-blue`、`from-ios-blue`、`shadow-ios-blue/*` 在 `AuthCard`、`UserAuthEntry`、`SyncStatusBar` 中共出现 10+ 次，因 `--color-ios-blue` 未定义而完全无效。

本期一并清理：统一替换为 `text-primary` / `from-primary` / `shadow-primary/*`。不新增 `--color-ios-blue`，避免同一语义两套 token。

### 2.3 无效动画类

`animate-in`、`fade-in`、`zoom-in-95` 依赖 `tailwindcss-animate`，项目未安装。改为原生 `transition`：

```css
.sheet-enter { transform: translateY(100%); }
.sheet-enter-active { transform: translateY(0); transition: transform 240ms ease-out; }
```

或直接用 Tailwind 的 `transition-transform duration-200 data-[state=open]:translate-y-0 translate-y-full` 组合。

### 2.4 `pb-safe` 叠加

`AmountKeypad` 容器已含 `pb-safe`，放进抽屉后与抽屉自身的 safe-area padding 叠加成双倍 20px。处理：给键盘增加 `insetSafeArea?: boolean`（默认 `true`），抽屉内传 `false`。

### 2.5 暗色模式不可用

`[data-theme='dark']` 无任何设置点。本期不启用开关，但需：

- 补齐 `--theme-primary*`、`--color-income/expense`、`--color-fab` 的暗色值，避免将来启用时出现色板断层；
- 把 `profile` 页「跟随系统深色模式自动适配」改为事实描述或删除。

## 3. 样式实现约束

### 3.1 颜色

只允许三类来源：

1. `globals.css` `@theme` 定义的语义类名；
2. Tailwind 内置中性色（`slate` / `zinc`）用于骨架与遮罩；
3. 深色概览卡的少量硬编码需要在迭代一中抽成 token。

禁止：
- 新增未定义的 `*-ios-*` 类名；
- 在业务组件里写 `bg-[#xxxxxx]`；
- 同一语义在不同页面用不同色值。

### 3.2 圆角与间距

- 卡片 `rounded-3xl`（现有约定），小控件 `rounded-2xl`，胶囊 `rounded-full`。
- `@theme` 中已定义 `--radius-ios-*` 但无消费方；本期不推广，沿用现有 `rounded-2xl/3xl`，避免两套体系。
- 页面横向内边距统一 `px-4`，内容宽度 `max-w-md mx-auto`。

### 3.3 安全区

- 页面容器：`pb-[calc(4rem+env(safe-area-inset-bottom))]`（底栏高度 + 安全区）。
- FAB：`bottom-[calc(5rem+env(safe-area-inset-bottom))] right-4`。
- 抽屉：底部 `pb-[env(safe-area-inset-bottom)]`，键盘不再重复加。

不使用现有的 `.pb-safe` 工具类（其 fallback 为固定 20px，桌面端会凭空多出间距），改为显式 `env()` 表达式。

### 3.4 层级

| 层 | z-index |
| --- | --- |
| 页面内容 | 0 |
| FAB | 30 |
| 底栏 `MobileBottomNav` | 40 |
| 抽屉 / 详情面板 | 50 |
| 分类选择（二级抽屉） | 60 |
| Toast | 70 |

FAB 在底栏之下：底栏常驻，FAB 需在视觉上位于底栏上方但不遮挡底栏点击区域，通过 bottom 偏移实现，不靠 z-index 竞争。

### 3.5 图标

统一使用 `lucide-react`（已安装）。分类图标采用「分类名首字 + 语义色圆底」的降级方案，待后端返回 `icon` 字段后再切换为图标映射。

## 4. `BottomSheet` 契约

```text
BottomSheetProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  title?: string
  layer?: 'base' | 'nested'      // nested 用于分类选择，z-index 更高
  onBeforeClose?: () => boolean  // 返回 false 阻止关闭（未保存内容确认）
  children: React.ReactNode
}
```

实现要求：

- 用 `createPortal` 挂到 `document.body`；
- 打开时 `body.overflow = 'hidden'` 并保存原值，关闭时恢复原值（现有 `Dialog` 直接置空，嵌套时会互踩）；
- 焦点进入面板内第一个可聚焦元素，关闭后归还触发元素；
- `Esc` 关闭，触发 `onBeforeClose`；
- 点击遮罩关闭，触发 `onBeforeClose`；
- 不实现下滑手势（需求 7.1 明确不把手势作为唯一关闭方式，且手势与列表滚动冲突）。

## 5. 状态与反馈组件

### 5.1 `Toast`

```text
toast.success('已保存')
toast.error('保存失败，请重试')
toast.action('已删除', { label: '撤销', onClick })   // 5 秒后自动消失
```

单例容器挂载在 `UserNavShell` 内，`z-70`，位于底栏之上。支持同时最多 1 条（后入覆盖先入），符合移动端窄屏。

### 5.2 空态与错误态

沿用 `LedgerList` 已有的两套视觉：

- 空态：虚线边框卡片 + 图标 + 说明 + 可选操作按钮；
- 错误态：`role="alert"` + 浅红背景 + 重试按钮。

不新建空态组件，抽为 `components/common/EmptyState.tsx` 与 `ErrorState.tsx` 后由账本页与账单页共用。

## 8. UI 验收清单

| 项 | 标准 |
| --- | --- |
| 移动端 375×812 | 无横向滚动，FAB 不遮挡最后一行账单 |
| 桌面 1440×900 | 内容居中 `max-w-md`，底栏隐藏时无多余 6rem 空白 |
| 安全区 | iPhone 模拟器下 FAB 与底栏不重叠 |
| 颜色 | 支出与收入色在浅色卡片上对比度 ≥ 4.5:1 |
| 键盘可达 | Tab 可遍历抽屉内全部控件，`Esc` 可关闭 |
| 空/错/加载 | 三种状态均有明确文案，不出现布局跳动 |
| 无无效类名 | `grep -r "ios-blue\|animate-in" frontend/src` 零命中 |
