# 账本设置 `/user/ledgers/:ledgerId/settings`

单个账本的资料、成员、分类、币种、复制与删除。二级页面，从「我的账本」的 `⋯` 或账本页顶部进入。

## 1. 页面结构与布局

```text
┌────────────────────────────────────────┐
│ ‹            家庭账本                  │
├────────────────────────────────────────┤
│      🏠                                 │
│      家庭账本                           │
│      共享账本 · 人民币 CNY · OWNER      │
├────────────────────────────────────────┤
│ 编辑账本                            ›  │
│ 成员与邀请                   4 位成员 › │
│ 分类管理                            ›  │
├────────────────────────────────────────┤
│ 账本币种              人民币 CNY      ›  │
├────────────────────────────────────────┤
│ 复制账本                            ›  │
│ 删除账本                            ›  │  ← 仅满足条件时渲染
└────────────────────────────────────────┘
```

分组规则：

| 分组 | 项 |
| --- | --- |
| 资料区 | 编辑账本 |
| 协作区 | 成员与邀请（仅 `SHARED`）、分类管理 |
| 财务区 | 账本币种 |
| 危险区 | 复制账本、删除账本 |

**「成员与邀请」只在共享账本显示**。个人账本没有成员管理，服务端也会拒绝个人账本的邀请（`40903`）。

## 2. 数据来源

| 用途 | 接口 | 缓存键 | staleTime |
| --- | --- | --- | --- |
| 账本详情 | `GET /ledgers/:id` | `['ledgers','detail',id]` | 60s |
| 成员数 | 同上返回 `memberCount`，不单独请求 | — | — |
| 编辑资料 | `PATCH /ledgers/:id` | 成功后失效 `detail` 与 `list` | — |
| 复制 | `POST /ledgers/:id/copy` | 成功后失效 `list` | — |
| 删除 | `DELETE /ledgers/:id` | 成功后失效 `list` + `preferences` | — |

### 2.1 权限

`memberRole` 决定渲染：

| 角色 | 可见项 |
| --- | --- |
| `OWNER` | 全部 |
| `EDITOR` / `VIEWER` | 只读：名称、类型、币种、角色、成员数；不渲染任何 `›` 可点项 |

需求 7.7 明确“无权管理的成员可以查看账本名称、类型、币种和成员角色，但不显示管理操作”。

## 3. 交互规则

### 3.1 编辑账本

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，`trim()` 后非空；同一用户可有同名账本 |
| 图标 | 可选，从固定图标集选择 |
| 颜色 | 可选 |
| 时区 | IANA 标识，默认 `Asia/Shanghai` |
| 类型 | **只读**，创建后不可改 |

保存必须带 `updatedAt`。`40902`（资料并发冲突）时提示「账本资料已被修改，请查看最新内容」并刷新。

**改时区需二次确认**，文案说明「会改变统计的自然日/月/年分组边界，账单原始时间不变」。这是需求 7.4 的硬性要求。

### 3.2 修改币种

- 账本已有账单（含软删除）时，币种只读。
- 空账本可改，但需二次确认并说明「金额输入与展示单位会改变」。
- 后端会校验，前端只是提前拦住明显不可用的情况。

### 3.3 复制账本

只复制基本设置 + 分类树，**不复制**账单、账户、成员、邀请、余额、统计。

请求必须带 `clientRequestId`（防止重试创建多个账本）。成功后提示「已创建『xxx』」，不自动切换当前账本。

### 3.4 删除账本

渲染条件（全部满足才显示）：

- 当前用户是 `OWNER`
- 账本无任何账单（含软删除）
- 无其他活跃成员
- 无待处理邀请
- 用户还有其他可访问账本

前端做的是**显隐**，真正拦截在服务端。错误码映射：

| code | 文案 |
| --- | --- |
| `40911` | 账本内有账单，不能删除 |
| `40912` | 还有其他成员，请先移除 |
| `40913` | 还有待处理邀请，请先撤销 |
| `40914` | 这是你的最后一本账本，请先新建或加入其他账本 |

确认弹窗必须写明「永久删除，无法恢复」。

## 4. 状态矩阵

| 状态 | 触发 | 呈现 |
| --- | --- | --- |
| 加载中 | 详情请求中 | 头部骨架 + 4 行骨架 |
| 只读（Editor/Viewer） | 角色非 Owner | 无 `›`、无危险区 |
| 保存中 | PATCH 进行中 | 保存键 loading，字段禁用 |
| 并发冲突 | `40902` | 提示并刷新详情 |
| 删除条件不满足 | 有账单/成员/邀请 | 不渲染删除项 |
| 删除进行中 | DELETE 进行中 | 确认键 loading，页面禁用 |
