# 我的邀请 `/user/invitations`

受邀者处理共享账本邀请的页面，同一路由承担两种入口：登录前的邀请说明（带 `token` 进入）和登录后的邀请列表与就地响应。三期修复“能看到邀请但无法响应”的断点。

## 1. 页面结构与布局

```text
┌────────────────────────────────────────┐
│ ‹              我的邀请                 │
├────────────────────────────────────────┤
│ ┌ 邀请详情 ──────────────────────────┐  │
│ │ 家庭账本                            │  │
│ │ 小宝 邀请你以 EDITOR 加入            │  │
│ │ 11月11日 16:00 前有效                │  │
│ │ [接受邀请并加入]  [拒绝]             │  │
│ └────────────────────────────────────┘  │
├────────────────────────────────────────┤
│ 待处理邀请                              │
│ 家庭账本  EDITOR  11月11日到期    ›     │
│ 旅行账本  VIEWER  11月9日到期     ›     │
├────────────────────────────────────────┤
│ 已处理邀请（折叠）                       │
└────────────────────────────────────────┘
```

- 带 `token` 进入时，邀请详情卡置顶，列表仍在其下，便于用户确认还有哪些邀请。
- 不带 `token` 时只显示列表，列表条目自带接受/拒绝操作，不再要求用户回头找链接。
- 邮箱不匹配或未填邮箱时，详情卡替换主按钮为「补全邮箱」引导，不显示可点的接受。
- 已加入该账本时，主按钮变为「进入账本」，不显示拒绝。

## 2. 数据来源

| 用途 | 接口 | 缓存键 | staleTime |
| --- | --- | --- | --- |
| 登录前邀请说明 | `GET /invitations/preview?token=` | `['user','invitation','preview',token]` | 0 |
| 登录后邀请详情 | `GET /invitations/token?token=` | `['user','invitation','token',token]` | 0 |
| 我的待处理邀请 | `GET /invitations` | `['user','invitations']` | 30s |
| 按记录接受 | `POST /invitations/:invitationId/accept` | 成功后失效 `invitations`、`ledgers`、`ledgers/preferences` | — |
| 按记录拒绝 | `POST /invitations/:invitationId/decline` | 成功后失效 `invitations` | — |
| 旧链接兼容 | `POST /invitations/accept`、`POST /invitations/decline`（body 带 token） | 同上 | — |

### 2.1 关键字段

`GET /invitations/token` 返回：

```ts
interface InvitationTokenDetail {
  id: string;
  ledger: { id: string; name: string; type: 'PERSONAL' | 'SHARED'; defaultCurrency: string; timezone: string };
  inviter: { id: string; nickname: string | null; avatar: string | null };
  role: 'EDITOR' | 'VIEWER';
  status: 'PENDING' | 'ACCEPTED' | 'DECLINED' | 'EXPIRED' | 'REVOKED';
  createdAt: string;
  expiresAt: string;
  targetEmailMasked: string;
  hasEmail: boolean;
  emailMatched: boolean;
  canAccept: boolean;
  canDecline: boolean;
  blockedReason:
    | 'EMAIL_REQUIRED' | 'EMAIL_MISMATCH' | 'ALREADY_MEMBER'
    | 'EXPIRED' | 'REVOKED' | 'DECLINED' | 'ACCEPTED' | 'LEDGER_UNAVAILABLE'
    | null;
}
```

`POST /invitations/:invitationId/accept` 返回 `alreadyMember`、`id`、`ledgerId`、`memberRole`、`joinedAt` 和账本摘要。

### 2.2 安全约束

- 预览、详情、列表响应均为 `Cache-Control: no-store`；前端不写入 localStorage 或持久化 store。
- 登录前预览只返回账本名、邀请人昵称、角色、状态和到期时间，不返回 `ledgerId`、成员、账单和完整邮箱。
- `token` 只出现在地址栏和请求参数，不写日志、不进错误上报、不拼进页面标题与分享文案。
- 接受成功后用 `router.replace` 清掉带 `token` 的地址。

## 3. 交互规则

### 3.1 进入页面

| 场景 | 行为 |
| --- | --- |
| 未登录 + `?token=` | 路由守卫跳登录，`redirect` 保留 `token` 与 `action`；登录成功后回到本页 |
| 已登录 + `?token=` | 直接拉详情，渲染详情卡 + 列表 |
| 已登录无 token | 只渲染列表 |
| `?action=decline` | 详情卡直接展示拒绝确认，不再需要二次跳转 |

### 3.2 响应邀请

| 动作 | 前置 | 结果 |
| --- | --- | --- |
| 接受 | `canAccept === true` | 成功进入账本；`alreadyMember=true` 时提示“已在该账本”并直接进入 |
| 拒绝 | `canDecline === true` | 成功后该项从待处理列表移除，停留本页 |
| 补全邮箱 | `blockedReason=EMAIL_REQUIRED` | 跳个人资料修改邮箱，携带回跳地址；改完回来重新拉详情 |
| 更换邮箱 | `blockedReason=EMAIL_MISMATCH` | 展示 `targetEmailMasked`，同上跳转 |
| 进入账本 | `blockedReason=ALREADY_MEMBER` | 直接进入 `ledger.id` 对应账本 |

- 同一时间只允许一个进行中的响应请求，按钮统一 loading 并禁用。
- 响应失败保留详情卡与 token，显示错误条并可重试；不把失败渲染成终态。
- 页面停留较久后响应返回 `40931`：重新拉详情，按新状态渲染终态并提示“邀请状态已变化”。

### 3.3 终态展示

| `blockedReason` / `status` | 文案与操作 |
| --- | --- |
| `EXPIRED` | 「邀请已过期」+ 请对方重新邀请 |
| `REVOKED` | 「邀请已被撤销」 |
| `DECLINED` | 「你已拒绝该邀请」 |
| `ACCEPTED` | 若已是成员则显示「已加入」并进入账本，否则「邀请已被使用」 |
| `LEDGER_UNAVAILABLE` | 「账本已不可用」 |

终态一律隐藏接受按钮，避免用户反复点击。

### 3.4 错误映射

| HTTP / code | 文案 |
| --- | --- |
| `40431` | 邀请不存在或链接已失效 |
| `40931` | 邀请状态已变化，请刷新 |
| `40031`（`action=SET_EMAIL`） | 请先补全邮箱后再处理邀请 |
| `40331`（`action=CHANGE_EMAIL`） | 当前邮箱与邀请目标不一致 |
| `42901` | 操作过于频繁，请稍后再试 |

## 4. 状态矩阵

| 状态 | 触发 | 呈现 |
| --- | --- | --- |
| 列表加载中 | `invitations` 请求中 | 列表骨架 ×3 |
| 列表为空 | `items.length === 0` 且无 token | 「暂无待处理邀请」+ 返回账本 |
| 详情加载中 | 详情请求中 | 详情卡骨架，列表照常 |
| 可响应 | `blockedReason=null` 且 `canAccept` | 接受（主）+ 拒绝（次） |
| 需补全邮箱 | `EMAIL_REQUIRED` | 说明 + 「去补全邮箱」 |
| 邮箱不匹配 | `EMAIL_MISMATCH` | 脱敏目标邮箱 + 「去更换邮箱」 |
| 已加入 | `ALREADY_MEMBER` | 「已加入」+ 「进入账本」 |
| 终态 | `EXPIRED/REVOKED/DECLINED/ACCEPTED/LEDGER_UNAVAILABLE` | 终态说明，无操作按钮 |
| 提交中 | mutation pending | 按钮 loading，全部禁用 |
| 提交失败 | 请求错误 | 错误条 + 重试，保留详情 |
| 详情加载失败 | 40431 或其他 | 说明 + 返回账本；不回退成列表假装成功 |
| 离线 | `!isOnline` | 按钮禁用 + 「当前离线，无法处理邀请」 |

## 6. 验收清单

- [ ] 未登录打开 `?token=` 链接，登录成功后回到本页且 `token` 仍在，详情卡可直接接受
- [ ] 注册新账号走同一路径，回跳后同样保留邀请上下文
- [ ] 已登录且邮箱匹配时，详情卡显示接受与拒绝，接受后进入账本
- [ ] 列表条目无需 token 即可接受/拒绝，成功后列表即时更新
- [ ] `EMAIL_REQUIRED` 显示补全邮箱入口，改完邮箱返回后可直接响应
- [ ] `EMAIL_MISMATCH` 展示脱敏目标邮箱，不展示完整邮箱
- [ ] `ALREADY_MEMBER` 显示“已加入”并可直接进入账本，不重复创建成员
- [ ] 过期/撤销/拒绝/已接受均展示终态且无接受按钮
- [ ] 重复点击接受只发出一次有效请求，不产生第二条成员关系
- [ ] 响应返回 `40931` 时重新拉详情，不把错误渲染成成功
- [ ] 成功后地址栏不再保留 `token`
- [ ] 页面在 iOS Safari 与 Android Chrome 均可滚动、按钮不被安全区遮挡
