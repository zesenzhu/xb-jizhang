# 一期页面与交互设计

## 1. 页面结构总览

```text
/user                             账单页（改造自现有首页）
├── LedgerTopBar                  账本名 · 月份切换 · 收支日历入口
├── MonthSummaryCard              总支出 / 总收入 / 结余
├── BillSearchBar                 关键词搜索 + 筛选入口 + 生效条件标签
├── BillGroupList                 按账单日分组
│   └── BillDayCard               日期 + 星期 + 当日合计 + 账单行
│       └── BillRow               图标 分类 时间·备注 金额
├── BillListFooter                加载更多 / 到底提示
├── CreateBillFab                 右下角悬浮入口（有权限时）
└── BillCreateSheet               记账抽屉（按需挂载）
    ├── SheetTypeSegment          支出 / 收入
    ├── SheetCategoryGrid         分类九宫格
    ├── SheetAmountDisplay        金额与币种
    ├── SheetMetaFields           时间 / 账户 / 商家 / 付款人 / 备注
    └── SheetKeypad               数字键盘 + 双提交键
```

`/user/ledger`、`/user/ledger/new`、`/user/profile` 保持现状，不参与本期改造。

## 2. 账单页 `/user`

### 2.1 顶部账本栏

| 元素 | 行为 | 数据来源 |
| --- | --- | --- |
| 账本名 | 点击打开账本切换面板（复用 `LedgerList` 的列表区，改为底部面板形态） | `getLedgers()` |
| 左箭头 | 上一月，跨年时年份随之变化 | 本地月份状态 |
| 右箭头 | 下一月，不允许超过当前月 | 本地月份状态 |
| 月份文案 | `YYYY年M月` | 本地月份状态 |
| 收支日历 | 一期渲染为禁用态胶囊，点击提示「即将上线」 | — |

账本只有 1 个时仍显示名称，切换入口点击后只有 1 项，不隐藏（需求 5.1 要求「仅有一个可用账本时仍显示当前账本名称」）。

### 2.2 概览卡

深色卡，与参考截图一致的信息层级：

```text
总支出 ¥170.32                    ← 主视觉，font-black
总收入 ¥0.00    月结余 -¥170.32    ← 次级，text-white/60 标签 + 白色数值
```

- 三个数值全部来自当前筛选结果，不是全量。
- 处于筛选状态时，卡片右上角追加「筛选结果」胶囊。
- 数据为 0 时显示 `¥0.00`，不显示占位符。
- 卡内数值随筛选或月份变化刷新，不做乐观更新。

### 2.3 搜索与筛选

搜索框位于概览卡下方（与截图一致），输入不触发请求；点击键盘确认或搜索图标才提交。筛选入口打开底部筛选面板，参数见 `数据层与状态设计.md` 第 5 节。

已生效条件以胶囊形式横向滚动展示，每项可单独移除，末尾固定「清除全部」。

### 2.4 日期分组卡

```text
11/02 星期一                              支出: ¥45.70  ⌄
┌─────────────────────────────────────────────────┐
│ [餐饮] 餐饮                                     -¥16.80 │
│        22:20 · 晚饭                                     │
├─────────────────────────────────────────────────┤
│ [餐饮] 餐饮                                     -¥20.00 │
│        12:14 · 猪脚饭                                   │
└─────────────────────────────────────────────────┘
```

- 日期文案：当年显示 `MM/DD`，跨年追加年份；今天与昨天分别加「今天」「昨天」前缀。
- 右侧当日合计：点击折叠/展开该组，默认展开。同时有收支时显示「支出: ¥x  收入: ¥y」。
- 账单行：分类图标（圆形）、分类名、`HH:mm · 标题或备注`、右对齐金额。
- 标题与备注都为空时只显示时间，不显示占位文案。
- 金额：支出前缀 `-`，收入前缀 `+`，颜色分别取 `text-financial-expense` / `text-financial-income`。不单靠颜色区分（符号已表达）。

### 2.5 分页加载

- 首屏取 `page=1&pageSize=30`。
- 列表底部 `IntersectionObserver` 触发下一页；到底后显示「没有更多账单」。
- 加载中在列表底部显示 2 行骨架，不清空已有数据。
- 切换月份、账本或筛选条件时重置为第 1 页并回到顶部。

### 2.6 状态矩阵

| 状态 | 触发条件 | 呈现 |
| --- | --- | --- |
| 首次加载 | 无缓存且请求中 | 概览卡骨架 + 3 组日期卡骨架 |
| 有数据 | `items.length > 0` | 正常渲染 |
| 空账本 | `total === 0` 且无筛选条件 | 「还没有账单」+ 说明 + 有权限时引导点击右下角 |
| 筛选无结果 | `total === 0` 且有筛选条件 | 「没有符合条件的账单」+ 清除筛选按钮，保留输入 |
| 加载失败 | 请求错误且无缓存 | 错误文案 + 重试按钮，保留顶部筛选条件 |
| 分页失败 | 后续页请求错误 | 列表底部「加载失败，点击重试」，已有数据不清空 |
| 无创建权限 | `memberRole === 'VIEWER'` | 不渲染 FAB；空态引导改为「联系账本所有者」 |
| 离线 | `navigator.onLine === false` | 顶部提示条「当前离线，无法查看最新账单」；FAB 保留但点击后提示不可用 |

### 2.7 与现有实现的衔接

当前 `/user` 页的深色账本卡继续复用其视觉，但内容替换为概览；卡片内原有的「管理我的账本 / 新建账本」两个按钮移除（账本管理入口移到账本切换面板），`AmountKeypad` 区块整体移入记账抽屉。

`SyncStatusBar` 顶部条保留，`isOnline` 改由真实的 `online`/`offline` 事件驱动（当前 `useAppStore.isOnline` 恒为 `true`）。

## 3. 记账抽屉

### 3.1 结构

```text
┌───────────────────────────────────────┐
│ ✕                    支出 收入       账本名 │  ← 顶栏
├───────────────────────────────────────┤
│  [🍜] [🛒] [👕] [🧴] [📱]             │  ← 分类九宫格
│  [💄] [🧖] [📲] [🏠] [🚌]             │     可上下滚动
│  ...                                  │
├───────────────────────────────────────┤
│ 选择账户  报销  优惠  图片  标签   ⚙    │  ← 快捷字段条（本期仅账户可用）
├───────────────────────────────────────┤
│ ¥ 0.00                                │  ← 金额
│ 🕐 19:02  点击填写备注              ⌃  │  ← 时间 + 备注
├───────────────────────────────────────┤
│  1   2   3   ＋×                     │
│  4   5   6   －÷                     │  ← 运算键一期不实现，改为退格
│  7   8   9   保存再记                  │
│  .   0   ⌫   完成                     │
└───────────────────────────────────────┘
```

与截图差异：右侧「＋× / －÷」改为「退格」，因需求 7.7 只要求数字、小数点、退格、清空四种操作；`保存再记` 即需求的「保存并继续」。

### 3.2 交互规则

| 场景 | 行为 |
| --- | --- |
| 打开 | 从底部滑入，高度约视口 88%，顶部留出账单页上下文；遮罩 `bg-black/40` |
| 关闭（无内容） | ✕ 或遮罩直接关闭 |
| 关闭（有内容） | 弹确认「放弃本次记账吗」，两个操作：继续填写 / 放弃 |
| 类型切换 | 支出 ⇄ 收入，**清空已选分类**，保留金额、时间、备注、账户、商家 |
| 分类选择 | 点击分类格进入分类面板；一级分类有二级时展开选择；无二级直接选中 |
| 时间选择 | 点击时间打开日期时间选择；选未来时间时禁止提交并高亮该字段 |
| 保存 | 校验通过 → 创建 → `invalidateQueries` → 关闭抽屉 → 列表滚动到顶部 |
| 保存并继续 | 创建成功 → 清空金额、商家、备注 → 保留类型、时间、分类、账户 → 保持打开 |
| 提交中 | 完成键显示 loading，两个提交键同时禁用 |
| 提交失败 | 保留全部输入，抽屉内顶部显示错误条，可重试 |

### 3.3 校验时机

- 金额：由键盘输入天然约束（两位小数、非负）；为 0 时完成键禁用并显示「请输入金额」。
- 分类：未选时点击完成，滚动到分类区并高亮描边 + 提示「请选择分类」。
- 时间：未来时间即时提示，不等到提交。
- 备注：超过 200 字即时截断并提示。

### 3.4 分类选择面板

底部第二层抽屉，覆盖在记账抽屉之上：

```text
✕                     交通                      ⊞
─────────────────────────────────────────────
[🚌] 交通                                    ›
[🚕] 交通-打车                                ›
[🚇] 交通-地铁                                ›
```

- 按一级分类分组，点击一级展开其二级；已有二级的一级行右侧显示 `›`。
- 顶部一级分类可横向切换（截图右上角 `⊞` 位置），一期简化为返回上一级。
- 无二级的分类点击即选中并关闭面板。
- 二级分类选中后关闭面板，抽屉分类字段显示 `交通-打车`。
- 停用分类不出现（依赖后端 `isActive` 过滤）。

### 3.5 记账抽屉表单状态

不使用全局 store，用 `useReducer` 在抽屉组件内部管理：

```text
{ type, amountText, categoryId, occurredAt, accountId, title, note, payerId, isDirty, submitting, error }
```

`isDirty` 用于关闭确认判断：金额非 `0`、已选分类、或商家/备注非空时置 `true`。

## 4. 账单详情

一期采用底部面板而非独立页面，避免破坏返回后的滚动位置（需求 6.3）：

- 顶部：类型徽标 + 金额（大号）
- 中部：分类、发生时间、账户、商家、备注、实际付款人
- 底部：记账人、最后修改人、创建时间、更新时间
- 操作区：编辑（`OWNER`/`EDITOR`）、删除（`OWNER` 或本人创建的 `EDITOR`）

编辑在抽屉内完成，字段规则与新建一致，额外携带 `version`。版本冲突时展示：

```text
账单已更新
其他成员刚刚修改了这条账单，请查看最新内容后重新编辑。
[查看最新内容]
```

确认后刷新详情并退出编辑态，不静默覆盖。

删除确认展示金额、类型和日期；成功后列表项移除并显示 5 秒撤销入口（是否交付取决于后端 B4）。

## 5. 视觉规范落地

### 5.1 布局约束

- 内容宽度 `max-w-md mx-auto`，与现有页面一致。
- 页面底部预留 `pb-24`（底栏高度）并叠加 `env(safe-area-inset-bottom)`。
- FAB 定位：`fixed right-4 bottom-[calc(5rem+env(safe-area-inset-bottom))]`，`z-30`，位于底栏（`z-40`）之下不被遮挡，但需实测确认不压住最后一行账单。

### 5.2 颜色

只使用 `globals.css` 的语义 token：

| 用途 | 类名 |
| --- | --- |
| 页面背景 | `bg-app-bg` |
| 卡片 | `bg-app-card` |
| 概览深色卡 | `bg-app-card-elevated` 需扩展暗色值，或沿用现有 `bg-[#16181d]` 并抽成 token |
| 主色 / 强调 | `text-primary` / `bg-primary` |
| 支出金额 | `text-financial-expense` |
| 收入金额 | `text-financial-income` |
| 次要文字 | `text-text-muted` |

禁止新增 `text-ios-blue`、`animate-in` 一类未定义类名。

### 5.3 动效

- 抽屉：`translate-y` 过渡 240ms `ease-out`。
- 列表项删除：高度与透明度过渡 180ms。
- 不为保留类名而安装 `tailwindcss-animate`，改用 CSS `transition` 与 `@keyframes`。

## 6. 无障碍要求

- 抽屉打开时焦点进入抽屉，关闭后归还触发按钮。
- 抽屉与详情面板使用 `role="dialog"` + `aria-modal="true"` + `aria-labelledby`。
- 所有图标按钮提供 `aria-label`。
- 金额键盘的每个按键为 `<button type="button">`，可用 Tab 遍历。
- 颜色不是唯一信息载体：收支有正负号，错误有文字，离线有文本提示。

## 7. 与现有路由守卫的衔接

新增 `/user` 账单页仍属于一级 Tab（`USER_PRIMARY_TAB_ROUTES['/user'] = 'home'`），保留底栏与 `pb-24`。

`UserAuthBoundary.resolveRouteSkeleton` 中 `/user` 走默认分支 `UserHomeSkeleton`，本期需把该骨架改为账单页骨骼（概览卡 + 日期组），避免加载完成后布局跳动。

`routes.contract.test.ts` 对一级 Tab 映射有断言，改动 `USER_PRIMARY_TAB_ROUTES` 必须同步更新测试。
