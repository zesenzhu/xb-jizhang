# 分类管理

记账面板内对账本分类做增、改、停用。入口在分类九宫格末尾的「+」格子与选分类标题右侧的「管理」。

## 1. 与后端能力的对齐

`docs/api/账户与分类接口.md` 与 `category.controller.ts` 当前只提供三个写操作，**没有物理删除**：

| 操作 | 接口 | 角色 | 说明 |
| --- | --- | --- | --- |
| 查询 | `GET /ledgers/:id/categories` | 成员 | 默认只返回启用分类；`includeInactive=true` 仅 `OWNER` |
| 新建 | `POST /ledgers/:id/categories` | `OWNER` | `type` 必填，`parentId` 可为空 |
| 编辑/排序 | `PATCH /ledgers/:id/categories/:categoryId` | `OWNER` | 可改 `name` / `parentId` / `sortOrder` / `icon` / `color` / `isActive` |
| 停用 | 同上，`isActive: false` | `OWNER` | 被账单引用的分类只能停用 |
| 物理删除 | — | — | **不提供**：历史账单需要保留分类关联，系统默认分类也不允许删 |

因此前端的「删除」语义是**停用**，不是硬删。UI 文案统一用「停用」，不写「删除」。

### 1.1 后端强制的约束

这些是服务端校验，前端只做前置提示，不作为安全边界：

- 最多两级：`parentId` 必须指向同账本、同类型、启用中的一级分类
- 一级分类改名后不能与其子分类重名（`@@unique([ledgerId, type, parentId, name])`，一级部分索引另算）
- 有启用中子分类的一级分类不能停用（`请先停用子分类`）
- 已经拥有子分类的一级分类不能挂到别人下面
- 重名返回 `40921`

### 1.2 为什么「新增分类」入口出现在空账本里

`DEFAULT_CATEGORIES` 只在**新建账本**时初始化，历史账本不会被自动补齐（迁移 `20261104120000_category_hierarchy` 只加字段，不回填数据）。所以老账本、或分类被全部停用后，会出现「当前账本还没有可用的分类」——这正是需要「+」入口的场景。

## 2. 页面结构与布局

### 2.1 九宫格内的新增格子

```text
选择支出分类                    管理
┌────┬────┬────┬────┬────┐
│ 餐饮│ 交通│ 购物│ ... │ ＋ │   ← 第 6 格起循环，＋ 固定排最后
└────┴────┴────┴────┴────┘
```

- 「＋」只在 `canManage`（`OWNER`）时渲染
- 空态时整个九宫格替换为「还没有分类」+「新增分类」按钮
- 点击「＋」打开 `CategoryEditorSheet`（新建态）

### 2.2 分类编辑面板

`layer="nested"`，叠在记账面板之上：

```text
✕                    新增分类
────────────────────────────────
名称        [___________________]
归类        ○ 一级分类  ● 归到「餐饮」
────────────────────────────────
排序        [0        ]  小的在前
────────────────────────────────
        [取消]        [保存]
```

- 新建时默认一级分类；选择归到某个一级时，该一级分类的选择器只列**启用中的一级分类**，排除自身（编辑态）
- 名称长度 `1–50`，前后空格丢弃
- 排序非负整数，默认 `0`

### 2.3 分类管理面板

```text
✕                    管理支出分类
────────────────────────────────
餐饮            5 个子类      编辑 ⌄
  早餐                         编辑
  午餐                         编辑
交通            4 个子类      编辑 ⌄
────────────────────────────────
       [显示已停用]  [＋ 新增分类]
```

- 列出启用分类；「显示已停用」勾选后追加已停用项（`includeInactive=true`）
- 每个一级分类右侧「编辑」进入编辑态，可改名/排序/停用
- 停用按钮在编辑态底部，已有启用子分类时禁用并说明原因

## 3. 数据来源

| 用途 | 接口 | 缓存键 | staleTime |
| --- | --- | --- | --- |
| 分类列表 | `GET /ledgers/:id/categories` | `['ledger',id,'categories']` | 5min |
| 含停用列表 | 同上 + `includeInactive=true` | 独立键，避免与记账用的启用列表互相污染 | 5min |
| 新建 | `POST /ledgers/:id/categories` | 成功后失效 `['ledger',id,'categories']` 全部 | — |
| 编辑/停用 | `PATCH /ledgers/:id/categories/:categoryId` | 同上 | — |

**失效范围要含前缀**：记账抽屉、分类管理、统计页都读同一个键，改完必须让三处同时刷新，否则用户会看到「刚建的分类在记账面板里选不到」。

## 4. 交互规则

| 场景 | 行为 |
| --- | --- |
| 点击「＋」 | 打开新建态，类型继承当前支出/收入分段 |
| 名称留空 | 保存键禁用，不弹错误 |
| 名称与同级重复 | 保存后 `40921` → 输入框下方提示「同级已有同名分类」 |
| 归属选择 | 只列同类型、启用中的一级分类，不含自身 |
| 保存成功 | 关闭面板，九宫格立即出现新分类，自动选中 |
| 编辑已停用分类 | 允许改名与重新启用 |
| 停用有启用子分类的一级分类 | 按钮禁用 + 「请先停用子分类」 |
| 非 `OWNER` | 不渲染「＋」与「管理」；直接调接口返回 `40321` |
| 离线 | 保存键禁用 + 「当前离线」 |

## 5. 状态矩阵

| 状态 | 触发 | 呈现 |
| --- | --- | --- |
| 空账本 | 启用分类为 0 | 「还没有分类」+「新增分类」 |
| 加载中 | 列表请求中 | 九宫格骨架 |
| 加载失败 | 请求错误 | 「分类加载失败」+ 重试 |
| 保存中 | 请求进行中 | 保存键 loading，取消键禁用 |
| 重名 | `40921` | 输入框下方红色提示，保留输入 |
| 权限不足 | `40321` | 「只有账本所有者可以管理分类」 |
| 已有子分类 | 停用一级 | 停用键禁用 + 说明 |

## 6. 组件清单

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| `CategoryEditorSheet` | `components/bill/CategoryEditorSheet.tsx` | 新建/编辑表单：名称、归属、排序、停用 |
| `CategoryManageSheet` | `components/bill/CategoryManageSheet.tsx` | 分类树列表 + 显示已停用 + 编辑入口 |

### 纯函数

`lib/bill/category-manage.ts`：

- `validateCategoryName(name)` — 去空格、长度、空值
- `parentOptions(nodes, editingId)` — 可作为父级的候选（排除自身）
- `canDeactivateCategory(node)` — `{ ok, reason }`
- `sortCategories(items)` — 与后端同口径：`sortOrder asc, name asc`

## 8. 已知降级

| 项 | 降级 | 解除条件 |
| --- | --- | --- |
| 图标 / 颜色 | 不提供选择，沿用名称哈希色板；后端字段可透传 | 设计出图标选择器 |
| 拖拽排序 | 用数字 `sortOrder` 手填 | 需要拖拽组件 |
| 物理删除 | 只能停用 | 后端提供 `DELETE` 且允许无引用分类硬删 |
| 历史账本补默认目录 | 需手动新增 | 后端提供 backfill 脚本 |
