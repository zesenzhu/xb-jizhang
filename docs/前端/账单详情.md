# 账单详情

从账单页点击账单行打开的底部面板，包含详情展示、编辑与删除。

## 1. 页面结构与布局

```text
┌───────────────────────────────────────┐
│ ✕              账单详情                │
├───────────────────────────────────────┤
│          支出  -¥16.80                 │  ← 类型徽标 + 大号金额
│              餐饮                       │
├───────────────────────────────────────┤
│ 发生时间     2026-11-02 22:20          │
│ 账户         微信                       │
│ 商家/对象    晚饭                       │
│ 备注         —                          │
│ 实际付款人   宝哥                       │
├───────────────────────────────────────┤
│ 记账人       小宝                       │
│ 最后修改     宝哥 · 11-03 09:12         │
│ 创建时间     11-02 22:21                │
│ 更新时间     11-03 09:12                │
├───────────────────────────────────────┤
│  [删除]                        [编辑]   │
└───────────────────────────────────────┘
```

`layer='base'`（`z-50`）。操作区按权限显隐，无权限时不渲染按钮。

编辑态在本面板内切换为表单，结构与记账抽屉一致（分类、金额、时间、账户、商家、备注），额外携带 `version`。

## 2. 数据来源

| 用途 | 接口 | 缓存 |
| --- | --- | --- |
| 详情 | `GET /ledgers/:id/transactions/:tid` | 不缓存（staleTime 0） |
| 成员昵称 | `GET /ledgers/:id/members` | `['ledger',id,'members']`，5min |
| 编辑 | `PATCH /ledgers/:id/transactions/:tid` | 成功后失效详情与列表 |
| 删除 | `DELETE /ledgers/:id/transactions/:tid` | 成功后失效列表 |

详情不缓存：编辑后必须立即看到新值，且共享账本中他人可能随时修改。

### 2.1 字段映射

| 展示项 | 来源 | 缺失处理 |
| --- | --- | --- |
| 类型与金额 | `type` + `amountCents` | 必填 |
| 分类 | `category.name` | 必填 |
| 发生时间 | `occurredAt`，按账本时区格式化 | 必填 |
| 账户 | `account.name` | 未填 → 整行不渲染 |
| 商家/对象 | `title` | 空 → 整行不渲染 |
| 备注 | `note` | 空 → 整行不渲染 |
| 实际付款人 | `payer.nickname`，回退 `payerId` 查成员表 | 仅支出且填写时渲染 |
| 记账人 | `createdById` 查成员表 | 查不到显示「未知成员」 |
| 最后修改 | `updatedById` + `updatedAt` | 同上 |
| 创建时间 | `createdAt` | 必填 |

后端 `transactionSelect` 只返回 `createdById` / `updatedById` 裸 ID（缺口 D3），昵称靠成员表映射。

### 2.2 时间展示

发生时间按账本时区格式化，与账单页分组口径一致。创建/更新时间同。

一期时区硬编码 `Asia/Shanghai`（缺口 B3），常量集中在 `lib/bill/timezone.ts`。

## 3. 交互规则

### 3.1 编辑

| 场景 | 行为 |
| --- | --- |
| 进入编辑 | 预填全部可编辑字段，携带当前 `version` |
| 取消编辑 | 回到只读态，不发起请求 |
| 保存成功 | 详情、列表、日合计、概览全部刷新；回到只读态 |
| 保存失败（普通错误） | 保留输入，面板内显示错误条，可重试 |
| 版本冲突 `40922` | 见 3.2 |

可编辑字段：类型、金额、发生时间、分类、账户、商家、备注、付款人。不可编辑：`ledgerId`、`createdById`、`clientRequestId`、`source`。

### 3.2 版本冲突处理

```text
账单已更新
其他成员刚刚修改了这条账单，请查看最新内容后重新编辑。
[查看最新内容]
```

点击后刷新详情、退出编辑态、展示最新值。**不静默覆盖**他人修改（需求 8.2）。

### 3.3 删除

| 场景 | 行为 |
| --- | --- |
| 权限 | `OWNER` 可删任意；`EDITOR` 仅可删 `createdById === 当前用户` 的账单；`VIEWER` 无入口 |
| 确认 | 弹窗展示金额、类型、日期 |
| 成功 | 面板关闭，列表项移除，显示 5 秒撤销入口 |
| 重复删除 | 返回原结果（后端已幂等），前端不报错 |
| 删除后编辑 | 不允许，详情返回 `40421` 时提示「账单已被删除」并关闭面板 |

删除权限在后端由 `transaction.service.ts` 的 `remove` 判定（`VIEWER` 拒绝、`EDITOR` 仅自己创建），前端入口显隐只是一致性体验，不作为安全边界。

### 3.4 撤销删除（依赖 B4）

后端无 `RESTORE` 接口（缺口 B4）。**一期降级：不做撤销，删除后直接 Toast 提示「已删除」。**

若后端补齐 `POST /transactions/:id/restore`，则改为：

```text
Toast[action]('已删除', { label: '撤销', onClick: () => restore(id), duration: 5000 })
```

5 秒后 Toast 消失即视为最终删除。

## 4. 状态矩阵

| 状态 | 触发 | 呈现 |
| --- | --- | --- |
| 加载中 | 详情请求中 | 顶部骨架条 + 字段骨架 |
| 只读态 | 加载完成 | 字段列表 + 操作区 |
| 编辑态 | 点击编辑 | 表单替换字段区，操作区变为「取消 / 保存」 |
| 保存中 | 提交中 | 保存键 loading，取消键禁用 |
| 冲突态 | `40922` | 冲突提示条 + 「查看最新内容」 |
| 已删除 | `40421` | 「账单已被删除」+ 关闭 |
| 无编辑权限 | `VIEWER` | 不渲染编辑/删除按钮 |
| 提交失败 | 其他错误 | 错误条 + 输入保留 |

## 6. 错误码映射

| HTTP | code | 前端表现 |
| --- | --- | --- |
| 403 | 40321 | 「当前成员没有该操作权限」 |
| 404 | 40421 | 「账单不存在或已被删除」，关闭面板并刷新列表 |
| 409 | 40922 | 版本冲突，展示冲突提示条 |
| 5xx | 50001 | 「服务暂时不可用，请稍后重试」，保留输入 |

文案优先取 `ApiRequestError.message`，为空时用上表兜底。
