# 小宝记账第五期前端实施设计

## 1. 文档定位

本文是第五期前端实现的总控文档。它负责把产品需求、API 契约和页面设计连接起来，记录前端的数据模型、组件边界、缓存策略、状态处理、测试范围和实施顺序。

分类图标选择和统计图表交互分别维护页面细节；出现冲突时，本文负责说明跨页面的共同约束，接口字段以对应 API 文档和实际 DTO 为准。

## 2. 现状与问题

### 2.1 当前已经具备

- `/user` 已有分类选择、分类管理、账单列表、账单详情和附件查看能力。
- `/user/statistics` 已有概览、趋势、分类统计和周期汇总四个模块。
- 统计查询已经按模块使用独立 React Query key，时间范围和账单下钻使用服务端返回的 UTC 半开区间。
- `BillRow` 保留分类 Icon，附件只显示回形针数量；附件图片在账单详情中查看，不占用分类 Icon 的位置。
- `CategoryIcon` 当前支持颜色背景和名称首字降级，但还没有渲染图标库键和图片资源。

### 2.2 本期需要补齐

| 领域 | 当前问题 | 第五期处理 |
| --- | --- | --- |
| 分类图标数据 | 前端仍主要使用 `icon` 字符串和首字降级 | 对齐 `iconSource`、`iconKey`、`iconAssetId`、`iconUrl`、`color` |
| 分类图标编辑 | `CategoryEditorSheet` 没有图标库和图片上传入口 | 新增临时表单选择、上传、确认、重试和恢复默认 |
| 跨页面展示 | 记账、账单、统计各自处理图标 | 使用同一个 `CategoryIcon` 渲染契约 |
| 趋势图 | 主要依赖 SVG `<title>`，移动端无法稳定查看详情 | 增加点击、键盘聚焦和 Tooltip |
| 环形图 | 没有“其他”聚合，中心金额长文本可能溢出 | 前端聚合、中心布局约束和 Tooltip |
| 统计下钻 | 图表交互反馈不完整 | Tooltip 提供明确下钻入口，继续复用现有 URL 构造器 |

## 3. 推荐方案

### 3.1 统一分类图标渲染器

所有页面只调用一个渲染器，不根据分类名称猜测图标：

```ts
interface CategoryIconDescriptor {
  name: string;
  iconSource: 'NONE' | 'LIBRARY' | 'IMAGE';
  iconKey: string | null;
  iconAssetId: string | null;
  iconUrl: string | null;
  iconUrlExpiresAt: string | null;
  color: string | null;
}
```

降级顺序固定为：

1. `IMAGE` 且图片加载成功时显示图片；
2. `LIBRARY` 且 `iconKey` 在前端受控映射表中时显示 Tabler 图标；
3. 使用 `color` 背景和分类名称首字；
4. 使用固定默认图标和中性颜色。

图标容器必须有稳定尺寸和 `shrink-0`。图片加载失败只影响当前图标，不影响分类名称、金额、账单列表或统计模块。

### 3.2 图标库依赖与安全边界

用户端系统操作图标继续使用 `lucide-react`；分类图标使用 Tabler 精选子集。前端维护稳定键到组件的显式映射：

```text
tabler:tools-kitchen-2 -> ToolsKitchen2
tabler:bus             -> Bus
tabler:wallet          -> Wallet
```

不允许把服务端返回的字符串直接当作组件名或动态模块路径。图标键不存在时直接走降级，不阻塞整个分类列表。

推荐引入固定版本的 `@tabler/icons-react`，并把可用键、中文名称、英文别名和分组维护在独立的前端注册表中。后端默认分类常量与该注册表必须通过接口契约测试校验，避免默认分类保存了前端无法渲染的键。

### 3.3 分类图片读取与缓存

- 分类列表和统计分类项可以携带短期 `iconUrl`，但前端不持久化签名 URL。
- `iconUrlExpiresAt` 到期或图片加载失败时，通过分类图标读取地址接口重新获取。
- 读取请求使用 React Query 或轻量请求协调器按 `ledgerId + iconAssetId` 去重，避免一个页面为同一图片发出多个请求。
- 第一版不新增分类图标专用 IndexedDB Blob 缓存。分类图标体积小、更新频率低，先使用浏览器 HTTP 缓存和短期 URL；离线时使用已有分类数据和首字降级。
- 账本切换、退出登录和成员失效时，清理当前图标读取状态，不能短暂展示上一个账本的图片。

### 3.4 图片上传流程

```text
选择文件
  -> 客户端校验 MIME、大小和图片预览
  -> 创建上传会话
  -> 使用 requiredHeaders 执行 PUT
  -> 调用 complete 确认
  -> 保存分类并提交 iconAssetId
```

上传会话、PUT、完成确认和分类保存必须是四个可观察状态。上传完成不代表分类已经保存成功；分类保存失败时保留表单内容，并允许重新提交或放弃绑定。关闭面板时撤销本地预览 URL，未绑定资源由服务端清理任务负责回收。

## 4. 页面与组件实施范围

### 4.1 分类选择和记账抽屉

| 位置 | 改动 | 规则 |
| --- | --- | --- |
| `CategoryGrid` | 接收统一图标描述 | 支出/收入分类都按服务端图标显示 |
| `CategoryIcon` | 扩展图标库、图片和降级 | 固定尺寸，不因图片加载改变九宫格布局 |
| 记账表单 | 复用分类对象 | 只记录分类 ID，不把图标展示值写入账单 payload |
| 离线账单 | 保存分类展示快照 | 快照包含图标描述，图标失效时仍能用首字显示 |

分类 Icon 只服务于视觉识别；分类选择、账单创建和离线同步仍以 `categoryId` 为唯一业务字段。

### 4.2 分类管理

`CategoryEditorSheet` 增加图标区域：当前预览、图标库、上传图片、恢复默认。选择过程只更新本地表单，不直接修改 React Query 缓存。

权限边界：只有 `OWNER` 显示编辑入口并调用上传、恢复和分类写接口；`EDITOR` 和 `VIEWER` 不显示入口，直接调用接口仍由后端返回权限错误。

保存分类时提交字段必须满足互斥关系：

| `iconSource` | 前端提交 |
| --- | --- |
| `NONE` | `iconKey: null`、`iconAssetId: null` |
| `LIBRARY` | 合法 `iconKey`、`iconAssetId: null` |
| `IMAGE` | `iconKey: null`、已确认的 `iconAssetId` |

前端可以提前校验，服务端校验仍是最终安全边界。

### 4.3 账单列表和详情

- 账单列表的分类 Icon 始终显示分类图标，不用附件图片替换分类 Icon。
- 账单列表只显示附件数量提示；附件原图在账单详情的附件画廊中展示。
- 账单详情中的分类名称、分类 Icon 和附件互相独立，任一图片读取失败都不能隐藏账单事实字段。
- 分类被停用、图标被替换或图片资源被清理后，历史账单使用当前分类图标或统一降级图标。

### 4.4 统计页

统计页继续由四个模块组成：概览、趋势、分类和周期汇总。第五期只改变图表交互和分类视觉，不改变统计口径、金额分、账本时区和下钻参数。

#### 趋势图

- 服务端一次返回 `expenseCents`、`incomeCents`、`netCents` 和 `transactionCount`。
- 指标 Tab 只改变当前渲染值和颜色，不重复请求。
- 点击柱、键盘聚焦或桌面悬停显示 Tooltip；移动端不依赖 hover。
- Tooltip 显示完整金额和账单数；下钻使用服务端 `drilldown.from/to`。
- `transactionCount=0` 时不显示下钻按钮。

#### 分类环形图

- 服务端返回完整分类明细，前端按金额降序保留前 8 项，其余合并为“其他”。
- “其他”只存在于图表视图，没有分类 ID，不允许跳转到虚假的分类账单。
- 分类列表仍展示完整明细；图表、进度条、列表和 Tooltip 使用同一个颜色与图标描述。
- 点击扇区、键盘聚焦或列表行打开 Tooltip，普通分类显示分类下钻入口。
- 中心金额使用稳定的容器尺寸，长金额允许缩小或换行，不压出环形图边界。

## 5. 数据与缓存契约

### 5.1 分类数据

分类列表、分类创建/编辑响应和统计分类项应使用同一套字段：

```text
iconSource
iconKey
iconAssetId
iconUrl
iconUrlExpiresAt
color
```

前端类型必须同时更新 `CategorySummary` 和 `CategoryItem`。旧的 `icon` 字段只作为迁移兼容字段，不能作为新的渲染决策入口。

### 5.2 查询键

| 数据 | 推荐缓存键 | 失效时机 |
| --- | --- | --- |
| 分类列表 | `['ledger', ledgerId, 'categories']` | 分类新增、编辑、停用、恢复默认 |
| 图标库 | `['ledger', ledgerId, 'category-icon-library', type, query]` | 图标库版本变化或手动重试 |
| 图片读取地址 | `['ledger', ledgerId, 'category-icon-access', assetId]` | URL 过期、读取失败、账本切换 |
| 趋势 | `['ledger', ledgerId, 'statistics', 'trend', scope]` | 时间范围或公共筛选变化 |
| 分类统计 | `['ledger', ledgerId, 'statistics', 'categories', query]` | 时间范围、类型、层级或公共筛选变化 |

趋势 `metric` 不进入查询键，前提是接口稳定返回三个金额字段；分类 `type`、层级和根分类必须进入分类统计键。

### 5.3 下钻契约

前端只传递服务端返回的下钻区间：

```text
startAt/endAt + type + categoryRootId 或 categoryId 或 uncategorized
```

不使用浏览器时区重新计算日期，不把“其他”转换成不存在的分类 ID，不重复在前端聚合金额后再发起下钻请求。

## 6. 状态矩阵

| 状态 | 分类图标 | 分类编辑 | 趋势/环形图 |
| --- | --- | --- | --- |
| 首次加载 | 固定尺寸骨架或降级占位 | 固定表单骨架 | 固定高度骨架 |
| 空数据 | 首字和中性颜色 | 空图标选择结果 | 空环/空趋势，不绘制假数据 |
| 图片加载失败 | 颜色 + 首字 | 保留当前选择，提示重试 | 不影响金额和分类名称 |
| 图标库失败 | 保留当前图标，提供重试 | 不清空已填写表单 | 不影响统计数据 |
| 上传中 | 显示进度，禁止重复提交 | 保留取消/关闭确认 | 不触发统计刷新 |
| 分类保存失败 | 保留表单和预览 | 面板不关闭，显示可恢复错误 | 不清空旧统计 |
| 统计请求失败 | 不影响分类页面 | 不影响编辑内容 | 模块级错误和重试，保留范围 |
| 离线 | 使用已有数据和降级图标 | 禁止上传和保存 | 使用缓存或显示数据不可用 |
| 无权限 | 不显示敏感图片 | 不显示写入口 | 说明账本不可访问，不展示旧账本数据 |
| 切换账本 | 清理旧图标读取状态 | 丢弃未保存临时选择 | 清理旧 Tooltip、选中项和旧图表 |

## 7. 组件边界

```text
components/
├── bill/
│   ├── CategoryIcon.tsx              统一展示与降级
│   ├── CategoryIconPickerSheet.tsx   图标库选择
│   ├── CategoryIconUpload.tsx        图片选择、PUT、complete
│   ├── CategoryEditorSheet.tsx       分类表单编排
│   └── CategoryGrid.tsx              记账分类选择
├── statistics/
│   ├── TrendChart.tsx                趋势图和数据点交互
│   ├── CategoryDonut.tsx             环形图和分类扇区交互
│   ├── StatisticsTooltip.tsx         统一 Tooltip 内容和定位
│   └── CategoryRow.tsx                分类图标、金额和下钻
└── common/
    └── CategoryIconDescriptor.ts      跨页面类型与降级纯函数
```

组件不直接拼接 OSS/MinIO 地址，不直接操作 Prisma 字段，不在 UI 层修改统计金额。HTTP 请求、上传队列、图标 URL 读取和金额格式化分别放在 `lib/api`、`lib/bill`、`lib/statistics` 或对应的纯函数模块中。

## 8. 测试计划

### 8.1 纯逻辑与 API 契约

- `category-icon.ts`：来源互斥、渲染优先级、无效键降级、图片 URL 过期判断。
- `category-icon-library.test.ts`：中文搜索、英文别名、白名单键和空结果。
- `statistics-chart.test.ts`：前 8 项聚合“其他”、占比、金额分格式和零数据。
- `statistics-drilldown.test.ts`：普通分类、一级分类、二级分类、未分类和“其他”不生成错误参数。
- API contract：上传会话、PUT 的方法/headers/body、complete、读取地址、分类保存 payload 和错误处理。

### 8.2 组件与流程

- `CategoryIcon`：图标库、图片成功、图片失败、颜色首字和默认图标。
- `CategoryEditorSheet`：Owner 可编辑，非 Owner 无入口，取消不污染缓存，上传失败可重试。
- `TrendChart`：点击/键盘打开 Tooltip，`Esc` 关闭，零账单不显示下钻。
- `CategoryDonut`：普通分类和“其他”分别展示，长金额不溢出，普通分类可下钻。
- 跨路由下钻使用 E2E，验证 URL 参数和账单页首帧筛选状态。

### 8.3 验证命令

```bash

```

第五期涉及上传、签名地址和跨路由 Tooltip 时，增加浏览器验收；不能只用静态类型检查代替移动端交互验证。

## 9. 实施顺序

1. 先冻结 API DTO 和前端类型，统一分类与统计响应字段。
2. 固化 Tabler 白名单、默认分类键和图标映射，补充后端/前端契约测试。
3. 扩展 `CategoryIcon` 和分类选择/账单/统计展示，先完成只读展示。
4. 在分类管理中接入图标库选择、图片上传会话、PUT、complete 和保存绑定。
5. 增加图片 URL 过期处理、权限错误、离线降级和账本切换清理。
6. 增加趋势 Tooltip、环形图 Tooltip、“其他”聚合和键盘交互。
7. 完成统计下钻 E2E、移动端尺寸验收和全量回归。

只读展示依赖分类/统计响应字段；编辑和上传依赖分类图标 API、对象存储 CORS 和后端清理任务。API 未完成前不在前端用分类名称猜测图标，也不在前端伪造上传成功状态。

## 10. 取舍、风险与未决问题

### 已确定

- 分类图标属于账本，不属于成员；共享账本成员看到同一份图标。
- 账单列表的分类 Icon 与附件缩略图职责分离。
- 统计金额和日期范围以服务端为唯一口径；Tooltip 不重新计算业务数据。
- “其他”是图表展示聚合项，不是新的分类。
- 第一版不支持任意 SVG、AI 图标、图标市场和图表导出。

### 取舍与风险

- 使用 Tabler 精选子集增加一个前端依赖，但能避免用分类名称猜图标，并保证历史键稳定。
- 首版不做分类图片 IndexedDB 缓存，减少缓存淘汰和签名 URL 失效复杂度；离线时图片可能降级为首字。
- Tooltip 自绘交互比第三方图表库需要更多键盘和边界测试，但可以保持现有 SVG 方案和包体积。
- 每个图片图标都生成签名读地址会增加请求量，因此必须做服务端短期 URL 返回或前端请求去重，不能在列表中逐项无控制地请求。

### 待评审

1. `@tabler/icons-react` 的版本与最终白名单由谁维护，后端默认键和前端注册表如何在 CI 中互相校验。
2. 分类列表是否默认返回 `iconUrl`，还是所有 `IMAGE` 图标都由前端按需读取；建议优先返回短期 URL，缺失时再懒加载。
3. 分类图标资源是否允许离线预览最近一次图片；当前建议第一版只保证首字降级。
4. 统计 Tooltip 在移动端采用固定底部浮层还是贴近图表的数据点；当前建议移动端使用底部 Tooltip，桌面端贴近数据点。
5. 分类图标 API、统计响应和前端类型完成联调后，再把本文从 `review` 更新为 `approved`。
