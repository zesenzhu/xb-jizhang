# 一期数据层与状态设计

## 1. 现状与缺口

| 层 | 现状 | 本期动作 |
| --- | --- | --- |
| HTTP 客户端 | `createApiClient` 已实现 401 单飞刷新、错误归一 `ApiRequestError` | 直接复用 |
| 领域 API | 只有 `user-auth-api`、`admin-auth-api`、`ledger-api` | 新增 4 个模块 |
| 类型 | `TransactionSummary`/`AccountSummary`/`CategorySummary` 均无定义 | 新增 `lib/api/transaction-types.ts` 等 |
| 查询缓存 | `queryKeys` 已有 `transactions(ledgerId)` 占位但无消费 | 扩展为带筛选参数的键 |
| 客户端状态 | 5 个 store，`offlineStore` 无消费方 | 只补 `isOnline` 真实事件绑定 |

## 2. 新增 API 模块

命名与现有 `ledger-api.ts` 保持一致：`unwrap(response.data.data)`，错误由拦截器统一转换。

### 2.1 `lib/api/transaction-api.ts`

| 函数 | 请求 | 说明 |
| --- | --- | --- |
| `getTransactions(ledgerId, query)` | `GET /ledgers/:id/transactions` | 分页 + 筛选 |
| `getTransaction(ledgerId, id)` | `GET /ledgers/:id/transactions/:tid` | 详情 |
| `createTransaction(ledgerId, input)` | `POST /ledgers/:id/transactions` | 携带 `clientRequestId` |
| `updateTransaction(ledgerId, id, input)` | `PATCH /ledgers/:id/transactions/:tid` | 携带 `version` |
| `deleteTransaction(ledgerId, id, version)` | `DELETE /ledgers/:id/transactions/:tid` | `version` 走请求体 |

`clientRequestId` 用 `crypto.randomUUID()` 生成。抽屉打开时生成一次，重试复用同一个 id，保证失败重试不产生重复账单。

### 2.2 `lib/api/category-api.ts`

| 函数 | 请求 |
| --- | --- |
| `getCategories(ledgerId, query?)` | `GET /ledgers/:id/categories` |

一期只读。分类管理页不在范围（需求 4.2）。

### 2.3 `lib/api/account-api.ts`

| 函数 | 请求 |
| --- | --- |
| `getAccounts(ledgerId)` | `GET /ledgers/:id/accounts` |

只读，用于记账抽屉的账户选择。

### 2.4 `lib/api/ledger-member-api.ts`

| 函数 | 请求 |
| --- | --- |
| `getLedgerMembers(ledgerId)` | `GET /ledgers/:id/members` |

用途：付款人下拉、账单详情里把 `createdById` / `payerId` 映射为昵称。

## 3. 类型定义

放在 `lib/api/*-types.ts`，与现有 `ledger-types.ts` 同构。字段严格对齐后端 `TransactionSummary`：

```text
TransactionSummary {
  id, ledgerId, type: 'EXPENSE' | 'INCOME', amountCents,
  occurredAt, title, note, categoryId, accountId, payerId,
  source, clientRequestId, createdById, updatedById,
  version, deletedAt, createdAt, updatedAt,
  category: { id, type, name } | null,
  account: { id, name, visibility } | null,
  payer: { id, nickname } | null,
}
```

前端额外定义视图类型，不污染传输类型：

```text
BillDayGroup {
  billDate: string          // YYYY-MM-DD，账本时区
  label: string             // 11/02
  weekday: string           // 星期一
  isToday: boolean
  isYesterday: boolean
  expenseCents: number
  incomeCents: number
  items: TransactionSummary[]
}

MonthSummary {
  expenseCents: number
  incomeCents: number
  netCents: number
  isFiltered: boolean
  isPartial: boolean        // 分页未取全时为 true
}
```

## 4. 时区与日期分组

需求 11.3 要求按账本时区分组。后端无 `timezone` 字段（缺口 B3），一期前端固定使用 `Asia/Shanghai`，把常量集中在一处，后端补齐后改为读 `ledger.timezone`。

### 4.1 计算规则

```text
billDateOf(occurredAtIso, timeZone) →
  用 Intl.DateTimeFormat('en-CA', { timeZone, year, month, day }) 取 YYYY-MM-DD
```

不使用 `Date.prototype.getDate()`：它按设备时区计算，跨时区用户会看到不同的日期分组。

### 4.2 月份边界

月份筛选传给后端的 `from`/`to` 必须是账本时区当月的起止时刻：

```text
当月 1 日 00:00:00+08:00  → from
次月 1 日 00:00:00+08:00  → to
```

后端 `to` 是左闭右开（`lt`），因此不需要加一天减一毫秒。

### 4.3 分组与合计

```text
groupBills(items, timeZone) →
  1. 按 billDateOf(occurredAt) 分桶
  2. 桶内按 occurredAt 降序
  3. 桶按 billDate 降序
  4. 桶内分别累加 EXPENSE / INCOME 的 amountCents
```

纯函数放在 `lib/bill/bill-group.ts`，配套单元测试覆盖：跨 UTC 日界的账单、同日多笔、空列表、单一类型。

## 5. 筛选条件状态

筛选条件属于页面级状态，用 URL query 还是内存状态需要取舍：

**结论：内存状态 + 组件内 `useState`，不进 URL。**

理由：需求 6.3 只要求「返回列表时保留筛选」，不要求分享链接；URL 同步会让每次输入都触发 `router.replace`，与 Next App Router 的预取相互干扰。

```text
BillFilter {
  month: string            // YYYY-MM，默认当前月
  keyword: string
  type?: 'EXPENSE' | 'INCOME'
  categoryId?: string
  createdById?: string
}
```

`month` 与 `keyword` 直接驱动查询；其余来自筛选面板的「应用」动作。

切换账本时整体重置为默认值（需求 5.5）。

## 6. 查询缓存设计

### 6.1 键结构

扩展 `lib/query/query-config.ts`：

```text
queryKeys.transactions(ledgerId, filter) →
  ['ledger', ledgerId, 'transactions', normalizeFilter(filter)]
```

首段仍为 `'ledger'`，与 `UserWorkspaceProvider` 在退出登录时的 `removeQueries` 前缀匹配保持一致（首段是 `'user' | 'ledgers' | 'ledger'`），避免残留上一个用户的账单缓存。

`normalizeFilter` 需把 `undefined` 字段剔除并按固定顺序输出，否则键不稳定会导致缓存永远不命中。

### 6.2 staleTime

| 资源 | staleTime | 理由 |
| --- | --- | --- |
| 账单列表 | 30s（沿用现有配置） | 共享账本会有人同时记账 |
| 账单详情 | 0（不缓存） | 编辑后需立即反映 |
| 分类 | 5min | 一期不改分类 |
| 账户 | 5min | 一期不改账户 |
| 成员 | 5min | 昵称映射用 |

### 6.3 失效规则

| 动作 | 失效范围 |
| --- | --- |
| 创建账单 | 当前 `ledgers` 下所有 `transactions` 前缀（`ledgerId` 维度） |
| 编辑账单 | 同上 + 该账单 `detail` |
| 删除账单 | 同上 |
| 切换账本 | 不失效，靠 `ledgerId` 隔离键 |
| 切换月份/筛选 | 不失效，新键自然触发请求 |

## 7. 分页策略

一期不做无限缓存的“全量拉取”，用 `useInfiniteQuery`：

```text
useInfiniteQuery({
  queryKey: queryKeys.transactions(ledgerId, filter),
  queryFn: ({ pageParam }) => getTransactions(ledgerId, { ...filter, page: pageParam }),
  initialPageParam: 1,
  getNextPageParam: (last) => (last.hasNextPage ? last.page + 1 : undefined),
})
```

`pageSize` 固定 30。概览统计需要全部数据，处理方式见下节。

## 8. 概览统计的降级实现

后端无统计接口（缺口 4.2）。一期采用：

1. `useInfiniteQuery` 拉到当前已加载的所有页；
2. 前端累加已加载账单的金额；
3. 若 `hasNextPage === true`，概览卡显示「已统计前 N 笔」标记，`MonthSummary.isPartial = true`。

这是明确的临时方案。迭代四接入后端 `summary` 接口后，`isPartial` 恒为 `false`，相关 UI 分支删除。

**不得**为了让概览准确而把 `pageSize` 提高到 100 或循环拉取全部页——那会在成员多、账单多的账本上造成首屏瀑布式请求。

## 9. 表单状态机

### 9.1 状态定义

```text
BillFormState {
  mode: 'create' | 'edit'
  type: 'EXPENSE' | 'INCOME'
  amountText: string        // '0' / '12.5' / '12.50'
  categoryId: string | null
  occurredAt: string        // ISO
  accountId: string | null
  title: string
  note: string
  payerId: string | null
  clientRequestId: string   // 创建时生成一次
  version?: number          // 编辑时使用
  isDirty: boolean
  submitting: boolean
  error: string | null
}
```

### 9.2 关键转换

| 输入 | 转换 | 位置 |
| --- | --- | --- |
| `amountText` → `amountCents` | `Math.round(Number(text) * 100)`，需先校验 `^\d+(\.\d{1,2})?$` | `lib/bill/amount.ts` |
| `amountCents` → `amountText` | 编辑态回填，`formatCentsToYuan` 去千分位 | 同上 |
| `occurredAt` 与月份 | 创建时默认 `now`，用户选择未来时间则 `error` 置位 | 组件内 |

金额转换必须用字符串处理，禁止 `parseFloat` 后的浮点乘法用于业务判断（现有首页的 `Math.round(parseFloat(x) * 100)` 只做展示，可继续用于非关键路径）。

### 9.3 提交路径

```text
校验 → 组装 payload → createTransaction
  ├─ 成功：invalidate transactions → 关闭（清空） 或 重置（保存并继续）
  └─ 失败：error 置位，输入保留，clientRequestId 不变
```

「保存并继续」只重置 `amountText` / `title` / `note` / `isDirty`，保留 `type` / `categoryId` / `occurredAt` / `accountId` / `payerId`，并生成**新的** `clientRequestId`。

## 10. 离线与网络状态

`useAppStore.isOnline` 当前恒为 `true`，无任何监听。本期在 `UserWorkspaceProvider` 挂载时绑定：

```text
window.addEventListener('online')  → setIsOnline(true)
window.addEventListener('offline') → setIsOnline(false)
```

需求 13 明确一期离线不写：断网时 FAB 点击提示「当前离线，无法记账」，详情页编辑/删除按钮禁用。

`offlineStore`（`syncStatus`/`pendingCount`）为一期外能力，本期**不接**，保持无引用状态；若确认长期不用应删除，避免误接。

## 11. 成员昵称映射

`TransactionSummary` 只有 `createdById` / `updatedById` / `payerId`，无昵称。方案：

```text
useQuery(getLedgerMembers(ledgerId))  →  Map<userId, { nickname, username }>
```

详情展示时查表，缺失时降级显示「未知成员」。不额外为每条账单发起请求。

## 12. 错误处理约定

| HTTP | code | 前端表现 |
| --- | --- | --- |
| 401 | 40101 | 拦截器自动刷新；失败跳登录 |
| 403 | 40321 | 「当前成员没有该操作权限」；`VIEWER` 场景不展示入口，正常不应触达 |
| 404 | 40421 | 「账单不存在或已被删除」；列表刷新 |
| 409 | 40922 | 版本冲突：展示「账单已更新」并刷新详情 |
| 5xx | 50001 | 「服务暂时不可用，请稍后重试」；保留用户输入 |

错误文案统一从 `ApiRequestError.message` 取，为空时用兜底文案；不直接把后端 message 当作唯一来源（后端文案可能变化）。
